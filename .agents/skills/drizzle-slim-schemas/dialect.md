# Adding a dialect, or a driver

Two different jobs. ONE question tells them apart: **does the drizzle module export column builders?**

- **Dialect** (`drizzle-orm/<x>-core`): exports builders → needs a whole new `@mionjs/drizzle-orm-<x>-core` package.
  Checklist below.
- **Driver** (`drizzle-orm/d1`, `/durable-sqlite`, `/libsql`, `/neon-http`, `/better-sqlite3`): exports only a
  `drizzle()` factory, a session and a migrator. Its tables use its DIALECT's builders, already wrapped.
  - So a driver adds **no package, no `drizzle-dialects.json` row, no manifest work**.
  - Needs only type pins, an e2e lane, docs. Skip to [Both translate roads](#both-translate-roads)
    and [e2e-lane.md](e2e-lane.md).

## Step 0, not optional: boundary pass over the whole new manifest

- Run it BEFORE any package code exists.
- New dialect arrives with every export `pending` at once: the one moment its boundary gets set.
- Sibling decisions are the starting point, never the answer. Work the queue against the rule, confirm with the user.

## Touchpoints

Copy an existing dialect package, match it everywhere. Miss one → dialect looks finished while a gate or lane
silently skips it.

- `packages/drizzle-orm-<d>-core/`: `package.json`, `tsconfig.json`, `tsconfig.build.json`, `vite.config.ts`,
  `vitest.config.ts`, thin `README.md`, an `AGENTS.md` carrying ONLY what is specific to this dialect.
- `src/`: `columns.ts`, `types.ts`, `table.ts`, `helpers.ts`, `views.ts`, `drizzle.ts`, `index.ts`.
- `test/`: `index.spec.ts` (the equality matrix), `type-pins.stub.ts`, `typeTables.spec.ts`, `valueHelpers.spec.ts`,
  `manifest-coverage.spec.ts`, `completeness.spec.ts`.
- repo root: a `drizzle-dialects.json` row, a `tsconfig.json` reference,
  the `lint:eslint` glob AND the lint-staged glob in `package.json`, the vitest project list.
- e2e: its own lane and image, per [e2e-lane.md](e2e-lane.md).

`package.json` specifics, easy to get wrong:

- `versionLine: "drizzle-orm"`: puts the package on the drizzle version line, off the lockstep train.
  Release membership is automatic from that marker; `pnpm miondevx release check-drizzle-versions` guards it.
- Version aligned to drizzle's minor, not to the rest of the monorepo.
- Three peers: `drizzle-orm` (optional, own minor range), `@mionjs/run-types`, `@mionjs/drizzle-orm` (own minor range).
- `@mionjs/run-types` peer = RANGE, not a pin: consumer's single copy supplies both format types + runtime `getRunType`.
- `@mionjs/run-types` + `@mionjs/drizzle-orm` ALSO as `workspace:*` devDependencies (the one place per-package devDeps
  are allowed), so the package satisfies its own peers inside the workspace.
- The `./drizzle` subpath export, with a `source` condition like the root one.

Then regenerate (`pnpm miondevx core drizzle-manifest`) and get every gate green.

## Both translate roads

- Dialect is done when drizzle code **translates onto it** and that translation **converts to the pure-type road**,
  not when its builders compile.
- New dialect supports every feature the older ones do, or it is half a dialect.

**Road 1: `mion drizzle-migrate`, drizzle to mion.**

- Folds each column's modifier chain into one props object.
- Driven by `ts-go-runtypes/internal/drizzlemigrate/importmap.json`, generated by joining `drizzle-dialects.json`
  with the per-package manifests.
- `migrated` export → moves to the wrapping package, same name. Everything else stays on drizzle.
- Never hand-edit that map: flip the entry's `status` in its manifest, regenerate.
- `migrateAlias` (in the dialect's `drizzle-dialects.json` row) = its only hand-owned input,
  for a name whose DRIZZLE spelling is still needed in the same file. `sql` is the only one today.

**Road 2: `mion convert --to type`, builders to pure types.**

- Needs per column: the `typeAlias` recorded in the manifest, a key in `ColMods`, the name in `colModNames`
  (`packages/drizzle-orm/src/columns.ts`) AND in `drizzleModNames` (`ts-go-runtypes/internal/convert/drizzle.go`),
  its flag in the derivation key lists.
- Gated by `colMods.spec.ts`, `TestDrizzleModNamesMatchManifests`, each dialect's `manifest-coverage.spec.ts`.
- A refusal class must never quietly grow: the type-road coverage gate excuses a miss only when the converter itself
  REPORTED the refusal.

**Run the host half first.** `pnpm miondevx core drizzle-translate [--to-types]` does both translations and both
typechecks, no container, no database. Green here before touching an image: a translation bug costs ten times more
in a container.
