One package per database re-exports the entire [Drizzle ORM](https://orm.drizzle.team) surface for that dialect. Import your column builders from there instead of from drizzle, and everything else stays the same: same function names, same parameters, same runtime behavior.

| Database | Package |
|----------|---------|
| PostgreSQL | `@mionjs/drizzle-orm-pg-core` |
| MySQL | `@mionjs/drizzle-orm-mysql-core` |
| SQLite | `@mionjs/drizzle-orm-sqlite-core` |

Each package version follows drizzle-orm, not mion: version 0.45.x works with drizzle-orm 0.45.x, and the package declares that range as a peer dependency. Pick the package line that matches the drizzle-orm version in your project.

The difference is in the types. Drizzle's own table types forget most column parameters (a varchar length, a decimal precision, whether an int is unsigned). The proxy builders remember them: each column's data type carries the matching format type from `@ts-runtypes/core/formats`, with the parameters you wrote captured in it. When you infer a model from the table, those formats come with it, and the compiled validators enforce them with no extra runtime checks.

Because routes and tables share the same model types, a route typed with the inferred model uses the exact same compiled validator function as any other consumer of that model.

## Refine tables for your API

Your API often needs stricter rules than the database column: a name column can hold 100 characters, but the signup form wants at least 10. `refineTable` adds those rules at the type level. It returns the same table object (nothing about the SQL changes) with the extra format parameters merged into the captured ones. Derive your model types from the refined table, and every validator, mock or encoder you create from them enforces both the database rules and the refined ones:

<code-import path="packages/examples/src/drizzle/drizzle-refine-example.ts" lang="ts" />

A refinement that does not fit the column is a compile error, never a silent override: you cannot put a number rule on a string column, invent an unknown parameter, or change whether a column accepts null (that stays with notNull in the table itself). Columns without a format (booleans, JSON, enums) are not refinable.

`InferSelect`, `InferInsert` and `InferUpdate` derive the row, insert and update payload types from a table (refined or not): inserts drop generated columns and make defaulted ones optional, updates accept any subset of the insert payload.

## Semantic types by hand

Columns whose values have no matching format (geometry, vectors, MAC addresses, binary data, plain booleans and JSON) behave exactly as in plain drizzle. For JSON columns, drizzle's own `.$type<T>()` stays the escape hatch to declare a semantic type by hand:

```ts
import {pgTable, jsonb, uuid} from '@mionjs/drizzle-orm-pg-core';

const events = pgTable('events', {
  id: uuid('id').primaryKey(),
  payload: jsonb('payload').$type<{kind: string; at: number}>().notNull(),
});
```

The full list of what each column builder stamps, per database and column mode, lives in [Column Formats](./column-formats).
