The package `@mionjs/drizzle` ships one module per database that re-exports the entire [Drizzle ORM](https://orm.drizzle.team) surface. Import your column builders from there instead of from drizzle, and everything else stays the same: same function names, same parameters, same runtime behavior.

| Database | Import from |
|----------|-------------|
| PostgreSQL | `@mionjs/drizzle/pg` |
| MySQL | `@mionjs/drizzle/mysql` |
| SQLite | `@mionjs/drizzle/sqlite` |

The difference is in the types. Drizzle's own table types forget most column parameters (a varchar length, a decimal precision, whether an int is unsigned). The proxy builders remember them: each column's data type carries the matching format type from `@ts-runtypes/core/formats`, with the parameters you wrote captured in it. When you infer a model from the table, those formats come with it, and the compiled validators enforce them with no extra runtime checks.

Because routes and tables share the same model types, a route typed with the inferred model uses the exact same compiled validator function as any other consumer of that model.

## Semantic types by hand

Columns whose values have no matching format (geometry, vectors, MAC addresses, binary data, plain booleans and JSON) behave exactly as in plain drizzle. For JSON columns, drizzle's own `.$type<T>()` stays the escape hatch to declare a semantic type by hand:

```ts
import {pgTable, jsonb, uuid} from '@mionjs/drizzle/pg';

const events = pgTable('events', {
  id: uuid('id').primaryKey(),
  payload: jsonb('payload').$type<{kind: string; at: number}>().notNull(),
});
```

::note
The full list of what each column builder stamps, per database and column mode, lives in [Column Formats](./column-formats).
::
