Your migrations need real Drizzle objects, and `toDrizzle` is what makes them. Point `drizzle.config.ts` at one file that materializes everything you declared.

One rule to remember: anything you do not export from that file is invisible to your migrations.

## What needs its own call

Tables and views come with everything declared inside them, so materializing the table is enough for its columns, indexes, constraints and inline policies.

Standalone objects are read by drizzle-kit on their own, so each one needs its own `toDrizzle` call:

| Declared with | Materialize |
| --- | --- |
| `pgTable`, `pgView`, `pgMaterializedView` | the table or view itself |
| `pgEnum`, `pgSequence`, `pgSchema`, `pgRole` | each handle |
| `pgPolicy(...).link(table)` | the policy itself |
| `pgPolicy` inside a table's third argument | nothing, it comes with the table |

## Where the rest of your app points

Your routes, your models and your client never import this file. They import the schema module that declares the tables, and take their types from it:

```ts
import {accounts} from './schema.ts';
import type {InferSelectModel} from '@mionjs/drizzle-orm';

export type Account = InferSelectModel<typeof accounts>;
```

That is the whole point of the split. The file above is the only one that loads Drizzle, and it only runs when you generate or apply migrations.
