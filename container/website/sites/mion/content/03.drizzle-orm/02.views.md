A view you declare with explicit columns works like a table here. It is recorded the same way, `toDrizzle` builds the real drizzle view from it, and its row type travels through your routes and your client without pulling drizzle types along.

Views are read only, so a view has one model instead of three.

For a view that already exists in the database, use `existing()` instead of `as()`. You still get the row type, and drizzle-kit will not try to create it.

## The row type

A view's row type comes from `InferSelectViewModel`, a different name from the table one:

```ts
type AdultUser = InferSelectViewModel<typeof adultUsers>;
```

Drizzle splits these two names as well, for the same reason: there is no insert or update payload for a view, so asking for one is a mistake worth catching while you type it.

Everything else works as it does for tables. The columns carry the same format types, so a validator built from a view's row type enforces the same lengths, ranges and shapes.

## Materialized views

`pgMaterializedView` takes the same columns and the same query, plus the storage options PostgreSQL accepts:

```ts
export const topTeams = pgMaterializedView('top_teams', {
  id: serial('id'),
  code: varchar('code', {length: 10}).notNull(),
})
  .using('btree')
  .with({fillfactor: 90})
  .tablespace('custom_tablespace')
  .withNoData()
  .as(sql`select id, code from teams`);
```

MySQL views take `algorithm`, `sqlSecurity` and `withCheckOption` instead. SQLite views take no options at all.

## Views built from a query

Drizzle has a second way to declare a view, where the columns come from a query builder rather than from you:

```ts
// this form stays on drizzle
export const userView = pgView('user_view').as((qb) => qb.select().from(user));
```

That form is not part of this package. Its columns are worked out by drizzle's own query typing, which is exactly the machinery these packages exist to keep out of your app.

Declare those views with drizzle itself, over your `toDrizzle` tables, in the file that runs your queries. If you want a view's row type in your app, declare the columns yourself and use the form above.
