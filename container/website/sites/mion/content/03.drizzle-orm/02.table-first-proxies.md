If you prefer declaring drizzle tables directly (tables first) instead of generating them from types, `@mionjs/drizzle` ships one module per database that re-exports the entire drizzle surface. Import your column builders from there instead of from drizzle, and everything else stays the same: same function names, same parameters, same runtime behavior.

| Database | Import from |
|----------|-------------|
| PostgreSQL | `@mionjs/drizzle/pg` |
| MySQL | `@mionjs/drizzle/mysql` |
| SQLite | `@mionjs/drizzle/sqlite` |

The difference is in the types. Drizzle's own table types forget most column parameters (a varchar length, a decimal precision, whether an int is unsigned). The proxy builders remember them: each column's data type carries the matching format type from `@ts-runtypes/core/formats`, with the parameters you wrote captured in it. When you infer a model from the table, those formats come with it, and the compiled validators enforce them with no extra runtime checks.

Because routes and tables share the same model types, a route typed with the inferred model uses the exact same compiled validator function as any other consumer of that model.

## What gets a format

Column parameters map to format constraints wherever the value types line up:

- varchar and char capture their length (`String<{maxLength: 100}>`).
- integer columns get their real width (`Int32`, `Int16`, `Int8`, unsigned variants for MySQL).
- uuid, inet, date, time and timestamp columns get their matching formats, following the mode you declared (a timestamp in string mode validates as a date-time string, in date mode as a Date).
- MySQL year validates its real 1901 to 2155 window.

Columns declared with an enum keep drizzle's exact literal union; that is already the strictest possible type, so no format is layered on top.

Columns whose values have no matching format (geometry, vectors, MAC addresses, binary data, plain booleans and JSON) behave exactly as in plain drizzle. For JSON columns, drizzle's own `.$type<T>()` stays the escape hatch to declare a semantic type by hand:

```ts
import {pgTable, jsonb, uuid} from '@mionjs/drizzle/pg';

const events = pgTable('events', {
  id: uuid('id').primaryKey(),
  payload: jsonb('payload').$type<{kind: string; at: number}>().notNull(),
});
```

::note
The proxies complement the types first workflow described in the [overview](./drizzle-overview). Types first keeps your TypeScript types as the source of truth; tables first keeps your drizzle tables as the source of truth. Both end in the same place: models with full format fidelity and shared compiled validators.
::
