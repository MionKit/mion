Check whether the client and server routes are in sync.

A client is built against the route types of one server build. When you deploy new route types, an app that is already open still calls with the old ones, and the server may reject or misread its data. Use this middleware so such a call stops before it runs, and your app can ask the user to reload.

Each call sends an id for the types of every route it calls, and the server compares it with its own. A different id stops the call before the route runs, and your code gets an error to act on.

## Changes That Stop a Call

The id covers the route's params type, its return type and the wire format of each. Only the `compact` parser writes a different wire format.

| Change on the server | The call |
| --- | --- |
| The route's params type | Stopped |
| The route's return type | Stopped |
| The parser of the route or router switches to or from `compact` | Stopped |
| mion upgraded, while the client was built with the old version | Stopped, for every route |
| The route's options, like a `query` turned into a `mutation` | Runs |
| A middleware's params type | Runs. The middleware's own validation rejects data that no longer fits. |
| A route added | Other routes keep running |
| The route removed | Not checked. The call fails because the route is not found. |

In a batch every route is checked, and one changed route stops the whole batch.

What happens next depends on where the client got the route's metadata:

| Route metadata | What the client does | What you do |
| --- | --- | --- |
| Bundled at build time (the default) | Returns the error. | Reload the app to pick up a newer client build, or ship one. |
| Fetched from the server with [mionMethodsMetadata](/rpc/middlewares/fetch-metadata) | Drops its saved copy, fetches the new metadata and sends the call again, once. | Nothing. You see the error only if the second try fails too. |

### Calls Without Ids

A call that sends no id is stopped with `route-sync-required`. The answer carries what the client needs, so `useSyncRoutes` learns the ids and sends the call again. This happens on the first call of a route whose metadata the client has not fetched yet.

::note
Without `useSyncRoutes` the client sends no ids, so every call ends with `route-sync-required`. The same goes for any other caller, like `curl` or a client in another language.
::

## Build Check

When the client bundles its routes, the build checks that it installs the client half. If a route runs `mionSyncRoutes` and nothing in the client uses `middlewares.mionSyncRoutes`, the build fails with MET009. Look up the code in [All Diagnostics](/runtypes/diagnostics/all-diagnostics).
