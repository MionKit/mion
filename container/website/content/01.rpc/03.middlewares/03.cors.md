Let a browser app on another origin call your API. CORS (cross-origin resource sharing) is the browser check that blocks such calls, and hides most response headers, unless the server allows them.

`mionCors` sets those answers from your routes' types: the request headers your headers middleware read, and the response headers your routes return. Adding a header to a route needs no CORS change.

## Adding the Middleware

Add `mionCors` from `@mionjs/router/middlewares` and state which origins may call. Put it first: a preflight (the check request the browser sends before the real call) carries none of your headers, so an auth middleware before it would refuse it.

<code-import path="packages/private-examples/src/router/cors.routes.ts" lang="ts [server.routes.ts]" />

Placement decides which routes get CORS. At the root it covers every route; inside a group it covers that group. An API without it sends no CORS headers, and the browser blocks every call from another origin.

## Options

| Option | What it does |
| --- | --- |
| `origin` | Origins that may call: one string, a list, a `RegExp`, a function, or `'*'` for any. |
| `credentials` | Lets the browser send cookies. The caller's origin is sent back, never `*`. Needs listed origins: `'*'` with `credentials` throws. |
| `maxAge` | Seconds the browser keeps a preflight answer before asking again. |
| `allowHeaders` | Extra request headers a raw middleware reads. |
| `exposeHeaders` | Extra response headers a raw middleware sets. |

## Headers From Your Types

Each route's lists come from the middleware and the route in its [execution chain](/rpc/server/middleware#execution-chain). A batch gets the lists of all its routes.

| CORS header | Holds |
| --- | --- |
| `Access-Control-Allow-Headers` | `content-type`, every header a headers middleware reads, and `allowHeaders` |
| `Access-Control-Expose-Headers` | Every header a route or middleware returns, mion's `x-rpc-error` and `x-build-version`, and `exposeHeaders` |
| `Access-Control-Allow-Methods` | The route's [HTTP methods](/rpc/server/routes#allowed-http-methods) |

A header that a raw middleware reads or sets has no type, so list it by hand:

To keep a declared header from the browser, mark it `cors: false` in its type, see [Keeping Headers Off CORS](/rpc/server/headers#keeping-headers-off-cors). The mark wins over `allowHeaders` and `exposeHeaders`.

## Requests It Answers

| Request | Answer |
| --- | --- |
| From an allowed origin | The route runs; the answer allows the origin and lists the exposed headers. |
| From another origin | The route runs, with no CORS headers, so the browser hides the answer. |
| A preflight (`OPTIONS`) | Answered 200 by the middleware. The route never runs. |
| An error | The same CORS headers, so the client can read the error. |

::note
`OPTIONS` reaches only routes behind `mionCors`. Anywhere else it is refused with a 405.
::

## What CORS Protects

CORS decides which browser pages may read your answers. It is not access control: a server, a script or `curl` calls your API with no CORS check at all. Keep your auth middleware.

A `cors: false` header is still sent, and only allowed origins see exposed headers. Treat the mark as tidying, not as hiding a secret.
