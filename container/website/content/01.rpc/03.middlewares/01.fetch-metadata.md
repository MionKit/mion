Fetch route metadata from the server instead of bundling it in the client.

Route metadata is what the client needs to call a route: its param and return types, its options, and its validation and JSON round trip functions. By default, the mion build plugin bundles it into your client code.

Use this middleware when:

- You don't want the routes metadata in the client bundle, for example to keep the bundle small for a large API.
- Your client is built in a separate project from your server, or without the mion build plugin.

The client asks the server for a route's metadata on its first call, and saves it in the browser for later visits. When you deploy a server that changes a route, the client fetches it again, with no client rebuild.

::warning
A client that fetches metadata builds the validation and JSON round trip functions at runtime, so a strict Content Security Policy blocks it. A client built without the mion build plugin cannot send batches.
::

## Getting Route Metadata

| Mode | How the client gets it | What you set up |
| --- | --- | --- |
| Bundled (default) | The build ships it with the client, for every route the client calls. | Nothing. |
| Fetched | The `mionFetchMetadata` middleware sends it on a route's first call, and the client saves it. | The middleware in your routes, `useFetchMetadata` in the client, and `client: {routes: 'fetch'}`. |

Use the fetched mode for a client built apart from its API. The server sends its own compiled functions, so they always match it.

## What the Middleware Answers

Given a list of route ids, it returns the metadata of each route and of every middleware that runs with it.

| It describes | It never describes |
| --- | --- |
| Every route | Your handler code |
| Middleware that takes params or headers, or returns data | [Raw middleware](/rpc/server/middleware#raw-middleware), and middleware with no params and no return data |
| The compiled validation and JSON round trip functions of those | mion's internal routes |

## Why Metadata Is Public

Any client can ask for any route's metadata, without logging in. A client with bundled metadata has the same metadata in its JavaScript. Treat it like a public API schema: it shows your types, never your data.

::note
Route metadata is not access control. Protect your routes with your own middleware.
::

## Listing Every Method

A client written without mion can POST this body to any route path to list every public route and middleware, and the ids of your [batches](/rpc/client/batch), so it can call a batch by id. The route at that path does not run.

```json
{"mionFetchMetadata": [[], "all"]}
```
