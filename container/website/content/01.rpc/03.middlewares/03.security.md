Stop other sites from sending requests with your users' cookies (CSRF, cross-site request forgery). Let the browser apps you choose call your API from another origin (CORS, cross-origin resource sharing).

Add it whenever the browser attaches a login on its own, like a cookie. With a login in an `Authorization` header, you need it only for CORS.

## Security Options

<code-import path="packages/private-examples/src/router/security-raw-headers.routes.ts" lang="ts [server.routes.ts]" />

| Option | What it does |
| --- | --- |
| `origins` | Origins you trust: a list, `'*'` for any, or a function `(ctx, origin)` returning a boolean. They may send requests from another site and, with `cors`, read the answers. `null` is never trusted. |
| `cors` | Lets the trusted origins read answers. Off by default. Needs `origins`, or it throws. |
| `cors.credentials` | Lets the browser send cookies. Needs listed origins: `'*'` with `credentials` throws. |
| `cors.maxAge` | Seconds the browser keeps a preflight answer before asking again. |
| `cors.allowHeaders` | Extra request headers a raw middleware reads. |
| `cors.exposeHeaders` | Extra response headers a raw middleware sets. |
| `cors.excludeHeaders` | Headers the browser never reads or sends cross-origin, even when a route declares them. Wins over `allowHeaders` and `exposeHeaders`. |
| `csrf` | The checks below, all on by default. `csrf: false` turns them all off. |

## CSRF Checks

Each check refuses a request another site can make a browser send. A call from the mion client always passes.

<code-import path="packages/private-examples/src/router/security-csrf.routes.ts" lang="ts [server.routes.ts]" />

| Check | Refuses | Answer |
| --- | --- | --- |
| `methodByIntent` | A method the route's intent does not take: a `query` takes GET, HEAD and POST; a `mutation`, a `route` and a batch take only POST. | 405 `method-not-allowed`, with an `Allow` header |
| `crossOrigin` | A POST another site sent, unless its origin is trusted. Read from the browser's `Sec-Fetch-Site` header, else from `Origin` against `Host`. A caller sending neither (a server, a script, `curl`) passes. | 403 `cross-origin-request-refused` |
| JSON body, no option of its own | A body not sent as `application/json`, like a plain HTML form or a fetch with no type. | 415 `unsupported-media-type` |

## CORS Headers From Your Types

`mionSecurity` fills the CORS headers from your routes' types. Adding a header to a route needs no change here.

| CORS header | Holds |
| --- | --- |
| `Access-Control-Allow-Headers` | `content-type`, every header a headers middleware reads, and `allowHeaders` |
| `Access-Control-Expose-Headers` | Every header a route or middleware returns, mion's `x-rpc-error` and `x-build-version`, and `exposeHeaders` |
| `Access-Control-Allow-Methods` | `GET, POST` for a query, `POST` for the rest |

::tip
Add `cors: false` to a route or middleware to keep all its headers off both lists, like `excludeHeaders`. It needs `MionSecurityHandlerOptions` in your router's `handler` part, see [Options a Middleware Adds](/rpc/server/middleware#options-a-middleware-adds).
::

## Answers per Request

| Request | Answer |
| --- | --- |
| From a trusted origin | The route runs; with `cors`, the answer allows the origin and lists the exposed headers. |
| A GET from another origin | The route runs, with no CORS headers, so the browser hides the answer. |
| A POST from another origin | Refused with a 403. |
| A preflight (`OPTIONS`) | Answered 200 by the middleware, CORS on or off. The route never runs. |
| A refused request or an error | The same CORS headers, so the client can read the error. |
| Every answer | `x-content-type-options: nosniff`, and no `server: mionjs` header. A `server` value you set in `responseHeaders` stays. |

## What the Middleware Protects

The CSRF checks stop other sites from making the browser act for your users. CORS decides which pages may read your answers. Neither is access control: a server, a script or `curl` calls your API with no browser. Keep your auth middleware.

::note
An excluded header is still sent, so never use `excludeHeaders` to hide a secret.
::
