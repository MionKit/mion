## Handling a Stopped Call

A stopped call returns no value. The error is in `middlewareErrors.mionSyncRoutes`, with the type `route-types-mismatch` and the changed route ids in `errorData.routeIds`.

What happens next depends on where the client got the route's metadata:

| Route metadata | What the client does | What you do |
| --- | --- | --- |
| Bundled at build time (the default) | Returns the error. | Reload the app to pick up a newer client build, or ship one. |
| Fetched from the server with [mionFetchMetadata](/rpc/middlewares/fetch-metadata/server) | Drops its saved copy, fetches the new metadata and sends the call again, once. | Nothing. You see the error only if the second try fails too. |

## Calls Without Ids

A call that sends no id is stopped with `route-sync-required`. The answer carries what the client needs, so `useSyncRoutes` learns the ids and sends the call again. This happens on the first call of a route whose metadata the client has not fetched yet.

::note
Without `useSyncRoutes` the client sends no ids, so every call ends with `route-sync-required`. The same goes for any other caller, like `curl` or a client in another language.
::

## Build Check

When the client bundles its routes, the build checks that it installs the client half. If a route runs `mionSyncRoutes` and nothing in the client uses `middlewares.mionSyncRoutes`, the build fails with MET009. Look up the code in [All Diagnostics](/runtypes/diagnostics/all-diagnostics).
