mion has starter projects that set up a fully typed frontend and backend in one step. Each keeps the mion API in its own `api/` folder, so you can deploy the frontend and the API independently.

::code-group
```bash [Vue]
npm create @mionjs/starter-vue my-app
```

```bash [React]
npm create @mionjs/starter-react my-app
```

```bash [Nuxt]
npm create @mionjs/starter-nuxt my-app
```
::

:spacer

## Vue Starter

A [Vue 3](https://vuejs.org) SPA + [Vite](https://vitejs.dev) starter with a standalone mion API.

- Vue Router
- `api/` folder with build targets for Node, Bun, Vercel and Cloudflare Workers
- Fully typed `@mionjs/client` wired to the local API
- mion Vite plugin
- Vitest + Playwright e2e tests preconfigured

```bash
my-app/
├── app/                      # Vue 3 SPA source
│   ├── pages/                # Route views
│   ├── composables/          # Shared Vue composables
│   ├── mion-client.ts        # Typed mion client wired to the API
│   ├── router.ts             # Vue Router setup
│   └── main.ts               # SPA entry
├── api/                      # Standalone mion API (own build)
│   ├── src/
│   │   ├── api.ts            # Route registry + initApi()
│   │   ├── models.ts         # Shared API models
│   │   ├── features/         # Feature modules (handlers, models, repos)
│   │   ├── server.node.ts    # Node.js entry
│   │   ├── server.bun.ts     # Bun entry
│   │   ├── vercel-serverless.ts
│   │   └── cloudflare-worker.ts
│   └── vite.config.ts        # mion Vite plugin + multi-target build
├── e2e/                      # Playwright tests
└── vite.config.ts            # Frontend Vite config (loads mion plugin)
```

:spacer

## React Starter

A [React 19](https://react.dev) SPA + [Vite](https://vite.dev) starter with the mion API running on Node.

- React Router in SPA mode
- One `vite.config.ts`: the API runs inside `vite dev`, and `vite build` outputs the SPA and the API
- Fully typed `@mionjs/client`
- oxlint with the mion lint rules
- Vitest + Playwright e2e tests preconfigured

```bash
my-app/
├── app/                      # React SPA source
│   ├── pages/                # Route views
│   ├── mion-client.ts        # Typed mion client wired to the API
│   ├── orders-batch.ts       # batch + inputFrom example
│   └── main.tsx              # SPA entry + React Router setup
├── api/                      # mion API
│   ├── src/
│   │   ├── router.ts         # createMionRouter()
│   │   ├── api.ts            # Route tree + mion.initRoutes()
│   │   ├── models.ts         # Shared API models
│   │   ├── features/         # Feature modules (handlers, models, repos)
│   │   └── server.node.ts    # Node.js entry
│   └── tests/                # Vitest API and client tests
├── e2e/                      # Playwright tests
├── tsconfig.json             # One tsconfig for the app and the API
└── vite.config.ts            # React + mion Vite plugin, API build to dist-server/
```

:spacer

## Nuxt Starter

A [Nuxt 4](https://nuxt.com) SPA starter with the mion API running on Node, Bun or Cloudflare Workers.

- Nuxt in SPA mode (`ssr: false`); `nuxt generate` outputs a static SPA
- The API runs inside `nuxt dev`
- Fully typed `@mionjs/client`
- ESLint with the Nuxt and mion lint rules
- Vitest + Playwright e2e tests preconfigured

```bash
my-app/
├── app/                      # Nuxt SPA source
│   ├── pages/                # File-based routes
│   └── lib/
│       ├── mion-client.ts    # Typed mion client wired to the API
│       └── orders-batch.ts   # batch + inputFrom example
├── api/                      # mion API
│   ├── src/
│   │   ├── router.ts         # createMionRouter()
│   │   ├── api.ts            # Route tree + mion.initRoutes()
│   │   ├── models.ts         # Shared API models
│   │   ├── features/         # Feature modules (handlers, models, repos)
│   │   ├── server.node.ts    # Node.js entry
│   │   ├── server.bun.ts     # Bun entry
│   │   └── cloudflare-worker.ts
│   ├── tests/                # Vitest API and client tests
│   └── vite.config.ts        # API build, one target per run
├── e2e/                      # Playwright tests
├── tsconfig.mion.json        # One tsconfig for the app and the API, used by mion
└── nuxt.config.ts            # Nuxt config, mion Vite plugin
```

:spacer

::note
In every starter, the [mion Vite plugin](../devtools/vite) compiles validation and the JSON round trip at build time, for faster cold starts. To deploy where runtime `new Function()` is blocked, set [`emitMode: 'both'`](/rpc/devtools/vite#all-plugin-options).
::
