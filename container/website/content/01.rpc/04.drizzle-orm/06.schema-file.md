Your migrations need real Drizzle objects, and `toDrizzle` makes them. Point `drizzle.config.ts` at one file that materializes everything you declared. Anything you do not export from that file is invisible to your migrations.

## Standalone Objects

Materializing a table or view also covers its columns, indexes, constraints and inline policies. drizzle-kit reads standalone objects on their own, so each one needs its own `toDrizzle` call:

| Declared with | Materialize |
| --- | --- |
| `pgTable`, `pgView`, `pgMaterializedView` | the table or view itself |
| `pgEnum`, `pgSequence`, `pgSchema`, `pgRole` | each handle |
| `pgPolicy(...).link(table)` | the policy itself |
| `pgPolicy` inside a table's third argument | nothing, it comes with the table |

## Importing Types in Your App

Your routes, models and client never import this file. They take their types from the schema module that declares the tables:

```ts
import {accounts} from './schema.ts';
import type {InferSelectModel} from '@mionjs/drizzle-orm';

export type Account = InferSelectModel<typeof accounts>;
```

The file above is the only one that loads Drizzle, and it only runs when you generate or apply migrations.
