---
title: Row Level Security
description: Roles, policies and enableRLS on PostgreSQL tables, recorded for your migrations.
---

Row level security is PostgreSQL only. Roles and policies are recorded like everything else, so drizzle-kit sees them in your migrations.

None of it changes your row types. RLS decides what the database lets through, not what your app reads.

<code-import path="packages/examples/src/drizzle/drizzle-rls-example.ts" lang="ts" />

## Roles

`pgRole(name, config)` declares a role for drizzle-kit to create. `existing()` marks a role that is already there, so drizzle-kit leaves it alone:

```ts
const appUser = pgRole('app_user', {createRole: true});
const authenticated = pgRole('authenticated').existing();
```

## Policies

A policy declared in the table's third argument belongs to that table and comes along with it. `as`, `for`, `to`, `using` and `withCheck` are Drizzle's own options.

A policy can also live apart from its table and attach with `link()`. That one belongs to no table, so export it and materialize it yourself, or your migrations will not see it:

```ts
export const adminReads = pgPolicy('admin_reads', {for: 'select', using: sql`true`}).link(documents);
```

## Turning it on

`enableRLS()` turns the switch on for a table. It can only be called once: the type it returns no longer carries the method, the same as in Drizzle.

## Provider helpers

Helpers like `crudPolicy` from `drizzle-orm/neon`, and the predefined roles in `drizzle-orm/supabase`, are not wrapped here. Import them from Drizzle and drop the result straight into the array. It passes through untouched:

```ts
import {crudPolicy} from 'drizzle-orm/neon';

pgTable('docs', {...}, () => [crudPolicy({role: admin, read: true, modify: false})]);
```
