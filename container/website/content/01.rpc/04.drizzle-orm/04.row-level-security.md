title: Row Level Security
description: Roles, policies and enableRLS on PostgreSQL tables, recorded for your migrations.
---

Row level security is PostgreSQL only. drizzle-kit sees your roles and policies in your migrations, and your row types do not change.

<code-import path="packages/examples/src/drizzle/drizzle-rls-example.ts" lang="ts" />

## Database Roles

`pgRole(name, config)` declares a role for drizzle-kit to create. `existing()` marks a role that is already there, so drizzle-kit leaves it alone:

```ts
const appUser = pgRole('app_user', {createRole: true});
const authenticated = pgRole('authenticated').existing();
```

## Security Policies

A policy declared in the table's third argument belongs to that table and comes with it. `as`, `for`, `to`, `using` and `withCheck` are Drizzle's own options.

A policy declared apart and attached with `link()` belongs to no table, so export it and materialize it yourself, or your migrations will not see it:

```ts
export const adminReads = pgPolicy('admin_reads', {for: 'select', using: sql`true`}).link(documents);
```

## Enabling Row Level Security

`enableRLS()` turns row level security on for a table. You can call it only once: the type it returns drops the method, as in Drizzle.

## Provider Policy Helpers

Helpers like `crudPolicy` from `drizzle-orm/neon`, and the predefined roles in `drizzle-orm/supabase`, are not wrapped here. Import them from Drizzle and put the result in the array as is:

```ts
import {crudPolicy} from 'drizzle-orm/neon';

pgTable('docs', {...}, () => [crudPolicy({role: admin, read: true, modify: false})]);
```
