title: Relations
description: Why relations stay on Drizzle, and how to declare them over your materialized tables.
---

Relations are declared with Drizzle, not here. They emit no SQL and create no foreign keys: they exist so Drizzle's query builder can nest your results. That makes them part of the query layer, and the query layer is Drizzle's.

In practice this costs you nothing. Declare your schema with the slim packages, materialize it with `toDrizzle`, then declare relations over the result in the file that runs your queries.

## Why the split helps

Your schema file stays free of Drizzle types, so the row types it exports travel through your routes and your client cheaply. The query file is where Drizzle already lives, so relations cost nothing extra there.

If you want a nested shape to cross your API, build it from the slim models rather than from Drizzle's inferred query type:

```ts
export interface AuthorWithPosts extends Author {
  posts: Post[];
}
```

That type is plain data. It validates, it serializes, and your client gets it without loading Drizzle.

## Foreign keys are separate

A relation is not a foreign key. If you want the database to enforce the link, declare it in the schema with `references()` or `foreignKey()` (see [Indexes and Constraints](/rpc/drizzle-orm/constraints)). Relations only describe the shape of a nested read.
