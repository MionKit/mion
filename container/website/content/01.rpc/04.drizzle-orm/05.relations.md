Relations are declared with Drizzle, not here. They emit no SQL and create no foreign keys: they exist so Drizzle's query builder can nest your results, which makes them part of Drizzle's query layer. Declare your schema with the slim packages, materialize it with `toDrizzle`, then declare relations over the result in the file that runs your queries.

<code-import path="packages/private-examples/src/drizzle/drizzle-relations-example.ts" lang="ts" />

## Why Relations Stay in the Query File

Your schema file stays free of Drizzle types, so the row types it exports stay cheap in your routes and your client. The query file already loads Drizzle, so relations cost nothing extra there.

## Nested Results in Your API

To send a nested shape through your API, build it from the slim models rather than from Drizzle's inferred query type:

```ts
export interface AuthorWithPosts extends Author {
  posts: Post[];
}
```

That type is plain data: it validates, it serializes, and your client gets it without loading Drizzle.

## Foreign Keys

A relation is not a foreign key. For the database to enforce the link, declare it in the schema with `references()` or `foreignKey()` (see [Indexes and Constraints](/rpc/drizzle-orm/constraints)).
