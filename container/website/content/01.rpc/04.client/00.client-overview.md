Routes are called like any other async function. The client only imports the API type from the server, so no server code ever reaches the browser.

## Calling Routes

The `routes` and `middlewares` objects hold every remote route and middleware, except a middleware that takes no params and returns no data. Calling a route creates a `RouteSubRequest`, and `call()` sends it.

The client follows the validation and JSON round trip rules set on the server, including the params [sanitizing](/rpc/server/validation#sanitizing-params) transforms. Wrong params fail in the browser, with no request sent.

::note
By default the build ships each route's validation and JSON round trip functions with the client. To fetch them from the server instead, see [mionFetchMetadata](/rpc/middlewares/fetch-metadata).
::

## Queries and Mutations

A `query()` is read only, so small payloads travel in the url as a GET. A `mutation()` changes data, so it always travels in the body as a POST. A plain `route()` also travels in the body.

::tip
Cancelling a query is always safe, the worst case is wasted work on the server. A cancelled mutation may already have changed data. See [Cancellation and Timeouts](/rpc/client/cancellation-timeouts).
::

## Validating Server Responses

The server does not check its answers. Set `validateServerResponses: true` to check every answer and returned header against its type on the client.
The type errors of a wrong answer or header go in `errorData`.
