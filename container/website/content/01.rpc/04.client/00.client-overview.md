## Features

| Feature | What you get |
| --- | --- |
| Typed remote methods | Every route and middleware shows up with its params and return type, with autocompletion and static type checking. |
| Never throws | The result and the error come back together, so there is nothing to wrap in try/catch. |
| Validation and serialization | Params are validated, and params and results are serialized out of the box, including Date, Map and Set. |
| Local validation | Wrong params are caught in the browser, with no request to the server. |
| Local sanitizing | The same transforms the route declares (trim, lowercase, strip separators) run before validation and before sending. |
| Response checks | Turn on `validateServerResponses` to check every answer against its return type. |
| Middleware hooks | A middleware gets its data, like an auth token, from a hook that runs before every request. Its response hooks can retry the call. |
| Route sync | A call built against outdated route types is stopped before it runs, see [mionSyncRoutes](/rpc/middlewares/mion-sync-routes). |

## Sending Middleware Data

A middleware gets its data, like an auth token, from its `onRequest` hook. Call the function the hook receives with the middleware params, or skip the call to send nothing.

::code-split
<code-import path="packages/private-examples/src/client/client-middleware-hooks.ts" lang="ts [client.ts]" />
<code-import path="packages/private-examples/src/client/middleware-hooks.routes.ts" lang="ts [server.routes.ts]" />
::

| Hook | Runs | Removed with |
| --- | --- | --- |
| `onRequest` | Before each request that runs the middleware, a route's first call included. It can be async. Its second argument is the request, to pick data per route. A middleware has one. | `offRequest()` |
| `onResponse` | After each successful middleware result, strongly typed. Several run in the order added, even when one throws. | `offResponse(handler)`, only that one |
| `onError` | After each declared error of the given `type`, strongly typed. Several per type run in the order added, even when one throws. | `offError(type, handler)`, only that one |

::tip
If `onRequest` throws or rejects, the request is not sent and `undeclared` holds the error. Undeclared errors (transport, platform, framework) never reach `onError`.
::

### Retrying a Call

`onResponse` and `onError` get the call as a second argument. Its `retry()` sends the whole call again, for example after refreshing a token, and runs every `onRequest` first. Each middleware can retry once per call.

| Route | Retry allowed |
| --- | --- |
| `query()` | Always |
| `mutation()` or `route()` | Only if the call failed: the route returned an error, or it returned nothing and the response has an error |

::note
`retry()` returns `false` when it is not allowed, and the call keeps its current result.
::
