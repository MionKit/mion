## The Result Pattern

`call()` returns `[result, error, response]`. The result and the error come only from the route, and both are strongly typed: its return value, or one of its declared errors or a validation error. Every other error goes to the response and leaves both `undefined`.

::code-split
<code-import path="packages/private-examples/src/client/result-route-error.ts" lang="ts [returned by the route]" />
<code-import path="packages/private-examples/src/client/result-outside-route.ts" lang="ts [failed outside the route]" />
::

::tip
An empty result is not always a success. Check the response before you read it as one.
::

::note
The client builds the result, the server never sees it. Your handlers just return a value or an `RpcError`.
::

## Middleware Errors

A middleware's declared errors reach its `onError` hook and its path in the response, both strongly typed. Use the hook for app-wide handling, like a logout on `not-authorized`. To send a middleware its data, see [Middleware Hooks](/rpc/client/client-middleware#middleware-hooks).

::warning
Hooks run on every request that includes the middleware, whether or not you also read the response. Every `onError` for an error type runs, in the order added.
::
