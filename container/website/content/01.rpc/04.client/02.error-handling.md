## The Result Pattern

`call()` returns three slots: what the route returned, the error it declared, and the whole response. You usually read only the first two.

::code-split
<code-import path="packages/private-examples/src/client/result-short.ts" lang="ts [the two slots you need]" />
<code-import path="packages/private-examples/src/client/result-full.ts" lang="ts [all three slots]" />
::

| Slot | Name | What it holds |
| --- | --- | --- |
| 0 | result | What the route returned, if it ran and succeeded. |
| 1 | error | The route's declared errors plus `ValidationError`. A closed, strongly typed union. |
| 2 | response | Every answer in the response, by path: `response.products.pagination` for the `products/pagination` middleware. Each middleware is typed with its return value, declared errors and `ValidationError`. |
| 2 | `response['@thrownErrors']` | An array of every error nobody declared: a timeout, abort or network failure, a platform error, an undeclared throw, or a failed hook. Each is an open `RpcError<string>`. |

::note
The client builds the result, the server never sees it. Your handlers just return a value or an `RpcError`.
::

## Middleware Errors

A middleware's declared errors reach its `onError` hook and its path in the response, both strongly typed. Use the hook for app-wide handling, like a logout on `not-authorized`. To send a middleware its data, see [Middleware Hooks](/rpc/client/client-middleware#middleware-hooks).

::warning
Hooks run on every request that includes the middleware, whether or not you also read the response. Every `onError` for an error type runs, in the order added.
::
