Every server middleware with params or a result shows up in the client's `middlewares` object. Use it to send the middleware its data and handle what it returns.

## Middleware Hooks

Each middleware in `middlewares` has three hooks. `onRequest` sends its data, like a trace id. `onResponse` gets its result and `onError` its declared errors.

::code-split
<code-import path="packages/private-examples/src/client/client-middleware-hooks.ts" lang="ts [client.ts]" />
<code-import path="packages/private-examples/src/client/middleware-hooks.routes.ts" lang="ts [server.routes.ts]" />
::

| Hook | Runs | Removed with |
| --- | --- | --- |
| `onRequest` | Before each request that runs the middleware, a route's first call included. It can be async. Its second argument is the request, to pick data per route. A middleware has one. | `offRequest()` |
| `onResponse` | After each successful middleware result, strongly typed. Several run in the order added, even when one throws. | `offResponse(handler)`, only that one |
| `onError` | After each declared error of the given `type`, strongly typed. Several per type run in the order added, even when one throws. | `offError(type, handler)`, only that one |

::tip
`onRequest` gets a function. Call it with the middleware params, or skip it to send nothing.
::

::note
If `onRequest` fails, the request is not sent and the error goes to `response['@thrownErrors']`. `onError` only gets the errors the middleware declares.
::

## Retrying a Call

`onResponse` and `onError` get the call as a second argument. Its `retry()` sends the whole call again, for example after refreshing the session, and runs every `onRequest` first. Each middleware can retry once per call.

| Route | Retry allowed |
| --- | --- |
| `query()` | Always |
| `mutation()` or `route()` | Only if the call failed: the route returned an error, or it returned nothing and the response has an error |

::note
`retry()` returns `false` when it is not allowed, and the call keeps its current result.
::

## Reusable Client Middleware

A middleware is usually written only for the server. With mion it can also ship its client side as an installer, a function that receives `middlewares.x` and sets its hooks, so every app gets the same behaviour. Type its parameter with `ClientMiddlewareOf<typeof handler>`, so it works wherever the app places the middleware.
