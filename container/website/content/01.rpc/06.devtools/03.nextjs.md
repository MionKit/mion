mion resolves your types at build time, so the transform has to run wherever your code is
compiled. In a Next.js app that is Next itself, and `withMion` wires it up in one line.

<code-import path="packages/examples/src/codegen/next-config.ts" lang="ts [next.config.ts]" />

The `await` is required. The whole-program scan has to finish before the bundler starts
handing files over, and there is no later point to wait at.

That is the whole setup. Your front end gets the same compiled validators and serializers
the rest of mion uses, from the same types.

## Turbopack and webpack

`withMion` picks the right road for you.

Turbopack has no plugin API, so mion does not use one. Your `next.config` runs before any
bundler worker exists, so mion starts a small background process there that holds the type
resolver, then registers a loader that asks it to rewrite each file. You do not configure
any of that.

Running `next --webpack` instead? mion detects it and uses the ordinary webpack plugin. Same
result, nothing to change.

Only your own TypeScript is rewritten. Files in `node_modules` are left alone.

## Sharing Batches With Your API

If your client sends [batches](/rpc/client/batch), your Next app is the client half, and it needs
nothing: the transform gives every batch its id and every inline `inputFrom` mapper its hash. Your
mion API's own build generates the batch table and the mapper modules from this app's program. Point
its Vite config at this app's tsconfig:

there is no build order to keep.

## Editing types while the dev server runs

Edit a type in one file and every file that reflects it recompiles, including types declared
in a `.d.ts` with no import to follow. mion tells the bundler what each rewrite depends on,
so `next dev` stays correct without a restart.

## Options

`withMion` takes the same `runTypes` block and the same `client` pointer as the Vite plugin, so
[Vite Configuration](/rpc/devtools/vite) is the reference for every knob. The `client` pointer only
matters for the rare Next app that hosts the mion API itself.

Three Vite options have no meaning here and are not accepted: the Vue single file component
pass, middleware mode and the managed server (the `server` block). Next runs its own dev server,
and your mion API is a separate process.
