title: Linter
description: ESLint rules specific for mion that ensure RunTypes works properly.
---

mion ships an ESLint plugin with rules that catch common mistakes in mion routes and middleFns. It comes with `@mionjs/devtools`, on the `/eslint` entry, so there is no separate package to install.


## Summary

| Rule | Description | Recommended |
|------|-------------|-------------|
| `strong-typed-routes` | Ensures handlers have explicit type annotations | ✅ Error |
| `no-unreachable-union-types` | Detects unreachable union type members | ✅ Error |
| `no-unsafe-property-names` | Refuses properties named `__proto__`, `prototype` or `constructor` | ✅ Error |

## Installation

```bash
npm install @mionjs/devtools -D
```

## Configuration

The plugin needs ESLint's flat config (`eslint.config.js`). It is ESM only, so the older
`.eslintrc.json` format cannot load it.

Pick the rules yourself:

```js [eslint.config.js]
import {mionPlugin} from '@mionjs/devtools/eslint';

export default [
  {
    plugins: {'@mionjs': mionPlugin},
    rules: {
      '@mionjs/strong-typed-routes': 'error',
      '@mionjs/no-unreachable-union-types': 'error',
      '@mionjs/no-unsafe-property-names': 'error',
    },
  },
];
```

Or use the recommended config, which registers the mion rules together with the type
diagnostics from the compiler (the default export is the compiler's own plugin):

```js [eslint.config.js]
import runtypes from '@mionjs/devtools/eslint';

export default [runtypes.configs.recommended];
```

## Rules

### `@mionjs/strong-typed-routes`

Ensures that all route and middleFn handlers have explicit type annotations for parameters and return types. This is essential for mion's automatic validation and serialization to work correctly.

#### Why is this important?

mion uses TypeScript types at runtime to generate validation and serialization functions. Without explicit types, mion cannot properly validate incoming data or serialize responses.

### `@mionjs/no-unreachable-union-types`

Detects union types where some members can never be matched because a less specific type appears earlier in the union. This is particularly important for mion because it affects how data is validated and deserialized.

#### Why is this important?

When mion deserializes incoming JSON data, it tries to match against union types in order. If a less specific type (with fewer properties) comes before a more specific type (with more properties), the more specific type will never be matched because the less specific type will always match first.

### Purity is checked by RunTypes, not mion

mion used to ship a `@mionjs/pure-functions` rule. It was a hand-written reimplementation of the
RunTypes purity checker and has been removed: `runtypes/pure-functions` from
`@mionjs/devtools/eslint` surfaces the resolver's own diagnostics (`PFE9006`–`PFE9011`,
`PFN001`–`PFN002`) and covers the same ground with the same rules the build enforces. See the
[Pure Functions](/runtypes/guide/pure-functions) guide.

## RunTypes compiler rules (`runtypes/*`)

mion's own rules above are **additive**: they sit alongside the 25 `runtypes/*` rules shipped by
`@mionjs/devtools`, which surface the RunTypes compiler's own diagnostics as lint results. They
are the same diagnostics you would see at build time, reported on the line that caused them.

The recommended config enables them next to mion's, so one entry covers both families:

```js [eslint.config.js]
import runtypes from '@mionjs/devtools/eslint';

export default [runtypes.configs.recommended];
```

### Markers and pure functions

| Rule | What it catches | Recommended |
|------|-----------------|-------------|
| `runtypes/broken-tsconfig` | The tsconfig the linter was pointed at is missing or does not parse, so type-aware linting cannot run | ✅ Error |
| `runtypes/invalid-marker` | A marker the build cannot turn into a function: an unfilled generic, a non-literal options argument, an unresolved import | ✅ Error |
| `runtypes/redundant-marker` | A marker that works but probably does not do what you meant — e.g. a call made only to read its return type | ⚠️ Warn |
| `runtypes/pure-functions` | A registered pure function that breaks purity (`this`, `await`, `yield`, dynamic import, blocked globals, outer variables), is double-registered, or is referenced but never registered | ✅ Error |

### Validation

| Rule | What it catches | Recommended |
|------|-----------------|-------------|
| `runtypes/validate-non-serializable` | A type that can never be validated — validators only see the data-only projection | ✅ Error |
| `runtypes/validate-skipped-member` | A member the validator silently skips (function, method, static, symbol) | ⚠️ Warn |
| `runtypes/non-enumerable` | A `@nonEnumerable` property that is not optional — it can be absent, so the type must allow `undefined` | ✅ Error |
| `runtypes/unknown-keys` | A member the unknown-keys helpers skip | ⚠️ Warn |

### Serialization

| Rule | What it catches | Recommended |
|------|-----------------|-------------|
| `runtypes/json-non-serializable` | A type that can never be encoded to or decoded from JSON | ✅ Error |
| `runtypes/json-skipped-member` | A member the JSON encoder/decoder leaves out | ⚠️ Warn |
| `runtypes/binary-non-serializable` | A type that can never be serialized to or from binary | ✅ Error |
| `runtypes/binary-skipped-member` | A member the binary encoder/decoder leaves out | ⚠️ Warn |
| `runtypes/class-serializer` | A class serialized structurally because no serializer is registered — decodes to a plain object, not an instance | ⚠️ Warn |
| `runtypes/clone-unsupported-type` | A type `cloneExactShape` cannot clone safely (union of objects, callable root) | ✅ Error |
| `runtypes/clone-shared-reference` | A member the clone cannot rebuild, so both copies point at the same value | ⚠️ Warn |

### Formats and overrides

| Rule | What it catches | Recommended |
|------|-----------------|-------------|
| `runtypes/format` | A custom string format with a broken definition — a sample that fails its own pattern, invalid params, an uncompilable regex | ✅ Error |
| `runtypes/invalid-override` | The same (type, function) pair registered twice, or a redirect to a module that does not exist | ✅ Error |
| `runtypes/override-side-effect` | A `validate` override that also changes the JSON/binary union decoders, which run validation internally | ⚠️ Warn |
| `runtypes/other` | Any other compiler diagnostic, reached when a locally built binary runs ahead of the message catalog | ✅ Error |

### Generated enrichment files (FriendlyText / MockData)

| Rule | What it catches | Recommended |
|------|-----------------|-------------|
| `runtypes/no-enrichment-todo` | An unfilled `@todo` placeholder the generator scaffolded | ✅ Error |
| `runtypes/no-orphan-carcass` | A commented-out `@rtOrphan` block left behind when a type or field disappeared | ✅ Error |
| `runtypes/enrichment-field` | An entry that no longer matches its type — unknown field, reserved `rt$` prefix, plural template missing its `other` arm | ✅ Error |
| `runtypes/enrichment-message` | A message template with an undeclared error key, unknown `$[placeholder]`, or invalid plural arm | ⚠️ Warn |
| `runtypes/enrichment-broken-source` | A generated mirror whose source file or type is gone | ✅ Error |
| `runtypes/enrichment-misplaced-file` | A generated mirror that is no longer where the generator would write it | ⚠️ Warn |

::note
The `error` severities above are `@mionjs/devtools`' own defaults and mion keeps them as-is: every
one of them marks output that is **wrong or impossible to generate**, not a style preference, so
finding out at build time is the point. The `warn` rules all describe something that still works but
silently drops or reshapes data — worth reading, not worth blocking on.
::

---

::note
All rules are included in the `plugin:@mionjs/recommended` configuration and are enabled by default with `error` severity.
::

### `@mionjs/no-unsafe-property-names`

Refuses a property named `__proto__`, `prototype` or `constructor` in any interface, type literal or class, optional or not, however deeply nested. Those names are never data: every decoder refuses them on the wire, validation refuses them under an index signature, and the build fails for any type a route compiles with one of them. This rule reports the declaration itself, so the problem shows up in the editor before a build, and for types no route reaches yet.

The one way past it is on purpose: a type that describes a real constructor (a cast reaching a class through its `prototype`, say) never crosses the wire, so disable the rule on that line with an `eslint-disable-next-line` comment and leave a note saying why.

#### ✅ Valid Examples

```ts
interface Settings {
  builder: string;
}

class Box {
  size: number;
  constructor(size: number) {
    this.size = size;
  }
}
```

#### ❌ Invalid Examples

```ts
interface Settings {
  constructor: string;
}

type Poison = {
  __proto__: {admin: boolean};
};
```
