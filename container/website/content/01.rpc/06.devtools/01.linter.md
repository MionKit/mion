title: Linter
description: Lint rules that catch mistakes in mion routes as you write them.
---

`@mionjs/devtools/eslint` is an ESLint plugin that catches common mistakes in mion routes and middleware. It ships inside `@mionjs/devtools`, so there is no separate package.

The rules use the mion compiler that builds your validation and serialization, so they read your types. A handler is checked however you write it: inline, passed by name, typed with `Handler`, wrapped in `satisfies`, or tagged with JSDoc.

## Rule Summary

| Rule | Description | Recommended |
|------|-------------|-------------|
| `strong-typed-routes` | Ensures handlers have explicit type annotations | ✅ Error |
| `no-throw-in-handlers` | Reports a `throw` inside a route or middleware handler | ✅ Error |
| `returned-error-type` | Reports a declared error that is not an `RpcError` | ✅ Error |
| `no-unsafe-property-names` | Reports a property named `__proto__` | ⚠️ Warn |
| `enforce-type-imports` | Reports a value import from backend code, so server code stays out of the frontend bundle | Off, needs a `backendSources` option |

## Installing the Plugin

```bash
npm install @mionjs/devtools -D
```

## Picking Rules

The plugin is ESM only, so it needs ESLint's flat config (`eslint.config.js`), not `.eslintrc.json`.

```js [eslint.config.js]
import {mionPlugin} from '@mionjs/devtools/eslint';

export default [
  {
    plugins: {'@mionjs': mionPlugin},
    rules: {
      '@mionjs/strong-typed-routes': 'error',
      '@mionjs/no-throw-in-handlers': 'error',
      '@mionjs/returned-error-type': 'error',
      '@mionjs/no-unsafe-property-names': 'warn',
    },
  },
];
```

## Recommended Config

The recommended config, on the default export, turns on the mion rules and the RunTypes compiler rules
at the levels their tables show. It leaves out `enforce-type-imports`.

```js [eslint.config.js]
import runtypes from '@mionjs/devtools/eslint';

export default [runtypes.configs.recommended];
```

::note
The rules read `tsconfig.json` from the directory the linter runs in. Point them at another file
with `settings: {runtypes: {tsconfig: 'tsconfig.lint.json'}}`.
::

## mion Rules

### Typed Handlers

`@mionjs/strong-typed-routes` reports a route or middleware handler without explicit parameter and return types. mion builds validation and serialization from those types, so without them it cannot check incoming data or serialize responses. Only the call context needs no type, since it is never sent over the network.

### Returning Errors Instead of Throwing

`@mionjs/no-throw-in-handlers` reports a `throw` that escapes a route, query, mutation, middleware or headersFn handler. A returned error stays in the signature, so the client gets it typed. A thrown one goes to the undeclared slot, the client sees only its public message, and the declared return type is no longer true.

```ts
return new RpcError({...});   // the client gets it typed, the rest of the chain keeps running
return new FatalError({...}); // the client gets it typed, the request stops here
```

::note
A `throw` is still the way out for an error nobody declared, such as a bug or an infrastructure failure. Turn the rule off on that line with `eslint-disable-next-line @mionjs/no-throw-in-handlers` and say why.
::

### Returned Error Types

`@mionjs/returned-error-type` reports a handler whose declared return type can be an error that is not an `RpcError`. Only `RpcError` and its subclasses, such as `FatalError` or your own, get a typed slot in the response. Any other error fails the request and goes to the undeclared slot, so the code compiles but the client never gets the error its type promised.

### Unsafe Property Names

`@mionjs/no-unsafe-property-names` reports a property named `__proto__` in any interface, type literal or class, optional or not, at any depth. Writing that key on a plain object changes its prototype instead of storing a value, so every compiled function drops the member and its value is lost. TypeScript accepts it and nothing else tells you, so the rule reports the declaration in your editor before a build, even for types no route uses yet.

The rule allows `prototype` and `constructor`.

#### ✅ Valid Examples

```ts
interface Settings {
  builder: string;
  constructor: string;
  prototype: string;
}

class Box {
  size: number;
  constructor(size: number) {
    this.size = size;
  }
}
```

#### ❌ Invalid Examples

```ts
interface Settings {
  __proto__: string;
}

type Poison = {
  __proto__: {admin: boolean};
};
```

---

### Removed Rules

**Purity is checked by RunTypes, not mion.** `runtypes/pure-functions` reports the same purity errors the build does (`PFE9006` to `PFE9011`, `PFN001` to `PFN002`). See the [Pure Functions](/runtypes/guide/pure-functions) guide.

**Union order is handled for you.** The compiler orders union members when it builds the validator, so you can write them in any order and a looser member never shadows a more specific one.

## Compiler Lint Rules

`@mionjs/devtools` also ships 27 `runtypes/*` rules that report the RunTypes compiler's errors about
your types. Both sets come from the same compiler pass; the two prefixes let you set their levels
separately.

| Group | Rule | What it catches | Recommended |
|-------|------|-----------------|-------------|
| Markers | `runtypes/broken-tsconfig` | The tsconfig the linter was pointed at is missing or does not parse, so type-aware linting cannot run | ✅ Error |
| Comments | `runtypes/invalid-expect-error` | A `@mion-expect-error` comment that hides nothing, names a code that is always reported, or names a code that does not exist | ⚠️ Warn |
| Comments | `runtypes/invalid-downgrade-error` | A `@mion-downgrade-error` comment that lowers nothing, names a code that always stops the build, names a code that does not exist, or names one that is already a warning | ⚠️ Warn |
| Markers | `runtypes/invalid-marker` | A marker the build cannot turn into a function: an unfilled generic, a non-literal options argument, an unresolved import | ✅ Error |
| Markers | `runtypes/redundant-marker` | A marker that works but probably does not do what you meant (for example a call made only to read its return type) | ⚠️ Warn |
| Purity | `runtypes/pure-functions` | A registered pure function that breaks purity (`this`, `await`, `yield`, dynamic import, blocked globals, outer variables), is double-registered, or is referenced but never registered | ✅ Error |
| Validation | `runtypes/validate-non-serializable` | A type that can never be validated: validators only see the data-only projection | ✅ Error |
| Validation | `runtypes/validate-skipped-member` | A member the validator silently skips (function, method, static, symbol) | ⚠️ Warn |
| Validation | `runtypes/non-enumerable` | A `@nonEnumerable` property that is not optional, so the tag does nothing and the property always serializes | ⚠️ Warn |
| Validation | `runtypes/unknown-keys` | A member the unknown-keys helpers skip | ⚠️ Warn |
| Serialization | `runtypes/json-non-serializable` | A type that can never be encoded to or decoded from JSON | ✅ Error |
| Serialization | `runtypes/json-skipped-member` | A member the JSON encoder/decoder leaves out | ⚠️ Warn |
| Serialization | `runtypes/binary-non-serializable` | A type that can never be serialized to or from binary | ✅ Error |
| Serialization | `runtypes/binary-skipped-member` | A member the binary encoder/decoder leaves out | ⚠️ Warn |
| Serialization | `runtypes/clone-unsupported-type` | A type `cloneExactShape` cannot clone safely (union of objects, callable root) | ✅ Error |
| Serialization | `runtypes/clone-shared-reference` | A member the clone cannot rebuild, so both copies point at the same value | ⚠️ Warn |
| Serialization | `runtypes/unsafe-property-name` | A type a marker compiles that declares `__proto__` | ⚠️ Warn |
| Formats | `runtypes/format` | A custom string format with a broken definition (a sample that fails its own pattern, invalid params, an uncompilable regex) | ✅ Error |
| Overrides | `runtypes/invalid-override` | The same (type, function) pair registered twice, or a redirect to a module that does not exist | ✅ Error |
| Overrides | `runtypes/override-side-effect` | A `validate` override that also changes the JSON/binary union decoders, which run validation internally | ⚠️ Warn |
| Other | `runtypes/other` | Any other compiler diagnostic, reached when a locally built binary runs ahead of the message catalog | ✅ Error |
| FriendlyText / MockData | `runtypes/no-enrichment-todo` | An unfilled `@todo` placeholder the generator scaffolded | ⚠️ Warn |
| FriendlyText / MockData | `runtypes/no-orphan-carcass` | A commented-out `@rtOrphan` block left behind when a type or field disappeared | ⚠️ Warn |
| FriendlyText / MockData | `runtypes/enrichment-field` | An entry that no longer matches its type: an unknown field, or a property colliding with the reserved `rt$` prefix | ✅ Error |
| FriendlyText / MockData | `runtypes/enrichment-message` | A message template with an undeclared error key, an unknown `$[placeholder]`, an invalid plural arm, or a plural missing its `other` arm | ⚠️ Warn |
| FriendlyText / MockData | `runtypes/enrichment-broken-source` | A generated mirror whose source file or type is gone | ✅ Error |
| FriendlyText / MockData | `runtypes/enrichment-misplaced-file` | A generated mirror that is no longer where the generator would write it | ⚠️ Warn |

::note
An `error` rule marks output that is wrong or cannot be generated. A `warn` rule marks something
that still works, but drops data silently or is only untidy.
::

::note
The level here is what your editor shows, not always what your build does. `enrichment-field` is an
`error` rule whose findings are only Warnings to the build. A rule that can report an Error or a
RuntimeError is always `error`. See [Diagnostics](/runtypes/diagnostics/error-levels).
::
