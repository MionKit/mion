`mion compile` is the tsc-like lane of the same compiler the Vite plugin runs: it rewrites your marker call sites, emits `.js` files to your tsconfig `outDir`, writes the generated modules under the gen dir, and generates the batch transport. Use it when a project has no bundler, or when you want plain emitted files the way `tsc` produces them.

## Compiling a Server

Run it from the server project. When the client is a separate project, name its tsconfig, exactly like `client.tsConfig` on the Vite plugin:

```bash
mion compile --tsconfig tsconfig.json --client-tsconfig ../client/tsconfig.json
```

The command reads every `batch([...])` and inline `inputFrom` mapper out of the client program, writes `.mion/rpc/` (the batch table plus one module per mapper) under the gen dir, and appends the table's import to the emitted module that calls `createMionRouter`, relativized to where that file was emitted. Leave `--client-tsconfig` out when client and server are one project.

The same pointer can live in your tsconfig, so the flag is only needed when a single build differs:

```json
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "clientTsconfig": "../client/tsconfig.json"}]
  }
}
```

## Compiling a Client

Run it from the client project. The emitted files carry every batch id and every inline mapper hash, from the same source the server reads, so there is no build order to keep:

```bash
mion compile --tsconfig tsconfig.json
```

## What Lands Where

| Output | Location |
| --- | --- |
| Emitted `.js` (and source maps when the tsconfig asks for them) | The tsconfig `outDir` |
| Generated validators and serializers | `<genDir>/types/` |
| Batch table and mapper modules (server only) | `<genDir>/rpc/` |

The gen dir defaults to `.mion` next to your source; `--gen-dir` overrides it. Every import between these files is relative, so the emitted tree runs from wherever you deploy it.

::note
`mion compile --no-emit` checks a project and reports the build diagnostics without writing anything, like `tsc --noEmit`.
::

## Shared Options

Every project option from the [RunTypes configuration](/runtypes/introduction/configuration) works as a flag with the same name in kebab case (`--emit-mode`, `--gen-dir`, `--hash-length`), and a flag wins over the tsconfig entry, which wins over the default. Run `mion compile -h` for the full list.
