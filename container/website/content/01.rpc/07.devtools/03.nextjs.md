That is the whole setup. Your front end gets the same compiled validation and JSON round trip functions as the rest of mion, from the same types.

## Turbopack and webpack

`withMion` picks the right setup for you. Turbopack has no plugin API, so mion starts a background process from `next.config` and registers a loader that asks it to rewrite each file. With `next --webpack`, mion uses the ordinary webpack plugin.

Only your own TypeScript is rewritten. Files in `node_modules` are left alone.

## Batches in Your Next App

Nothing to configure. The same build reads your [batches](/rpc/client/batch) and compiles them into the route handler. Batches need the API in this app's build.

## Editing Types While the Dev Server Runs

Edit a type and every file rewritten from it recompiles, even when the type sits in a `.d.ts` with no import to follow. `next dev` stays correct without a restart.

## Options

`withMion` takes the same `tsConfig`, `client` and `runTypes` options as the Vite plugin, see [Vite Configuration](/rpc/devtools/vite#all-plugin-options). For example, `client: {routes: 'fetch'}` gets each route's metadata from the server instead of bundling it:

<code-import path="packages/private-examples/src/codegen/next-fetched-config.ts" lang="ts [next.config.ts]" />

See [mionFetchMetadata](/rpc/middlewares/fetch-metadata-client#disabling-routes-metadata-bundling).

The Vite `server` block is refused, and the Vue single file component switch is ignored. Next runs its own dev server and builds your API route with everything else.
