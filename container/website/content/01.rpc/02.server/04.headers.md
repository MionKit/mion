`HeadersSubset` is the type for the headers a handler reads or sends. mion validates them like any other param.

## Reading Request Headers

`mion.headersMiddleware` creates a middleware that reads request headers. Its second parameter is a `HeadersSubset<Required, Optional>`: the first type lists the headers a request must send, the second those it may send.

<code-import path="packages/private-examples/src/router/middlewares-optional-headers.ts" lang="ts" />

| Rule | What it means |
| --- | --- |
| Name case | Not case sensitive: a request with `authorization` matches `Authorization`. You read the value by the name you declared. |
| Values | Always strings. Parse numbers or dates yourself. |
| Other params | Params after the `HeadersSubset` come from the request body, as in any middleware. |

::tip
Only the declared names reach the handler. To read any other header, use `ctx.request.headers.get(name)`, see [Call Context](/rpc/server/call-context).
::

## Missing or Invalid Headers

A request without a required header, or with an empty one, ends with a `validation-error` (HTTP 422) before the handler runs. The client gets it typed like any [validation error](/rpc/server/validation).

## Sending Response Headers

Return a `HeadersSubset` from a middleware or a route to send its values as response headers, never in the body. In code built with mion, `new HeadersSubset(...)` throws a `headers-validation-error` inside your handler when a header is missing or has the wrong type, and no header is sent. The router does not check headers after your handler returns.

::tip
An optional header you leave out is not sent. When two handlers set the same header, the last one in the [execution chain](/rpc/server/middleware#execution-chain) wins.

## Headers on Every Response

The `globalResponseHeaders` router option adds headers to every response. The `defaultResponseHeaders` option of a platform adapter, like `startNodeServer`, does the same for the servers it starts. When two sources set the same header, the one higher in the table wins.

<code-import path="packages/private-examples/src/router/headers-global.routes.ts" lang="ts" />

| Order | Source |
| --- | --- |
| 1 | A `HeadersSubset` a handler returns |
| 2 | The adapter's `defaultResponseHeaders` |
| 3 | The router's `globalResponseHeaders` |
| 4 | The headers mion adds: `x-build-version`, and `server` on Bun, Cloudflare and Vercel |

## Build Version Header

mion adds an `x-build-version` header to every response: the version of the API the server was built from. A client built against another version gets an `api-version-mismatch` error, see [API Version Check](/rpc/middlewares/fetch-metadata-client#api-version-check). Set `apiVersionCheck: false` to stop sending the header and turn the client check off.

```ts
const mion = createMionRouter({apiVersionCheck: false});
```

## Error Type Header

When an error [ends the request](/rpc/server/error-handling#stopping-the-request), the response gets an `x-rpc-error` header with the error's `type`. A proxy or a log can read it without parsing the body.

::note
Only the first error that ends the request sets it. A `type` with characters other than letters, digits and `_ . : @ -`, or longer than 128 characters, makes the header read `unknown-error`. The body still has the full type.
::
