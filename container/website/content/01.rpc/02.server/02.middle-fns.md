Declare a middleFn (middleware function) with `mion.middleFn`, one of the helpers [the router](/rpc/server/routes#creating-the-router) returns. MiddleFns run before or after a route and chain together into the route's [Execution Chain](#execution-chain).

Use them for the extra work a route needs, like authorization, filters, body parsing or logging.

The first parameter is always the [Call Context](/rpc/server/routes#call-context). The other parameters come from the client, decoded and validated before the middleFn runs.

## Always Run

A thrown error or a returned `FatalError` ends the request: the remaining middleFns and the route do not run. A plain returned `RpcError` stops nothing, see [Error Handling](/rpc/server/error-handling).

A middleFn with `alwaysRun: true`, like the logger above, runs anyway, on every request.

## Requests That Already Failed

Only the middleFns that declare `alwaysRun` run for a request that failed before its route could run. None of these requests is parsed, and the two 404s never read the body.

<code-import path="packages/examples/src/router/middleFns-failed-requests.ts" lang="ts" />

| Request | Answer |
| --- | --- |
| A path that names no route | 404, `route-not-found` |
| A batch id the server does not know | 404, `batch-unknown-id` |
| A body the platform adapter refused | 413, `request-payload-too-large` |

::tip
On AWS Lambda and Google Cloud Functions the platform hands over the whole body, so the router refuses an oversized one. The middleFns registered before that point still run.
::

## Headers Functions

Use `mion.headersFn` with a `HeadersSubset<T>` parameter to read request headers, and return a `HeadersSubset` from a `middleFn` or `headersFn` to set response headers. These values travel as HTTP headers, not in the body like other params.

<code-import path="packages/examples/src/router/middleFns-header-definition.routes.ts" lang="ts" />

::note
Header names are **not case sensitive**: `Authorization` and `authorization` match the same header.
::

## Raw Middleware Functions

Use `mion.rawMiddleFn` to access the platform's native request and response. It receives the `CallContext`, the raw request, the raw response and the `RouterOptions`. It gets no remote parameters and returns no data: it can only change the context and return or throw errors.

<code-import path="packages/examples/src/router/middleFns-raw-definition.routes.ts" lang="ts" />

::tip
Raw middleFns extend the router's core: the router itself uses them to serialize and deserialize.
::

:spacer

## Execution Chain

The Execution Chain is the list of middleFns and the route that run on a route call: the middleFns before the route, the route, then the middleFns after it. It is built when the router starts, so it is the same for every request.

Everything in it runs in order, with no paths or conditions, unless an error occurs.

### Execution Order

<code-import path="packages/examples/src/router/valid-definition-order.routes.ts" lang="ts" />

**Generated Execution Chain for: `pets.getPet`**

<mermaid>
graph LR
  A(authorizationMiddleFn) --> B{{getPet}} --> E(errorHandlerMiddleFn) --> C(loggingMiddleFn)
  style B color:var(--site-accent)
</mermaid>

::note
Order matters: middleFns and routes run in the order they are defined, top down.
::

### Middleware Scope

A middleFn can run on a subset of routes only. The `userOnlyMiddleFn` above runs only for the routes under `users`, not those under `pets`.

**Generated Execution Chain for: `users.getUser`**

<mermaid>
graph LR
  A(authorizationMiddleFn) --> B(userOnlyMiddleFn) --> C{{getUser}} --> E(errorHandlerMiddleFn) --> D(loggingMiddleFn)
  style B color:#f59e0b
  style C color:var(--site-accent)
</mermaid>
