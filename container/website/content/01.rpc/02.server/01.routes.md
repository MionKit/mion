mion uses RPC-style routing: a route is a function you call remotely.

The first parameter is always the [Call Context](/rpc/server/call-context). The other parameters come from the client, decoded and validated before the route runs.

You define no URLs or paths. The API is a plain object where every entry is a route or middleware, which makes remote methods easy to reference from the client.

mion still gives each route a URL for plain HTTP requests, and the [client](/rpc/client/client-overview) handles it for you.

## Query and Mutation Handlers

The `query` and `mutation` helpers declare what a route does, so the client can choose how to send it. A `query` sends small payloads in the URL as a GET, a `mutation` always in the body. A `mion.route()` declares no intent, sends its data in the body and has no cache semantics.

<code-import path="packages/private-examples/src/router/query-mutation-definition.routes.ts" lang="ts" />

::tip
Prefer `mion.query()` and `mion.mutation()`: your code reads better, and it leaves room for future optimizations like caching layers.
::

## Undeclared Properties

By default, a param property your types do not declare is dropped while the request is decoded, not at validation. The `clone` and `compact` strategies rebuild the params from your declared type.

To reject the request instead, set `parser: {params: 'mutateStrict'}`. See [Validation](/rpc/server/validation#undeclared-properties).

## Request Size

Every route has its own request limit, set once when the routes are registered, in this order:

| Order | Limit | When it applies |
| --- | --- | --- |
| 1 | `maxBodySize` on the route | You set it on the route options. It wins. |
| 2 | Derived from the types | Every parameter of the route (and of the middleware in its chain) has a maximum: a string with `maxLength`, an array or a Set with `maxItems`, a Map with `maxItems`, and so on. The limit is the largest JSON such a body can be, times `maxBodySizeFactor` (a router option, 2 by default). |
| 3 | `maxBodySize` on the platform adapter | The types cannot say (a plain `string`, `string[]`, `Map`, record or `any`). 128 KB by default. |

<code-import path="packages/private-examples/src/router/security-max-body-size.ts" lang="ts" />

A body past the limit gets a 413 error, as early as the platform allows. Responses are not limited.

To turn type-derived limits off, set `derivedPayloadLimits: false` in the `runTypes` block of the Vite plugin or `withMion`. Every route then takes its own option or the adapter's number.

## Platform Ceilings

Some platforms refuse a request past their own ceiling before mion runs. The router never resolves a limit above it. Adapters for such a platform take the ceiling as the `maxBodySizeCap` option, so you can raise it for a bigger plan. Each platform page lists its number.

```ts
import {createCloudflareHandler} from '@mionjs/platform-cloudflare';

// a bigger plan allows more than the default ceiling
createCloudflareHandler({maxBodySizeCap: 200_000_000});
```

## Keeping the Raw Body

Once the body is parsed mion drops the raw text, so `ctx.request.rawBody` reads empty in your handlers. Set `releaseRawBody: false` in `createMionRouter` to keep it, for an access log that records exactly what arrived.

## Awaiting Every Step

mion awaits every middleware and route in the chain. Set `alwaysAwait: false` to skip the await on
synchronous handlers: faster, but the slowest requests can get slower under load.

```ts
const mion = createMionRouter({alwaysAwait: false});
```
