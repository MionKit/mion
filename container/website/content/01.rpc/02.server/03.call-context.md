Every route and middleware gets the call context as its first parameter. It holds everything about one request: the request, the response and the data your handlers share.

mion has no Express-style request and response objects. A handler reads its params and returns its answer, and mion moves both over HTTP.

## Call Context Fields

| Field | What it holds |
| --- | --- |
| `path` | The URL path of the route, like `/users/getUser`. |
| `request.headers` | The request headers, read only. See [Headers](/rpc/server/headers). |
| `request.body` | The parsed request body, one key per route or middleware. |
| `request.rawBody` | The body as it arrived. Empty once parsed, unless you set `releaseRawBody: false`. |
| `response.headers` | The response headers. See [Headers](/rpc/server/headers). |
| `response.statusCode` | The HTTP status the response is sent with. |
| `response.body` | The answers so far, one key per route or middleware. Never change it by hand. |
| `response.hasErrors` | `true` once an error ended the request. |
| `response.fatalError` | The error that ended the request. |
| `shared` | Your own data, shared by every handler in the request. |
| `urlQuery` | The URL query string. |
| `batchId`, `batchRouteIds` | The batch id and the route ids it runs, on a [batch](/rpc/client/batch) request. |
| `maxBodySize` | The size limit this request was read against. |

::tip
Never keep the context in a module-level variable or a cache. It holds the whole request body, so that memory is never freed.
::

## Sharing Data Between Handlers

`ctx.shared` carries data from one handler to the next in the same request, and is never sent to the client. The `contextDataFactory` router option creates it for every request and types it in every handler. Without a factory it is an empty object typed `any`.

## Wire Format

The URL path is the route id: its keys joined by `/`, after the `basePath`. The body is a JSON object with one key per route or middleware id, each holding an array of params. The response body uses the same keys, each holding a return value.

<code-import path="packages/private-examples/src/router/call-context-wire-format.routes.ts" lang="ts" />

One request to `users.getUser` carries the params of `auth` too, and gets both answers back:

```http
POST /users/getUser
{"auth": ["my-token"], "users/getUser": [42]}

200 OK
{"auth": 3600, "users/getUser": {"id": 42, "name": "Leo"}}
```

A handler with no params or no return value has no key. Headers travel as HTTP headers, never in the body. Errors use their own keys, see [Error Response Format](/rpc/server/error-handling#error-response-format).

::tip
A body that is a plain JSON array holds the route's params only, like `[42]`. It suits a quick `curl` call when no middleware needs params.
::

## Serialization Steps

For each request, mion:

1. Parses the body as JSON, once.
2. For each handler in the [execution chain](/rpc/server/middleware#execution-chain), decodes its params (a Date from a string, a Map from an array), validates them, then runs the handler.
3. Encodes every return value and sends the response.

A failed step ends the request with an error. To pick how params and return values are encoded, see [Parser Strategies](/rpc/server/serialization#parser-strategies).

## Queries in the URL

The client sends a `query()` route as a GET when the URL fits in 4096 characters. The same JSON body goes base64url encoded in the `data` query value:

```http
GET /users/getUser?data=eyJ1c2Vycy9nZXRVc2VyIjpbNDJdfQ
```

The server reads `data` only when the request has no body. A value that is not base64url fails with `invalid-query-body`.

## Request Body Safety

The router checks every body before your handlers run:

- The body must be valid JSON holding an object or an array. Anything else fails with `parsing-json-request-error` or `invalid-request-body`.
- Each handler's value must be an array of params, or the request fails with `serialization-error`.
- A `__proto__` key in a record or index signature type is refused with `serialization-error`, so a request cannot change an object's prototype. `prototype` and `constructor` are ordinary keys.
