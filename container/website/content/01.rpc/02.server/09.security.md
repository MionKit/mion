mion treats every request as untrusted. The router checks the shape of what arrives before any handler runs, keeps internal error text off the wire, and puts a size limit on every platform. This page states that contract in plain words so you know what you get for free and what your app still has to do.

## What the Router Checks

Every request goes through the same steps, in this order, and each step refuses bad input with a typed error before the next one runs.

| Step | What is checked | Error type |
| --- | --- | --- |
| Batch id | On a batch request, the id names a batch the build compiled into the server. Checked before the body is read | `batch-unknown-id` (404) |
| Body size | The body (or the `?data=` query body) is not larger than the route's request limit | `request-payload-too-large` (413) |
| Body shape | Valid JSON that is an object or an array | `parsing-json-request-error`, `invalid-request-body` |
| Query body | A `?data=` value is real base64url | `invalid-query-body` |
| Route lookup | The path names a registered route. Names like `constructor` or `__proto__` are never routes | `route-not-found` (404) |
| Decoding | Each parameter is rebuilt only from the exact form the client encodes (a Date from a string, a bigint from a whole-number string) | `serialization-error` |
| Nesting | A parameter nested deeper than the validator can walk | `request-nesting-too-deep` |
| Validation | Each parameter matches its declared type, and with `strictTypes` carries no unknown property | `validation-error` |

Route ids, header names and body keys are looked up as own keys only, so a request naming `constructor` or `toString` is simply unknown. Keys named `__proto__`, `prototype` or `constructor` are refused everywhere a value is rebuilt from the wire.

::tip
A [batch](/rpc/client/batch) travels as its id alone. The routes it runs and the mappings between them never travel on the wire, so there is nothing for a caller to compose: the server refuses an unknown id before reading the body.
::

::note
Decoding runs before validation. That is why a decoder only converts values that already have the right wire shape, and leaves anything else for validation to refuse. The RunTypes guide explains the decoder contract in [Decoding Untrusted Input](/runtypes/guide/decoding-untrusted-input).
::

## Error Responses

An error response carries only public fields: the error type, the public message, optional error data, an optional id and the status code. The engine's own error text, the internal message and the stack never leave the server, they stay on the original error for your logs. Messages are fixed strings, so a malformed body cannot echo itself back into the response.

The `x-rpc-error` response header carries the type of the first error. Only a plain token reaches the header (letters, digits and `_ . : @ -`); any other type is reported as `unknown-error` on the header and stays intact in the body.

## Body Size Limits

Every route has its own request limit, and the router settles it once when the routes are registered. The number is picked in this order:

| Order | Where the limit comes from | When it applies |
| --- | --- | --- |
| 1 | `maxBodySize` on the route | You set it on the route options. Wins over everything mion controls |
| 2 | Derived from the types | Every parameter of the route (and of the middleFns in its chain) has a maximum |
| 3 | `maxBodySize` on the platform adapter | The types cannot say. 128 KB by default on every adapter |

A type has a maximum when every variable part of it is bounded: a string with `maxLength` or `length`, an array with `maxItems` or `length` (`List<T, Max>`), a Map or Set with `maxSize` (`SizedMap`, `SizedSet`), and numbers, booleans, enums, literals, dates, tuples, objects and unions of those. A plain `string`, `string[]`, `Map`, `Set`, record, `any` or `bigint` without bounds has none, and sends its route to the adapter's number. The derived number is the largest compact JSON a valid body can be, counted at the escaped worst case, times `maxBodySizeFactor` (a router option, 2 by default) so a client that pretty prints its JSON is never refused. Extra keys count against it whether or not `strictTypes` is on. There is no router-wide size: the only numbers are the route's own and the adapter's. The one global switch is on the build: `derivedPayloadLimits: false` in the `runTypes` block of the Vite plugin or `withMion` (or `jsonMaxBytes: false` in the tsconfig plugin entry) turns type-derived limits off, the compiler emits nothing for them, and every route takes its own option or the adapter's number.

The adapter reads the body against the resolved number, so a request is stopped as early as the platform allows, and the router checks it again before parsing, so it holds on every platform. Every adapter takes `maxBodySize` in its options; a route's own option may go above it. What mion cannot raise is the platform's own request ceiling, listed here so you know how far an option can go. A request past it never reaches mion: the platform answers 413 on its own.

| Platform | How the route limit is applied | Request ceiling |
| --- | --- | --- |
| Node | A `content-length` past the route limit is refused before a byte is read, and a body that grows past it is refused mid-stream | None |
| uWebSockets | The native read stops at the route limit | None |
| Bun | The body is read against the route limit as it arrives and a stream past it is cancelled mid-flight. Bun also has one server-wide read limit, which mion sets to the largest limit any route resolves to when the server starts | None (Bun's own default of 128 MB is replaced by that number) |
| Cloudflare Workers | The body is read against the route limit as it arrives and a stream past it is cancelled mid-flight | 100 MB on Free and Pro, 200 MB on Business, 500 MB on Enterprise (the zone plan, not the Workers plan) |
| Vercel | The body is read against the route limit as it arrives and a stream past it is cancelled mid-flight | 4.5 MB |
| AWS Lambda | The platform hands over the whole body, so the router checks the route limit before parsing | 6 MB on a synchronous invocation, 1 MB behind an Application Load Balancer or on an asynchronous one; a base64 encoded binary body leaves about 4.5 MB |
| Google Cloud Functions | The platform hands over the whole body, so the router checks the route limit before parsing | 10 MB (1st gen), 32 MB (2nd gen) |

The four hosted adapters export their ceiling as a constant and take it as the `maxBodySizeCap` option, so a bigger plan or a vendor change is written in by hand:

```ts
import {createCloudflareHandler} from '@mionjs/platform-cloudflare';

// a Business zone allows 200 MB
createCloudflareHandler({maxBodySizeCap: 200_000_000});
```

Nothing mion resolves passes that ceiling: a route option, a derived limit or a batch sum above it is brought down to it, so the metadata never promises a size the platform refuses.

The resolved number rides the route metadata as `maxBodySize`, so a client can see it. A batch request gets the sum of its routes' limits.

::tip
The metadata middleFn sits in every chain and takes a list of ids, so it declares a fixed contribution (4 KB) to every derived limit. A middleFn of your own whose params have no maximum sends every route it guards to the adapter's number; give it `maxBodySize` on its options to declare its own contribution instead.
::

::tip
A string body is measured in characters, which is never more than its byte length, so the byte-exact adapter check always fires first where there is one.
::

## Route Metadata Is Public

The client needs to know how to encode a call and decode its answer, so the metadata route describes every route and every middleFn that takes parameters, takes headers or returns data. A raw middleFn, and a middleFn with neither parameters nor return data, never touch the wire and are not described. It also lists the registered batch ids. This is not an access control: route types are the public API contract, the same way a REST API's schema is.

## What Stays Your Job

The router checks shape and size, not intent. These belong to your app, usually in a middleFn:

- **Authentication and authorization**: who may call what.
- **Rate limiting and request throttling**.
- **CORS** and any other browser policy header.
- **Business limits** on values that validate but are still too big for you (a list of a million ids, a string of a megabyte), through the format types or a check in the handler.

::note
RegExp values do not travel: a `RegExp` in a route parameter fails the build, so a client can never hand your handler a pattern to run.
::
