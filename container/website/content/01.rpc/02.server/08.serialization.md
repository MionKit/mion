## Two Directions, One Strategy Each

Every route has two wires. The params travel from the client to the server, and the return value travels back. Each direction picks its own strategy, and mion compiles for a route only the functions its strategies need.

| Strategy  | What rides the wire                                                                                                    | Mutates the value | Undeclared keys |
| --------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------- | --------------- |
| `mutate`  | JSON. The non JSON leaves (Date, BigInt, Map, Set) are rewritten in place, then the value is stringified. The fastest. | Yes               | Kept            |
| `clone`   | JSON. A fresh value is built from the declared shape, so your object is left untouched.                                | No                | Dropped         |
| `direct`  | JSON. A single pass writes the JSON string itself, with no clone.                                                      | No                | Dropped         |
| `compact` | JSON without key names: every object rides as a positional array, which is 40 to 60 percent smaller on real world data. | No                | Dropped         |
| `binary`  | Bytes, the most compact wire. The JSON pair stays compiled beside it, so a plain JSON request still decodes.          | No                | Dropped         |

Without any option a route keeps the wire mion always had: the client sends its params as a JSON string (`direct`) and the server prepares its return value in place (`mutate`) for the platform to stringify.

## How the Response Is Framed

The strategy of a return value also decides what the platform adapter receives for the response. With `mutate`, `clone` or `compact`, every member of the execution chain hands back a JSON ready value and the platform stringifies the whole body once. With `direct`, each member writes its own JSON string and the router joins them. With `binary` on the route, the whole body is written as bytes. The framing is worked out once per route when the routes are registered, from what every member of its chain compiled.

## Compact in Detail

The compact strategy drops the key names from every object, so a `{name, age}` value rides as `["Ada", 36]`. Scalars and arrays of scalars are unchanged. Three things follow from that:

- The wire is coupled to the type on both ends, the way the binary wire is: the client and the server must share the same types, which mion guarantees by shipping the compiled functions with the route metadata.
- An optional property that is absent rides as `null`, so a property typed `T | null` cannot tell an absent value from a `null` one; both decode to `undefined`.
- The JSON is no longer self describing, so it is not something to hand to a tool that expects keys, and there is no JSON Schema for it.

The first call of a compact route whose params carry objects fetches the route metadata before sending, so the params are encoded right from the first call. A call with only scalars still goes out at once.

## Why a Custom Binary Format?

You might wonder why mion uses its own binary protocol instead of established formats like Protocol Buffers, MessagePack, or CBOR. The answer lies in **full TypeScript support** and **flexibility**.

**Full TypeScript Feature Support**

Unlike Protocol Buffers which requires separate `.proto` schema files and has limited type support, mion's binary format is generated directly from your TypeScript types. This means it supports:

- **Union types**: `string | number | MyType`
- **Discriminated unions**: tagged unions with type discriminators
- **Intersection types**: `TypeA & TypeB`
- **Tuples**: `[string, number, boolean]`
- **Optional properties**: `{ name?: string }`
- **Rest parameters**: `(...args: string[]) => void`
- **Circular and recursive types**: types that reference themselves
- **Generics**: full generic type support
- **Enums**: both string and numeric enums
- **Maps and Sets**: native JavaScript collections
- **Classes**: with custom serialization and deserialization

**End-to-End Control**

Since mion controls both the client and server serialization, we can optimize the protocol for our specific use case:

- **No schema files**: types are the schema
- **Compiled at build time**: serializers are generated from the types, for maximum performance
- **Type-aware encoding**: the encoder knows the exact type, eliminating type markers where possible
- **Compact representation**: optional properties use bitmaps, known properties don't need names

::note
For a deep dive into how binary serialization works internally, see the [Binary Serialization Deep Dive](/rpc/articles/binary-serialization) article.
::

## Binary Serialization in Detail

For applications where data transfer efficiency is critical, binary serialization provides more compact data transfer compared to JSON.

::tip
Binary serialization is especially effective for transferring data structures that contain numeric data. Using the numeric type formats from `@mionjs/run-types/formats` (like `Int32`, `UInt8`, `Float`) allows the binary serializer to use optimized fixed-size encodings, significantly reducing payload sizes compared to JSON.
::

A middleware function that runs in the chain of a binary route rides the same bytes, so declare it with `serializer: 'binary'` too (or set `binary` as the router default). One that was compiled for JSON only is reported with a warning when the routes are registered, and its data is left out of the binary body.

##### Buffer Pooling

Binary responses are written into a size-classed buffer that is reused across requests instead of
allocated per response. Where a platform can hand the buffer back safely it is enabled by default:
**node** (released on the response's `finish`/`close`) and **bun** (Bun copies the bytes into the
`Response` synchronously). The other adapters allocate per response.

mion sizes that buffer from what each route recently wrote, and falls back to measuring the exact
byte count when a route's recent sizes are too volatile for the statistics to pick the right size
class. Nothing needs configuring for this, the defaults are what the benchmarks are tuned against.
