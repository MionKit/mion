## Encoder Strategies

Every route has two wires: the params (the client encodes, the server decodes) and the return value (the server encodes, the client decodes). The `encoder` option picks a strategy for each of them.

| Strategy  | What it does                                                                          | Mutates your objects | Unknown keys | Payload   |
| --------- | ------------------------------------------------------------------------------------- | -------------------- | ------------ | --------- |
| `clone`   | Builds a fresh JSON value from the type, then the platform stringifies it.            | No                   | Dropped      | Normal    |
| `mutate`  | Rewrites Dates, Maps and the like in place, then the platform stringifies the value.  | Yes                  | Kept         | Normal    |
| `direct`  | Writes the JSON string in one pass.                                                   | No                   | Dropped      | Normal    |
| `compact` | Drops the key names: an object becomes an array of its declared properties, in order. | No                   | Dropped      | Smallest  |

The default is `clone` on both directions, the safe pairing. It never touches the value it encodes, so a handler can return a cached row and a caller can pass an object it still uses, and it builds the payload from the declared type, so anything the type does not declare never reaches the wire.

The option is written once on the router and applies to every route, as a string for both directions or as an object naming each one.

## Sending Only What the Type Declares

The return type decides the payload, not the object the handler returns. A handler can read a wide row and return it as is: with `clone`, the properties the type does not name are never written.

::tip
`mutate` is the faster return encoder: it rewrites Dates and the like in place and allocates no copy. Two conditions make it safe. The handler must be done with the object it returns (it is modified, so never return a cached or shared one), and the object must already hold exactly what the type declares, because `mutate` sends every property it finds.
::

The build reads the `encoder` option to decide which functions each route compiles, so write it inline or as an `as const` preset, as above. An option built at run time (a function call, a variable typed `string`) is a build error and a lint error, and the router refuses to start when the value it reads differs from what was compiled.
::

## What Each Route Compiles

A route only compiles the functions its strategies need. With the default it ships a validator, an error reporter and one `clone` pair per direction. Choosing `compact` swaps in the positional pair instead.

The response framing follows from the strategies. A `direct` return is a string the router joins into the body, and every other strategy hands the platform a value to stringify. A middleware function returning data with `direct` makes the whole response a joined string.

## Compact in Practice

`compact` measures 40 to 60 percent fewer bytes than keyed JSON on real objects, because the property names never travel. Keep these in mind:

- The wire is coupled to the type: both ends must share the same type, which mion guarantees by shipping the compiled functions to the client.
- An optional property that is absent rides a `null` placeholder and comes back `undefined`, so a property typed `T | null | undefined` cannot tell a present `null` from an absent value.
- The payload is positional, so it is not a JSON document another service can read by key. Pick `clone` or `direct` for an endpoint other tools consume.
- Whichever form a caller sends, the decoder rebuilds your object from the properties the type declares, so a key you did not declare never reaches your handler. That is what lets a compact route skip the unknown-key check entirely.
- A union of objects has no single positional shape, so it keeps its key names inside a small wrapper. The savings on such a type come from everything around it. The decoder still rebuilds it from the declared properties, so a key you did not declare is dropped there too.
