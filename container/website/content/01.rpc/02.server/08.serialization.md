## Parser Strategies

Every route has two wires: the params (the client encodes, the server decodes) and the return value (the server encodes, the client decodes). The `parser` option picks a strategy for each one.

<code-import path="packages/examples/src/router/parser-strategies.ts" lang="ts" />

| Strategy | What it does | Mutates your objects | Undeclared params properties | Payload |
| --- | --- | --- | --- | --- |
| `clone` | Builds a fresh JSON value from the type, then the platform stringifies it. | No | Dropped | Normal |
| `mutate` | Rewrites Dates, Maps and the like in place, then the platform stringifies the value. | Yes | Kept | Normal |
| `mutateStrict` | Same as `mutate`, and rejects the request when a property is undeclared. | Yes | Rejected | Normal |
| `compact` | Drops the key names: an object becomes an array of its declared properties, in order. | No | Dropped | Smallest |

Undeclared properties matter most on params, because a caller that is not a mion client can send them. `mutateStrict` is params-only: a return value has no caller to reject.

::note
A dropped property is gone from the params, not set to `undefined`, so it cannot slip into a database insert. Every strategy also checks unions, where dropping is not enough: see [Undeclared Properties](/rpc/server/validation#undeclared-properties).
::

## Sending Only What the Type Declares

With `clone` and `compact`, the return type decides the payload, not the object the handler returns. Ten database columns come out, three go on the wire, and the password hash cannot leak by accident.

`mutate` is the faster return strategy: it rewrites Dates and the like in place and allocates no copy. It is safe when the handler is done with the object it returns, and the object holds exactly what the type declares.
::

::tip
Write the `parser` option inline or as an `as const` preset, because the build reads it. A value built at run time (a function call, a variable typed `string`) is a build error and a lint error, and the router refuses to start when the value it reads differs from what was compiled.
::

## What Each Route Compiles

A route only compiles the functions its strategies need: one validator and one error reporter per direction, plus one encode and decode pair. The default ships the `clone` pair, `compact` the positional one, and the params validator follows the strategy too. Every strategy hands the platform a value to stringify, so the response framing is the same whichever one you pick.

## Compact in Practice

`compact` sends fewer bytes than keyed JSON, because the property names never travel.

- Both ends must share the same type, which mion guarantees by sending the compiled functions to the client.
- An absent optional property travels as `null` and comes back `undefined`, so a property typed `T | null | undefined` cannot tell a present `null` from an absent value.
- The payload is positional, not a JSON document another service can read by key. Pick `clone` for an endpoint other tools consume.
