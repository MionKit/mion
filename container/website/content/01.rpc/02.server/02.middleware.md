Declare a middleware with `mion.middleware`, one of the helpers [the router](/rpc/server/routes#creating-the-router) returns. Middleware run before or after a route and chain together into the route's [Execution Chain](#execution-chain).

Use them for the extra work a route needs, like authorization, filters, body parsing or logging.

The first parameter is always the [Call Context](/rpc/server/routes#call-context). The other parameters come from the client, decoded and validated before the middleware runs.

## Always Run

A thrown error or a returned `FatalError` ends the request: the remaining middleware and the route do not run. A plain returned `RpcError` stops nothing, see [Error Handling](/rpc/server/error-handling).

A middleware with `alwaysRun: true`, like the logger above, runs anyway, on every request.

## Requests That Already Failed

Only the middleware that declare `alwaysRun` run for a request that failed before its route could run. None of these requests is parsed, and the two 404s never read the body.

<code-import path="packages/examples/src/router/middlewares-failed-requests.ts" lang="ts" />

| Request | Answer |
| --- | --- |
| A path that names no route | 404, `route-not-found` |
| A batch id the server does not know | 404, `batch-unknown-id` |
| A body the platform adapter refused | 413, `request-payload-too-large` |

::tip
On AWS Lambda and Google Cloud Functions the platform hands over the whole body, so the router refuses an oversized one. The middleware registered before that point still run.
::

## Headers Functions

Use `mion.headersFn` with a `HeadersSubset<T>` parameter to read request headers, and return a `HeadersSubset` from a `middleware` or `headersFn` to set response headers. These values travel as HTTP headers, not in the body like other params.

<code-import path="packages/examples/src/router/middlewares-header-definition.routes.ts" lang="ts" />

::note
Header names are **not case sensitive**: `Authorization` and `authorization` match the same header.
::

## Raw Middleware

Use `mion.rawMiddleware` to access the platform's native request and response. It receives the `CallContext`, the raw request, the raw response and the `RouterOptions`. It gets no remote parameters and returns no data: it can only change the context and return or throw errors.

<code-import path="packages/examples/src/router/middlewares-raw-definition.routes.ts" lang="ts" />

::tip
Raw middleware extend the router's core: the router itself uses them to serialize and deserialize.
::

## Execution Chain

The Execution Chain is the list of middleware and the route that run on a route call: the middleware before the route, the route, then the middleware after it. It is built when the router starts, so it is the same for every request.

Everything in it runs in order, with no paths or conditions, unless an error occurs.

### Execution Order

<code-import path="packages/examples/src/router/valid-definition-order.routes.ts" lang="ts" />

**Generated Execution Chain for: `pets.getPet`**

<mermaid>
graph LR
  A(authorizationMiddleware) --> B{{getPet}} --> E(errorHandlerMiddleware) --> C(loggingMiddleware)
  style B color:var(--site-accent)
</mermaid>

::note
Order matters: middleware and routes run in the order they are defined, top down.
::

### Middleware Scope

A middleware can run on a subset of routes only. The `userOnlyMiddleware` above runs only for the routes under `users`, not those under `pets`.

**Generated Execution Chain for: `users.getUser`**

<mermaid>
graph LR
  A(authorizationMiddleware) --> B(userOnlyMiddleware) --> C{{getUser}} --> E(errorHandlerMiddleware) --> D(loggingMiddleware)
  style B color:#f59e0b
  style C color:var(--site-accent)
</mermaid>
