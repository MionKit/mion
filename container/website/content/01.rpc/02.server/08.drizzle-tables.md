Routes take and return the models of your Drizzle ORM tables like any other type. The [RunTypes Drizzle ORM section](/runtypes/drizzle-orm/drizzle-overview) covers declaring tables, column formats, views and migrations.

## Using Models in Routes

A route typed with your table models is validated before the handler runs, refined bounds included. Dates stay Dates on server and client, the client gets full types, and you register nothing per route. Both table forms give the same models, so only the import differs.

## Keeping Drizzle Types Out of Routes

Route parameters and return types use slim models, never Drizzle types, so the client never type-checks or bundles your database code. The [linter](/rpc/devtools/linter#public-drizzle-types) warns when a route uses a Drizzle type.
