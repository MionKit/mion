Routes take and return the models of your Drizzle ORM tables like any other type. Declaring tables, column formats, views and migrations are covered in the [RunTypes Drizzle ORM section](/runtypes/drizzle-orm/drizzle-overview).

## Using Models in Routes

Routes typed with the derived models are validated before the handler runs (refined bounds included), revive Dates on both ends of the wire, and give the client full types, with nothing to register per route. Both table forms infer the same models, so the routes differ only in their import.

## Keeping Drizzle Types Out of Routes

Route parameters and return types use slim models, never Drizzle types, so the client never type-checks or bundles your database code. The [linter](/rpc/devtools/linter#public-drizzle-types) warns when a route uses a Drizzle type.
