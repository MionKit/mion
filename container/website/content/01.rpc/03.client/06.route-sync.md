---
title: Keeping Client and Server in Sync
description: Stop a call before it runs when its route types changed on the server.
---

With `syncRoutes` on, every call proves your app was built against the server's route types. A call
built against other types stops before any of your code runs on the server.

## Turning On Route Sync

Set `syncRoutes: true` in `createMionRouter`, and type the client with what `initRoutes` returns.

## What Stops a Call

Each call sends one short id per route.

| What changed on the server | The call |
| --- | --- |
| The params or return type of the route | Stopped, nothing runs |
| The types of a middleware in front of the route, or which middlewares run | Stopped, nothing runs |
| The mion version | Stopped: another version can compile different functions |
| A route was added | Runs |
| Only route options (GET or POST, parser, validation) | Runs |

## Handling a Stopped Call

The call returns a `route-types-mismatch` error in the third slot and is not sent again. Your code
expects the old types, so reload the app or ship a new build.

## The First Call to a Route

A client with no metadata for a route yet sends no id. The server stops the call and returns the route's
metadata, then the client sends it again with the id. This happens once per route, and a
returning visitor skips it, see [What the Client Remembers](/rpc/client/metadata-cache).

::tip
A non-mion client (curl, another language) sends no ids, so the server stops all its
calls while `syncRoutes` is on.
::
