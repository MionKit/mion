---
title: Keeping Client and Server in Sync
description: Stop a call before it runs when its route types changed on the server.
---

With `syncRoutes` on, every call proves that your app was built against the server's route types. A call
built against other types is stopped before any of your code runs on the server.

## Turning On Route Sync

Set `syncRoutes: true` in `createMionRouter`, and type the client with what `initRoutes` returns.

::note
The client has no option for it: its build reads `syncRoutes` from the API type.
::

## What Stops a Call

Each call sends one short id per route. The id covers the params and return types of the route and of
every middleware in front of it.

| What changed on the server | The call |
| --- | --- |
| The params or return type of the route | Stopped, nothing runs |
| The types of a middleware in front of the route, or which middlewares run | Stopped, nothing runs |
| The mion version | Stopped: another version can compile different functions |
| A route was added | Runs |
| Only route options (GET or POST, parser, validation) | Runs |

## Handling a Stopped Call

The client puts a `route-types-mismatch` error in the third slot and does not send the call again. Your

## The First Call to a Route

A client that has no metadata for a route yet sends no id. The server stops that call and answers with the
route's metadata, and the client sends the call again with the id. This happens once per route, and a
returning visitor skips it, see [What the Client Remembers](/rpc/client/metadata-cache).

::tip
A client that is not a mion client (curl, another language) sends no ids, so the server stops all its
calls while `syncRoutes` is on.
::
