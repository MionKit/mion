With route sync on, every call proves your app was built against the server's route types. A call
built against other types stops before any of your code runs on the server.

## What Stops a Call

Each call sends one short id per route, built from its params and return types, and the wire format of each.

| What changed on the server | The call |
| --- | --- |
| The params or return type of the route | Stopped, nothing runs |
| The route's parser, to or from `compact` | Stopped: the data is written differently |
| The mion version | Stopped: another version can compile different functions |
| A middleware's types | Runs: the middleware checks its own params |
| A route was added | Runs |
| Other route options (GET or POST, validation, a parser other than `compact`) | Runs |

## Handling a Stopped Call

A route from your [bundled API](/rpc/client/bundled-api) returns a `route-types-mismatch` error in the third
slot and is not sent again: reload the app or ship a new build. A route whose metadata came from the server is
fetched again, saved, and sent once more.

## The First Call to a Route

A client with no metadata for a route yet sends no id. The server stops the call and returns the route's
metadata, then the client sends it again with the id. This happens once per route, and a
returning visitor skips it, see [What the Client Remembers](/rpc/client/metadata-cache).

::tip
A non-mion client (curl, another language) sends no ids, so the server stops all its
calls while `mionSyncRoutes` is in your routes.
::
