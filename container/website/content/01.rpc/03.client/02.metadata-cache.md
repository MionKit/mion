By default the build ships every route your client calls, so the client never asks the server about
it. See [Bundling the API Into the Client](/rpc/client/bundled-api).

With `bundleApi: false` or `'mixed'`, the client asks the server how a route works the first time you
call it. It saves the answer, so the next visit does not ask again.

## The First Call to a Route

A route's first call goes out before its metadata is known. Params go in forms every server reads (a date
as text, a map or set as an array), and the metadata comes back in the same answer. If the body cannot be
written that way, the client asks for the metadata first, then sends the call.

## When a Call Is Sent Again

A call is sent again at most once, and only when that cannot run a route twice.

| The answer | Sent again |
| --- | --- |
| The route succeeded | Never. Its metadata is saved |
| The server could not read the params of a first call | Once, in the route's own format |
| Saved metadata no longer matches the server | Once, after dropping the saved copy |
| The server runs another build of the API | Once, after checking the route |
| A mutation in the same batch succeeded | Never |
| The route returned one of its own errors | Never |
| A network error, a timeout or an abort | Never |

## Where the Cache Is Kept

In the browser's database (IndexedDB), one entry per server, under your site's own storage. Nothing is
shared with another site, and nothing is sent anywhere.

On a server (during server side rendering), or in a browser where storage is turned off,
the client keeps the same data in memory instead. Everything works the same, it just starts fresh each
time.

## Choosing the Storage

The `storageEngine` option picks the browser's database or memory.

```ts
import {initClient} from '@mionjs/client';

const client = initClient<MyApi>({baseURL, storageEngine: 'memory'});
```

## Using Your Own Store

Pass a function that returns your store. The client opens it once and reuses it, and falls back to memory
if it returns nothing or fails to open.

```ts
import type {MetadataStore} from '@mionjs/client';

const myStore: MetadataStore = {
  kind: 'my-store',
  readAll: (baseURL) => ..., // every record saved for that server
  write: (records) => ..., // all of them, or reject so the client can make room and retry
  remove: (baseURL, keys) => ..., // just the ones named
  clear: (baseURL) => ..., // that server, or everything when no server is given
};

const client = initClient<MyApi>({baseURL, storageEngine: () => myStore});
```

## What the Cache Holds

Only the shape of your API, nothing about your users and nothing you passed to a route.

| Kept | Why |
| --- | --- |
| Each route's description | Its params, its result, and how both travel |
| The compiled check and convert functions | So params are checked in the browser before anything is sent |

## Why the Cache Is Faster

Without it, the first call of every page costs an extra trip to the server to learn how the route works.
With it, a returning visitor's first call goes out already knowing.

## What a Browser May Clear

A browser can drop this cache at any time, for example:

- **Running low on space.** The browser clears site storage to make room.
- **Safari, after seven days.** Safari clears everything your site stored once someone has used the
  browser for seven days without visiting your site. No choice of store avoids it. Visiting the site
  resets the clock, and a site added to the home screen counts separately.

Nothing breaks: the client asks the server again for what is missing.

## Asking the Browser to Keep the Cache

A browser can mark your site's storage as worth keeping, so a clean up does not drop it. mion never shows
a permission popup on its own: it marks the storage only when the browser already allows it. To ask
yourself, call `requestPersistentStorage()`, ideally right after a sign in or another user action.

```ts
import {requestPersistentStorage} from '@mionjs/client';

const kept = await requestPersistentStorage();
```

## When Something Cannot Be Stored

If the browser refuses to store the cache and no room can be freed, your call still works. The error comes
back on your next call, in the third slot of the result.

```ts
const [result, error, undeclared] = await routes.sayHello(user).call();

if (undeclared?.type === 'metadata-cache-error') {
  console.warn('running without the local cache');
}
```

## When the Metadata Code Cannot Load

The code that asks the server loads as its own file the first time a call needs it. If that file cannot be
loaded, the call comes back with `metadata-load-error` in the third slot, and the next call tries again.
