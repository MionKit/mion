## Aborting Mutations

`client.abort()`, a `signal` and a `timeout` only end the wait on the **client**. The server sees a dropped connection, and nothing is undone. By then the server may not have received the request, may be halfway through it, or may already have committed it.

::warning
Treat an aborted mutation as **unknown**, not as **failed**. There is no client-side way to tell the difference.
::

::tip
Send an idempotency key with each logical action, so the server can return the stored result when you retry. After an abort, refetch the affected resource and show "syncing" rather than "failed".
::

Cancelling a `query()` is always safe, the worst case is wasted work on the server. See [Queries and Mutations](/rpc/client/client-overview#queries-and-mutations).
