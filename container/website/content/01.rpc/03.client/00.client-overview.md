## Features

| Feature | What you get |
| --- | --- |
| Typed remote methods | Every route and middleware shows up with its params and return type, with autocompletion and static type checking. |
| Never throws | The result and the error come back together, so there is nothing to wrap in try/catch. |
| Validation and serialization | Params and results are validated and serialized out of the box, including types like Date, Map and Set. |
| Local validation | Wrong params are caught in the browser, with no request to the server. |
| Local sanitizing | The same transforms the route declares (trim, lowercase, strip separators) run before validation and before sending. |
| Middleware hooks | A middleware gets its data, like an auth token, from a hook that runs before every request. |
| Route sync | A call built against outdated route types is stopped before it runs, see [Keeping Client and Server in Sync](/rpc/client/route-sync). |

::note
The client fetches route and middleware metadata from the server for local validation and serialization. A route's first call can start before it loads: params go in forms every server reads (a date as text, a map or set as an array), so most first calls get an answer straight away. If a route expects another format, the server answers with an error and the client sends the call again in that format. The client keeps what it learns, so a returning visitor skips this step, see [What the Client Remembers](/rpc/client/metadata-cache).
::

## Sending Middleware Data

A middleware gets its data, like an auth token, from its `onRequest` hook. Call the function the hook receives with the middleware params, or skip the call to send nothing.

::code-split
<code-import path="packages/private-examples/src/client/client-middleware-hooks.ts" lang="ts [client.ts]" />
<code-import path="packages/private-examples/src/client/middleware-hooks.routes.ts" lang="ts [server.routes.ts]" />
::

| Hook | Runs | Removed with |
| --- | --- | --- |
| `onRequest` | Before each request that runs the middleware, a route's first call included. It can be async. Its second argument is the request, to pick data per route. | `offRequest()` |
| `onResponse` | After each successful middleware result, strongly typed. | `offResponse()` |
| `onError` | After each declared error of the given `type`, strongly typed. | `offError(type)` |

::tip
If `onRequest` throws or rejects, the request is not sent and `undeclared` holds the error. Undeclared errors (transport, platform, framework) never reach `onError`.
::

## Queries and Mutations

A `query()` is read only, so small payloads travel in the url as a GET. A `mutation()` changes data, so it always travels in the body as a POST. A plain `route()` also travels in the body.

::tip
Cancelling a query is always safe, the worst case is wasted work on the server. A cancelled mutation may already have changed data. See [Cancellation and Timeouts](/rpc/client/cancellation-timeouts).
