## Features

| Feature | What you get |
| --- | --- |
| Typed remote methods | Every route and middleware function shows up with its params and return type, with autocompletion and static type checking. |
| Never throws | The result and the error come back together, so there is nothing to wrap in try/catch. |
| Validation and serialization | Params and results are validated and serialized out of the box, including types like Date, Map and Set. |
| Local validation | Wrong params are caught in the browser, with no request to the server. |
| Local sanitizing | The same transforms the route declares (trim, lowercase, strip separators) run before validation and before sending. |
| Prefilled data | Values like an auth token are stored once and sent with every later call. |

## Prefilling Middleware Function Data

When a middleware function is required by every request, like authorization, use `prefill()` on the `MiddleFnSubRequest`. Every later route call that needs it is filled in automatically.

Results and errors of a prefilled middleware function reach you in two ways:

| Channel | What it carries |
| --- | --- |
| Event handlers | Registered with `.prefill()` or with `.onError()` on the middleware function, strongly typed by the error `type` string. |
| The result tuple | Results by name in `middleFnResults`, declared errors by name in `middleFnErrors`. |

Undeclared errors (transport, platform, framework) never reach the handlers, they only reach `fatal`.

Use the handlers for global error handling with prefilled middleware functions. They give you strongly typed errors based on the error `type` string.

## Queries and Mutations

A route says what it is for, and the client sends it accordingly. A `query()` is read only, so small payloads travel in the url as a GET. A `mutation()` changes data, so it always travels in the body as a POST. A plain `route()` also travels in the body.

::tip
The difference matters when you cancel a request. Cancelling a query is always safe, the worst case is wasted work on the server. A cancelled mutation may already have changed data. See [Cancellation and Timeouts](/rpc/client/cancellation-timeouts).
::

## Sanitizing Params

For every route the server registered with `sanitizeParams`, the client applies the transforms the params types declare (trim, lowercase, strip separators) locally, before local validation and before sending, so both ends see the same value. This is on by default. Set the client option `sanitizeParams` to false to validate and send the value exactly as typed. The server still sanitizes those routes.
