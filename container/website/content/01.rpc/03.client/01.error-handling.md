## The Result Pattern

`call()` returns a tuple with 5 slots. You usually read only the first two: what the route returned and the error it declared.

::code-split
<code-import path="packages/private-examples/src/client/result-short.ts" lang="ts [the two slots you need]" />
<code-import path="packages/private-examples/src/client/result-full.ts" lang="ts [all five slots]" />
::

Every error lands in exactly one slot:

| Slot | Name | What it holds |
| --- | --- | --- |
| 0 | result | What the route returned, if it ran and succeeded. |
| 1 | error | The route's declared errors plus `ValidationError`. A closed, strongly typed union. |
| 2 | undeclared | Anything nobody declared: a transport failure (timeout, abort, network), a platform error, a framework error, or an undeclared throw. An open `RpcError<string>`. |
| 3 | middlewareResults | Middleware results, by middleware id. |
| 4 | middlewareErrors | Each middleware's declared errors plus `ValidationError`, by middleware id, so nothing is lost when several fail. |

::note
The client builds this tuple, the server never sees it. Your handlers just return a value or an `RpcError`.
::

## Middleware Errors

A middleware's declared errors reach its `onError` hook, strongly typed, and `middlewareErrors`, typed only as `RpcError`. Use the hook for app-wide handling, like a logout on `not-authorized`. To send a middleware its data, see [Sending Middleware Data](/rpc/client/client-overview#sending-middleware-data).

::warning
Hooks run on every request that includes the middleware, whether or not you also read the result tuple.
::
