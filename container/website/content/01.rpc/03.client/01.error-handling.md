## The Result Pattern

`call()` returns a tuple with 5 slots. You usually read only the first two: what the route returned and the error it declared.

::code-split
<code-import path="packages/examples/src/client/result-short.ts" lang="ts [the two slots you need]" />
<code-import path="packages/examples/src/client/result-full.ts" lang="ts [all five slots]" />
::

Every error lands in exactly one slot:

| Slot | Name | What it holds |
| --- | --- | --- |
| 0 | result | What the route returned, if it ran and succeeded. |
| 1 | error | The route's declared errors plus `ValidationError`. A closed, strongly typed union. |
| 2 | undeclared | Anything nobody declared: a transport failure (timeout, abort, network), a platform error, a framework error, or an undeclared throw. An open `RpcError<string>`. |
| 3 | middlewareResults | Middleware results, by name. |
| 4 | middlewareErrors | Each middleware's declared errors plus `ValidationError`, by name, one slot per middleware so nothing is lost when several fail. |

::note
The client builds this tuple, the server never sees it. Your handlers just return a value or an `RpcError`.
::

## Middleware Errors

A middleware's declared errors arrive by name in `middlewareErrors`, and in its `.onError()` handlers. To send its data, see [Passing Data to Middleware](/rpc/client/client-overview#passing-data-to-middleware) and [Prefilling Middleware Data](/rpc/client/client-overview#prefilling-middleware-data).

::warning
`prefill().onError().onSuccess()` handlers run on every request, whether or not you also read the outcome from the result tuple.
::

## Prefill vs Call with Middleware

| Aspect | `.prefill()` | `.call({middlewares: ...})` |
|--------|--------------|-------------------|
| **Persistence** | Data stored for ALL future requests | Data sent with this request only |
| **Error handlers** | Persistent via `.prefill().onError()` | Same `.onError()` API, registered directly on the middleware (no prefill needed) |
| **Use case** | Auth tokens, session data | Metadata related to the request |
