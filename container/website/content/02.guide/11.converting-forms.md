## One shape, any notation

RunTypes accepts three ways to write a shape: a plain TypeScript type, the value-first type builders, and a JSON Schema. They are interchangeable, so a codebase can also switch between them. The convert command rewrites your files from one form to another, in place.

```bash
# one file, or several
npx ts-runtypes convert --to builders src/models.ts src/api.ts

# or a whole folder (every .ts and .tsx inside it)
npx ts-runtypes convert --to json-schema src/models/
```

The targets are `type`, `builders` and `json-schema`. Declarations already written in the target form are left byte-for-byte unchanged, so running the command twice is safe.

## Identity never moves

Conversion changes the spelling, never the shape. Every converted declaration resolves to the same identity as before, which means the same generated validator, the same codecs, the same mock data. This is enforced, not aspirational: the converter's test suite converts randomly generated files through the full chain (type to builders to JSON Schema and back) and checks the identity of every declaration on every step.

## What converts

Everything the engine reflects: primitives and literals, string and number formats, arrays, tuples (labeled ones included, using RT.slot in builder form and the jsLabels keyword in schema form), objects (optional, readonly and quoted keys included), records (including an index signature beside named properties, which becomes an intersection in builder form and properties beside additionalProperties in schema form), unions, enums, classes, Date, Map, Set, Promise, RegExp, Temporal types, functions (named parameters use RT.slot too), template literals, branded types, and recursive types. Recursive shapes come out as `RT.circular` with `RT.self()` in builder form and as a `$ref: '#'` reference in schema form.

Declarations that reference each other stay references. A type that names another converted type keeps the name in every form, across files too: convert the files together and the imports are updated for you.

```bash
npx ts-runtypes convert --to builders src/user.ts src/order.ts
```

## What does not convert

Most shapes that the target form has no word for still convert: they ride an escape that carries the type itself, `getRunType<T>()` in builder form and `embedType<T>()` in schema form. That covers functions, template literals, bigint literals and more.

What is left is the short list below, where even the escape cannot help because the type cannot be written down inside it. The converter never guesses: it reports the shape, leaves that declaration exactly as you wrote it, converts the rest of the file, and exits with a non-zero code so CI notices.

| Shape | Why |
| ----- | --- |
| A generic type (`type Box<T> = ...`) | A type parameter has no single runtime shape until it is filled in. |
| A cycle that never passes through a named type | The self reference has nothing to point at. Give the inner type a name and it converts. |
| A symbol-keyed property | The property name is a symbol, and an escape can only carry a type it can write down. |
| A recursive type reached only inside an embedded type expression | Embedded types are quoted TypeScript, and quoted text cannot point back at the declaration being defined. |
| An exclusive union with a plain value branch, inside a recursive type | Only when converting to builder form. The plain type and JSON Schema forms carry it. |
| A reference to a type whose file is not in the same run | Add that file to the same command. |
| A Temporal type that resolves to `any` | The Temporal declarations are missing from your project. Add the `ESNext.Temporal` lib or a polyfill's types. Converting would bake the `any` in permanently. |
| Anything needing the RunTypes dialect, under `--portable` | Only with that flag, and deliberately: see below. |

That list is kept honest by a test. Every row is a real declaration handed to the real command, asserting the exact message you would see and that your file came back untouched: [unsupported-conversion.test.ts](https://github.com/MionKit/ts-run-types/blob/main/packages/ts-runtypes/test/features/unsupported-conversion.test.ts). When one of these starts converting, that test fails and the row goes away, so the list can never quietly drift from the tool.

One more case is not a refusal but worth knowing: converting to plain types leaves a builder const alone if your code still uses it elsewhere, since removing it would break those call sites.

## When JSON runs out of words

Some TypeScript types have no JSON spelling: a bigint literal, a function signature, a branded string. On the schema target these ride the embedType escape, which places a real TypeScript type inside a schema without losing anything.

If you need schemas that any JSON Schema tool can read, pass `--portable`. It forbids the RunTypes extensions (embedType and the jsType and jsFormat keywords), and any declaration that cannot be expressed without them becomes an error instead.

## Checking without writing

`--check` reports what would change and exits with code 1 while anything is pending, so it slots into CI. `--out-dir` writes the converted files into a copy of the folder and leaves your sources untouched.

```bash
npx ts-runtypes convert --to type --check src/models/
npx ts-runtypes convert --to builders src/models/ --out-dir converted/
```

Anything the converter cannot express is reported with a clear message and left exactly as it was, and the exit code tells you something needs attention. The shapes that can happen to are listed above.
