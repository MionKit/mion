## One shape, any notation

RunTypes accepts three ways to write a shape: a plain TypeScript type, the value-first type builders, and a JSON Schema. They are interchangeable, so a codebase can also switch between them. The convert command rewrites your files from one form to another, in place.

```bash
# one file, or several
npx ts-runtypes convert --to builders src/models.ts src/api.ts

# or a whole folder (every .ts and .tsx inside it)
npx ts-runtypes convert --to json-schema src/models/
```

The targets are `type`, `builders` and `json-schema`. Declarations already written in the target form are left byte-for-byte unchanged, so running the command twice is safe.

## Identity never moves

Conversion changes the spelling, never the shape. Every converted declaration resolves to the same identity as before, which means the same generated validator, the same codecs, the same mock data. This is enforced, not aspirational: the converter's test suite converts randomly generated files through the full chain (type to builders to JSON Schema and back) and checks the identity of every declaration on every step.

## What converts

Everything the engine reflects: primitives and literals, string and number formats, arrays, tuples, objects (optional, readonly and quoted keys included), records, unions, enums, classes, Date, Map, Set, Promise, RegExp, functions, template literals, branded types, and recursive types. Recursive shapes come out as `RT.circular` with `RT.self()` in builder form and as a `$ref: '#'` reference in schema form.

Declarations that reference each other stay references. A type that names another converted type keeps the name in every form, across files too: convert the files together and the imports are updated for you.

```bash
npx ts-runtypes convert --to builders src/user.ts src/order.ts
```

If a declaration references a type whose file is not part of the run, the command stops with an error instead of quietly inlining a copy. Add the file to the same invocation.

## When JSON runs out of words

Some TypeScript types have no JSON spelling: a bigint literal, a function signature, a branded string. On the schema target these ride the embedType escape, which places a real TypeScript type inside a schema without losing anything.

<code-import path="packages/examples/src/guide/convert-forms.ts" lang="ts" commentStart="// start-embed" commentEnd="// end-embed" />

If you need schemas that any JSON Schema tool can read, pass `--portable`. It forbids the RunTypes extensions (embedType and the jsType and jsFormat keywords), and any declaration that cannot be expressed without them becomes an error instead.

## Checking without writing

`--check` reports what would change and exits with code 1 while anything is pending, so it slots into CI. `--out-dir` writes the converted files into a copy of the folder and leaves your sources untouched.

```bash
npx ts-runtypes convert --to type --check src/models/
npx ts-runtypes convert --to builders src/models/ --out-dir converted/
```

A declaration the converter cannot express yet (a generic type, a labeled tuple, a cycle through an unnamed type) is reported with a clear message and left exactly as it was; the exit code tells you something needs attention. A builder const that is still used elsewhere in your code is also left alone when converting to plain types, since removing it would break those call sites.
