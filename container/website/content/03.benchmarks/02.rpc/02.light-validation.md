## Benchmark Code

Each request is an `updateSimpleUser` call with a **simple User model (~100 bytes payload)**.

```ts
interface SimpleUser {
  id: number;
  name: string;
  surname: string;
  lastUpdate: Date;
}

// ### mion ###
// the received user by the route is already validated and deserialized
// all Date fields are already JS Date objects (not strings from JSON.parse)
export const routes: Routes = {
  updateUser: (ctx, user: SimpleUser): SimpleUser => {
    user.lastUpdate = new Date();
    return user;
  },
};

// ### Other frameworks (Express, Fastify, Hono, etc.) ###
// Use Zod schemas for validation and date coercion
const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  surname: z.string(),
  lastUpdate: z.coerce.date(),
});

app.post("/updateUser", function (req, res) {
  const user = UserSchema.parse(req.body); // Validates + deserializes dates
  user.lastUpdate = new Date();
  res.json(user);
});
```

## Reading the Results

Requests take longer than in the ['hello world'](/benchmarks/rpc/hello-world) benchmark, mostly because of validation and the JSON round trip.

**Here, the validation and JSON round trip libraries can matter as much as the routing and framework.**

::note{icon="i-heroicons-light-bulb"}
**Why can http-node top this benchmark?** The SimpleUser schema has only 4 fields, so Zod validation is quick and this benchmark mostly measures HTTP handling, not validation and the JSON round trip. `http-node` is a bare `http.createServer` with zero framework overhead, and its fully synchronous handler avoids the microtask scheduling cost that `async/await` adds to frameworks like Hono bun. Bun servers only reach ~92-98% CPU utilization versus ~100-109% for http-node, suggesting an I/O or scheduling bottleneck rather than a raw speed advantage.
::
