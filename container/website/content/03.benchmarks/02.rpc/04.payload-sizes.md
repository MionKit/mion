The heavy validation route on every server, at four payload sizes from about 1 KB to 4 MB. It shows what happens when a request no longer fits in one network read.

Under each size, the same mion server also runs with [compact JSON](/rpc/server/json-round-trip#compact-payloads), which sends objects without their key names. The percentage is measured against plain JSON.

## Test Setup

Each request is the `updateUser` call from [heavy validation](/benchmarks/rpc/heavy-validation), padded to the target size by repeating its payment methods. Each one is a member of a discriminated union in the model, so every server validates the whole body at every size. All the [hello world](/benchmarks/rpc/hello-world) servers run here, so the sizes compare frameworks, not just mion's own adapters.

`mion.compact` is the `mion` server with `parser: 'compact'` on the router. Bytes count the request and response bodies of one call, headers left out.

::note{icon="i-heroicons-light-bulb"}
**Why these sizes?** A body over 512 KB cannot arrive in one socket read, and the
uWebSockets adapter takes a different, copy-free path for it. The 500 KB case is the
last one that fits in a single read, the 4 MB case does not.
::

::note{icon="i-heroicons-light-bulb"}
**Fewer connections on the largest payload.** Every size has the same cap on request-body
bytes in flight, so bigger payloads mean fewer requests at once. Without it, 4 MB bodies
would mostly wait in a queue, and the run would measure the queue instead of the server.
::
