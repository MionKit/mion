## Atomic and Collection Type Formats

A type format adds a rule to a type. An **atomic** format checks one value and replaces its type: `TF.Email` instead of `string`. A **collection** format wraps an array, object, Set or Map you already wrote and checks the whole, like its size or repeated entries.

| Family | Kind | Examples |
| --- | --- | --- |
| [String](/runtypes/type-formats/string) | atomic | `TF.Email`, `TF.UUIDv4`, `TF.Url`, `TF.CreditCard` |
| [Number](/runtypes/type-formats/number) | atomic | `TF.Int32`, `TF.Positive`, `TF.Currency` |
| [BigInt](/runtypes/type-formats/bigint) | atomic | `TF.BigInt64`, `TF.BigPositive` |
| [Date and time](/runtypes/type-formats/date-time) | atomic | `TF.StringDate`, `TF.Date`, `TFT.PlainDate` |
| [Collections](/runtypes/type-formats/collections) | collection | `TF.FormattedArray<string[], {maxItems: 5}>`, `TF.FormattedMap` |

::tip
An atomic format type is capitalized (`TF.Email`), and its builder is a call (`TF.email()`). A collection format has no named presets: its rules are options on the collection.
::

## Custom Type Formats

`TF.String`, `TF.Number` and `TF.BigInt` take your own params when no named format fits. `multipleOfTolerance` widens the rounding a decimal `multipleOf` allows. With `integer: true`, `multipleOf` must be a whole number.

<code-import path="packages/examples/src/guide/type-formats-custom.ts" lang="ts" />

| Format | Common params |
| --- | --- |
| `TF.String` | `minLength`, `maxLength`, `length`, `pattern`, `allowedChars`, `allowedValues`, … |
| `TF.Number` | `min`, `max`, `gt`, `lt`, `integer`, `float`, `multipleOf`, `multipleOfTolerance`, `isCurrency` |
| `TF.BigInt` | `min`, `max`, `gt`, `lt`, `multipleOf` (all `bigint` literals, e.g. `0n`) |

::tip
`min` / `max` are inclusive, `gt` / `lt` exclusive. Use one or the other per edge: the build rejects a type with both, such as `{min: 0, gt: 0}`. Date formats take the same four bounds.
::

## Branded Types

By default an atomic format is still structurally a `string` or `number`, so a raw string fits where a `UserId` belongs. Add a **brand name** as the second type argument and nothing else fits without an `as` cast. With builders, use the `brand()` tag: `TF.string({minLength: 1}, TF.brand('UserId'))`.
