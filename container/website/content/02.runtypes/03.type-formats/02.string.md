## Named String Formats

Each format also has a builder, named in lowercase (`TF.email()`, `TF.uuidv4()`). Date strings are on the [Date and Time Formats](/runtypes/type-formats/date-time) page.

| Group | Formats |
| --- | --- |
| Text | `TF.Alpha`, `TF.AlphaNumeric`, `TF.Numeric`, `TF.Lowercase`, `TF.Uppercase`, `TF.Capitalize` |
| Encodings | `TF.Base64`, `TF.Base32`, `TF.Base16`, `TF.JsonContent`, `TF.JsonContentBase64` |
| Ids | `TF.UUID`, `TF.UUIDv4`, `TF.UUIDv7` |
| Email | `TF.Email`, `TF.EmailAddress`, `TF.IdnEmail`, `TF.EmailPunycode`, `TF.EmailStrict` |
| Domains and hosts | `TF.Domain`, `TF.DomainUnicode`, `TF.DomainPunycode`, `TF.DomainStrict`, `TF.Hostname`, `TF.IdnHostname` |
| IP addresses | `TF.IP`, `TF.IPv4`, `TF.IPv6`, `TF.IPWithPort`, `TF.IPv4WithPort`, `TF.IPv6WithPort` |
| URLs | `TF.Url`, `TF.UrlHttp`, `TF.UrlFile`, `TF.Uri`, `TF.UriReference`, `TF.UriTemplate`, `TF.Iri`, `TF.IriReference` |
| JSON Schema keywords | `TF.StringDuration` (`P4DT12H30M5S`), `TF.JsonPointer`, `TF.RelativeJsonPointer`, `TF.RegexString` |
| Payment | `TF.CreditCard` |

## Email Formats

Pick the email format by how much of the address grammar you want to accept.

<code-import path="packages/private-examples/src/guide/type-formats-string.ts" lang="ts" commentStart="// start-email" commentEnd="// end-email" />

| Format | Use it for |
| --- | --- |
| `TF.Email` | Form fields: the everyday `name@example.com` shape |
| `TF.EmailAddress` | Any valid address, quoted local parts and `[ip]` domains included |
| `TF.IdnEmail` | The same as `TF.EmailAddress`, in any script |

::tip
All of them need a dotted domain. `TF.EmailStrict` also limits each half of the address with `localPart` and `domain` options, and `TF.EmailPunycode` takes a domain in its `xn--` form.
::

## String Transformations

A transformation rewrites a string, such as trimming spaces or lowercasing an email. You typically use it to sanitize user input before you store it.

<code-import path="packages/private-examples/src/guide/type-formats-transforms.ts" lang="ts" commentStart="// start-sanitize" commentEnd="// end-sanitize" />

| Transformation | Does |
| --- | --- |
| `trim` | Removes spaces at both ends |
| `lowercase`, `uppercase`, `capitalize` | Changes the case |
| `replace`, `replaceAll` | Replaces the first match, or every match |
| `stripSeparators` | Removes spaces and dashes (`TF.CreditCard` only) |

::tip
Validation never transforms a value. Only `createFormatTransformFn` does, and a mion route with [sanitizeParams](/rpc/server/validation#sanitizing-params) runs it on the params before validation.
::

## Transformation Rules

- They run in a fixed order: replacements and the separator strip first, then trim, then the case change.
- `TF.Email`, `TF.Domain`, `TF.IP` and `TF.Url` never change case unless you ask, because parts of them are case-sensitive.
- A mion route sanitizes on both ends, so applying a transformation twice must give the same result. Prefer `replaceAll` over `replace`, and use one case change per field.
