## 1. Install the Packages

Install the runtime package and the build plugin that reads your types.

::code-group
```bash [pnpm]
pnpm add @mionjs/run-types
pnpm add -D @mionjs/devtools
```
```bash [npm]
npm install @mionjs/run-types
npm install -D @mionjs/devtools
```
```bash [yarn]
yarn add @mionjs/run-types
yarn add -D @mionjs/devtools
```
::

::note
Only RunTypes ends up in your runtime bundle, and it has no dependencies. `@mionjs/devtools` works at build time and ships nothing to production.
::

## Import Paths

The main import has the everyday API. The rest is split into subpaths, so you only bundle what you import.

| Import | What it has |
| --- | --- |
| `@mionjs/run-types` | Validators, serializers, reflection and the type helpers |
| `@mionjs/run-types/formats` | Format types like Email and UUIDv4, plus their checks |
| `@mionjs/run-types/formats/temporal` | The TC39 Temporal formats |
| `@mionjs/run-types/builders` | Type builders, for types you assemble at runtime |
| `@mionjs/run-types/runtime` | Pure functions and class serializers you register yourself |
| `@mionjs/run-types/mocking` | Mock data generation |

::tip
Import mocking only from test files. A browser bundle that imports it ships the generator.
::

## Supported Bundlers

Vite is the shortest path, but the same plugin ships for other bundlers. Each one has its own entry point, and every entry takes the same options.

<code-import path="packages/examples/src/introduction/quick-start-rollup-config.ts" lang="ts" />

| Bundler | Import |
| --- | --- |
| Vite | `@mionjs/devtools/runtypes/vite` |
| Rollup | `@mionjs/devtools/runtypes/rollup` |
| Rolldown | `@mionjs/devtools/runtypes/rolldown` |
| webpack | `@mionjs/devtools/runtypes/webpack` |
| Rspack | `@mionjs/devtools/runtypes/rspack` |
| esbuild | `@mionjs/devtools/runtypes/esbuild` |
| Bun | `@mionjs/devtools/runtypes/bun` |
| Next.js | `@mionjs/devtools/runtypes/next` |

The generated code is the same whatever bundler runs it. For a tool that is not on the list, `@mionjs/devtools/unplugin` exposes the [unplugin](https://github.com/unjs/unplugin) instance the others are built from.

The Vite entry adds hot reload on top: while your dev server runs, editing a type refreshes every file that uses it, even a type only import or a global declared in a `.d.ts`.

## Setting Up Bun

The Bun entry covers both of the ways Bun runs plugins.

For a bundle, pass it to `Bun.build`:

```ts
import runtypes from '@mionjs/devtools/runtypes/bun';

await Bun.build({
  entrypoints: ['./src/index.ts'],
  outdir: './dist',
  plugins: [runtypes()],
});
```

With `bun run` or `bun test` there is no bundle step, so the plugin registers on Bun's loader from a preload file. Point `bunfig.toml` at it and every file is compiled as Bun imports it:

```toml
preload = ["./rt-preload.ts"]

[test]
preload = ["./rt-preload.ts"]
```

```ts
// rt-preload.ts
import {plugin} from 'bun';
import runtypes from '@mionjs/devtools/runtypes/bun';

plugin(runtypes());
```

::tip
`await plugin(...)` also works, but you do not need it: no file is loaded before the plugin is ready.
::

## Setting Up Next.js

Turbopack, the bundler Next 16 uses by default, takes no plugins at all, so Next.js has its own entry. Wrap your config and RunTypes handles the rest.

<code-import path="packages/examples/src/introduction/quick-start-next-config.ts" lang="ts" />

The `await` matters: RunTypes reads your types before Turbopack starts compiling.

Options go in a second argument, the same ones every other entry takes:

```ts
export default await withRunTypes({reactStrictMode: true}, {tsconfig: 'tsconfig.json'});
```

One wrapper covers both bundlers, so `next dev --webpack` and `next build --webpack` keep working.

In a monorepo, point Turbopack at the folder that holds your `node_modules` and any shared code you import. Turbopack will not compile files outside that folder:

```ts
import path from 'node:path';

export default await withRunTypes({
  turbopack: {root: path.resolve(import.meta.dirname, '..')},
});
```
