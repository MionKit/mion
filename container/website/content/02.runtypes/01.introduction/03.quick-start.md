## 1. Install the Packages

Install the runtime package and the build plugin that reads your types.

::code-group
```bash [pnpm]
pnpm add @mionjs/run-types
pnpm add -D @mionjs/devtools
```
```bash [npm]
npm install @mionjs/run-types
npm install -D @mionjs/devtools
```
```bash [yarn]
yarn add @mionjs/run-types
yarn add -D @mionjs/devtools
```
::

::note
Only RunTypes ends up in your bundle, and it has no dependencies. `@mionjs/devtools` runs at build time and ships nothing.
::

## Import Paths

The main import has the everyday API. The rest is split into subpaths, so you only bundle what you import.

| Import | What it has |
| --- | --- |
| `@mionjs/run-types` | Validators, serializers, reflection and the type helpers |
| `@mionjs/run-types/formats` | Format types like Email and UUIDv4, plus their checks |
| `@mionjs/run-types/formats/temporal` | The TC39 Temporal formats |
| `@mionjs/run-types/builders` | Type builders, for types you assemble at runtime |
| `@mionjs/run-types/runtime` | Pure functions and class serializers you register yourself |
| `@mionjs/run-types/mocking` | Mock data generation |

::tip
Import mocking only from test files. A browser bundle that imports it ships the generator.
::

## Supported Bundlers

The same plugin ships for other bundlers, one entry point each. Every entry takes the same options and generates the same code. The Vite entry also adds hot reload: editing a type refreshes every file that uses it, even a type only import or a global declared in a `.d.ts`.

<code-import path="packages/private-examples/src/introduction/quick-start-rollup-config.ts" lang="ts" />

| Bundler | Import |
| --- | --- |
| Vite | `@mionjs/devtools/runtypes/vite` |
| Rollup | `@mionjs/devtools/runtypes/rollup` |
| Rolldown | `@mionjs/devtools/runtypes/rolldown` |
| webpack | `@mionjs/devtools/runtypes/webpack` |
| Rspack | `@mionjs/devtools/runtypes/rspack` |
| esbuild | `@mionjs/devtools/runtypes/esbuild` |
| Bun | `@mionjs/devtools/runtypes/bun` |
| Next.js | `@mionjs/devtools/runtypes/next` |

::tip
For a tool not on the list, `@mionjs/devtools/unplugin` exposes the [unplugin](https://github.com/unjs/unplugin) instance the others are built from.
::

## Bundling With Bun

Pass the Bun entry to `Bun.build`:

```ts
import runtypes from '@mionjs/devtools/runtypes/bun';

await Bun.build({
  entrypoints: ['./src/index.ts'],
  outdir: './dist',
  plugins: [runtypes()],
});
```

## Running and Testing With Bun

`bun run` and `bun test` have no bundle step, so register the plugin from a preload file. Point `bunfig.toml` at it and every file is compiled as Bun imports it:

```toml
preload = ["./rt-preload.ts"]

[test]
preload = ["./rt-preload.ts"]
```

```ts
// rt-preload.ts
import {plugin} from 'bun';
import runtypes from '@mionjs/devtools/runtypes/bun';

plugin(runtypes());
```

::tip
`await plugin(...)` works too, but is not needed: no file loads before the plugin is ready.
::

## Setting Up Next.js

Turbopack, the bundler Next 16 uses by default, takes no plugins, so Next.js has its own entry. One wrapper covers Turbopack and webpack, so `next dev --webpack` and `next build --webpack` keep working. Options go in a second argument, the same ones every other entry takes: `withRunTypes({reactStrictMode: true}, {tsconfig: 'tsconfig.json'})`.

## Next.js in a Monorepo

Point Turbopack at the folder that holds your `node_modules` and any shared code you import. Turbopack will not compile files outside that folder.

```ts
import path from 'node:path';

export default await withRunTypes({
  turbopack: {root: path.resolve(import.meta.dirname, '..')},
});
```
