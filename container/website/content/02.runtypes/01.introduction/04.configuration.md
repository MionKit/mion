RunTypes reads its settings from the `plugins` list in your `tsconfig.json`. Configure a project once, and every build tool (Vite, Rollup, webpack, Rspack, esbuild) picks it up.

## Option Reference

Every option is optional; leave one out and the default applies. Set them in your tsconfig plugin entry, shown under [Setting Options](#setting-options).

| Option | Default | What it does |
| --- | --- | --- |
| `genDir` | inferred from tsconfig | The folder for generated files. Build output goes under `types/` (ignored by git); the [enrichment CLI](/runtypes/ai-integration/workflow-and-commands) writes its committed files under `enriched/` (`friendly/`, `mock/`, `i18n/<locale>/`). Each folder has a README. When omitted, it is `.mion` in your source folder (in the working directory for `mion compile` and Next.js), a dot-folder that tsconfig `include` globs skip, so the cache never enters your program. CLI flag: `--gen-dir`. |
| `emitMode` | `code` | How each generated function ships. `code` ships the function body as a string and builds it on first use (smallest output). `functions` ships ready functions. `both` ships both, for runtimes that block dynamic code (a strict CSP, Cloudflare Workers). A mion client built with `bundleApi` always ships ready functions for the routes it calls. |
| `moduleMode` | `default` | How the generated functions group into modules. `default` gives your bundler the best code splitting. `allSingle` groups each feature into one module (fewest files). `allModules` gives every entry its own module (rarely useful). |
| `hashLength` | `7` | Length of the short ids in generated names, always exactly this long. If two types get the same id, the build stops and prints both types, the shared id and the length to try next ([MKR014](/runtypes/diagnostics/all-diagnostics)). That is the only reason to raise it; each extra character gives 62 times more ids. |
| `downgradeErrors` | unset | A RuntimeError (a type that can never be encoded, a contradictory format rule) stops your build: no bundle, and the `mion` command line exits with a failure code. See [Error Levels](/runtypes/diagnostics/error-levels). List the codes to report as warnings instead, for example `['VL002']`; every other code still stops the build. A downgraded error still prints, marked `(downgraded)`. `'*'` downgrades all of them, for a project adopting mion that cannot list its codes yet. An Error cannot be downgraded, `'*'` included; naming one here is refused with the reason. For a bad call site in your own source, prefer a `@mion-expect-error` comment on the line above: it is precise, and an unused one is reported as a warning. |
| `pureFnReport` | off | A report of every pure function this build generated, for tooling that moves pure function bodies between two builds of one codebase (a framework that declares a mapper in client code but runs it on the server). On the bundler plugin: `'file'` writes it to `<genDir>/types/pure-fns-report.json` on every build (a fixed, gitignored path); `'callback'` passes it in process to `onPureFnReport` and writes no file; off (the default) does neither. Each record carries the call site, the pure function's id, the function and package that declared the registrar, and the function body. The shape is the same for every `moduleMode`. In tsconfig, `pureFnReport: true` writes the file (the handler is plugin only); the CLI flags are `--pure-fn-report-file` (writes the JSON) and `--pure-fn-report-wire` (sends it to the calling plugin, no file). |
| `jsonMaxBytes` | `true` | For every reflected type with a fully bounded size (strings with a maximum length, lists with a maximum number of items, and so on), emit the largest JSON a valid value can be. mion turns it into per route request size limits. Set `false` to emit nothing, for a project with its own limits. CLI flag: `--json-max-bytes=false`. |
| `binarySizing` | unset | Tuning for the first buffer a binary encoder allocates, detailed below. |
| `i18n` | unset | Translation settings for the friendly maps, detailed below. Left out, translations are off. |
| `markers` | unset | Which packages may declare the RunTypes marker types, detailed below. Left out, only `@mionjs/run-types` is trusted, which suits almost every project. |
| `tsconfig` | found like tsc | Path to your tsconfig, relative to the project root. It cannot live inside the tsconfig: set it on the bundler plugin, the lint settings, or with the CLI `--tsconfig` flag. When not set, it is found the way tsc finds it, searching upward from the working directory. A config you name must load, or the tool stops with an error. |

::note
mion adds three keys of its own to the same plugin entry. `clientTsconfig` (CLI flag `--client-tsconfig`) names a separate client project a mion API serves batches to, documented with the [mion Vite plugin](/rpc/devtools/vite#batch-transport). `bundleApi` and `apiTsconfig` (CLI flags `--bundle-api` and `--api-tsconfig`) ship a client's routes with it, documented in [Bundling the API Into the Client](/rpc/client/bundled-api).
::

::note
For in-process tooling, the bundler plugin also takes an `onPureFnReport(sites, phase)` callback, with the same records as the JSON file. It fires once with the whole report after the build scan (phase `'build'`), and again under Vite with just the changed file when you edit a pure function body (phase `'update'`). Setting it without `pureFnReport` implies `'callback'`: the report is on and no file is written.
::

### Binary Buffer Sizing

The `binarySizing` object tunes how the first buffer of a binary encoder is sized:

| Key | Default | What it does |
| --- | --- | --- |
| `bias` | `0.8` | How generous that first buffer is, from 0 (tight, may need to grow) to 1 (generous). |
| `items` | `100` | How many elements to assume for an array, Map or Set with no declared limit. |
| `stringBytes` | `32` | How long to assume a string with no declared limit is. |
| `maxBytes` | `65536` | A cap on the estimate, so a very large declared limit never creates a huge buffer. |

### Marker Packages

The `markers` object says where the marker types (`InjectRunTypeId`, `InjectTypeFnArgs`, `CompTimeArgs`, `PureFunction`) may come from. You need it only when a library declares them itself: the compiler trusts a marker only from a package it knows, so an unknown package leaves your type as `unknown`. The build reports this as MKR012 and names the package to add.

```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [
      {
        "name": "mion",
        "markers": {"packages": ["@my-org/runtypes-markers"]}
      }
    ]
  }
}
```

| Key | Default | What it does |
| --- | --- | --- |
| `packages` | none | Extra package names allowed to declare the marker types. It adds to `@mionjs/run-types`, never replaces it, so its markers keep working alongside your own. |
| `checkPackage` | `true` | When `false`, a type counts as a marker on its name alone, whatever package declared it: a type you happen to name `InjectRunTypeId` then drives rewrites too. Prefer naming your package in `packages`. |

::tip
Re-exporting the marker types (`export type {InjectRunTypeId} from '@mionjs/run-types'`) needs no configuration, because the declaration still belongs to RunTypes.
::

### Translations

The `i18n` object configures [translations](/runtypes/ai-integration/i18n) for your [FriendlyText](/runtypes/ai-integration/friendly-type) maps:

| Key | Default | What it does |
| --- | --- | --- |
| `sourceLocale` | `en` | The language your friendly maps are written in. It decides which plural forms `enrich` scaffolds in them. |
| `locales` | none | The locales you translate into; `enrich --i18n all` and its `--no-emit` check walk this list. Don't list the source locale. |
| `strict` | `false` | When `true`, an incomplete or out-of-date translation fails the i18n check by default, the same as passing `--require-complete` to a single run. Rendering at runtime stays lenient either way. |

## Setting Options

Add an entry named `mion` under `compilerOptions.plugins` in your `tsconfig.json`. A `@mionjs/devtools` bundler plugin option or a CLI flag overrides that entry, which overrides the built-in default. Two exceptions: options that describe the build itself (such as `tsconfig`) are plugin only, and the `i18n` object, which belongs to the enrich command, is tsconfig only.

::code-group
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [
      {
        "name": "mion",
        "emitMode": "code",
        "moduleMode": "default",
        "i18n": {"sourceLocale": "en", "locales": ["es", "pl"]}
      }
    ]
  }
}
```

```ts [vite.config.ts]
import {defineConfig} from 'vite';
import runtypes from '@mionjs/devtools/runtypes/vite';

export default defineConfig({
  plugins: [runtypes({emitMode: 'functions'})],
});
```
::

::note
Order `@mionjs/devtools` first among your `enforce: 'pre'` plugins, so it sees your source before other plugins rewrite it.
::

::tip
Set your options once in tsconfig. Use a build-tool option or a CLI flag only when a single build needs to differ.
::

## Syncing Enrichment Files During Dev

The `@mionjs/devtools` bundler plugin can scaffold and sync your committed `FriendlyText` and `MockData` maps while your dev server runs, instead of you running the [enrichment CLI](/runtypes/ai-integration/workflow-and-commands). Turn it on with an `enrich` object on the plugin (never in your tsconfig); it runs only in dev and watch. Like `enrich --update`, it updates the file structure but never fills in translated strings or any other value you wrote.

```ts [vite.config.ts]
import {defineConfig} from 'vite';
import runtypes from '@mionjs/devtools/runtypes/vite';

export default defineConfig({
  plugins: [
    runtypes({
      enrich: {
        friendly: true,
        mock: true,
        i18n: {sourceLocale: 'en', locales: ['es', 'pl']},
        suppressHmr: true,
      },
    }),
  ],
});
```

| Key | Default | What it does |
| --- | --- | --- |
| `friendly` | `false` | Scaffold and sync the `enriched/friendly/` maps as your types change. |
| `mock` | `false` | Scaffold and sync the `enriched/mock/` maps as your types change. |
| `i18n` | unset | Sync the per-locale `enriched/i18n/<locale>/` mirrors. Takes `sourceLocale`, `locales` and `strict`, the same shape as the tsconfig i18n object; its presence turns the locale sync on. |
| `suppressHmr` | on when any key above is on | Skip HMR for writes under `<genDir>/enriched`, so the dev server does not reload when the plugin (or you) touch a mirror file. |

## Enrichment Check on Production Builds

With `enrich` set, a production build never writes. The plugin runs a read-only check instead (the build equivalent of `enrich --require-complete`), and fails the build if any file is out of date, missing, still carries an unfilled blank, or holds a stale `@rtOrphan` entry.

## The Build Cache

RunTypes keeps a cache under `node_modules/.cache/mion` so a rebuild can skip types that did not change. It is on when your tsconfig sets `incremental` (or `composite`), and off otherwise; there is no separate option.

```json [tsconfig.json]
{
  "compilerOptions": {
    "incremental": true
  }
}
```

::note
Stale entries are never read after a new release or a changed setting. Anything that wipes `node_modules/.cache` clears it.
::
