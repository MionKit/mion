RunTypes does not reimplement TypeScript. It is built on **typescript-go**, the Go rewrite of the TypeScript compiler that ships as TypeScript 7 and runs as `tsgo`. RunTypes asks that compiler about your types, so you get the same answer TypeScript gives.

## RunTypes as a Superset of TypeScript

RunTypes adds a layer on top of TypeScript. It never changes the language.

- **Anything that works on typescript-go works with RunTypes.** The same checker reads your types, so RunTypes understands whatever `tsgo` understands.
- **100% compatible.** No compiler flag to turn on, no schema dialect to learn. Point the plugin at your `tsconfig.json` and your types are the schema.
- **A strict superset.** You keep everything TypeScript gives you, plus runtime functions generated from those same types: validators, JSON and binary serializers, mock data and reflection.

## Extending typescript-go Without Modifying It

The RunTypes binary carries the complete compiler: it loads your `tsconfig.json`, builds the same program `tsgo` would build, and runs the same type checker.

```bash
$ npx mion --version
mion 0.1.0 (tsgo v0.21.1)
```

The value in parentheses is the pinned typescript-go revision the binary was built against; your numbers will differ per release.

## RunTypes as a Complement to typescript-go

The embedded compiler could type check and even emit JavaScript for your whole project, the same way `tsgo` does. RunTypes does not do that. Its single job is to take the compiler's understanding of your types and turn it into runtime code.

::note
RunTypes ships no `build` or `tsc` style command. Keep running `tsgo` (or `tsc`) for your build exactly as you do today.
::

## Current Limitations of the Compiler

**typescript-go is still a preview.** TypeScript 7 is under active development and is not the stable default yet, so a rough edge can come from the compiler itself.

**For now, RunTypes runs as a second pass.** The hook that once let runtime libraries plug into the compiler was never ported to the Go compiler ([microsoft/typescript-go#516](https://github.com/microsoft/typescript-go/issues/516)), so `tsgo` and the RunTypes binary run as two separate processes. Each builds its own view of the project, so your files are read twice.

That second read costs build time only, and nothing about it reaches your runtime bundle. If the compiler ever exposes a supported extension point, RunTypes would fold into a single pass.

See [About mion RunTypes](/runtypes/introduction/about-mion-runtypes) for the design decisions behind all of this, or jump to the [Quick Start](/runtypes/introduction/quick-start) to wire it up.
