::diagnostic-levels
::

Every diagnostic has a name like `validate-symbol-root`: its area, then what went wrong. Error and RuntimeError both print the word `error`, so check the name to see which one you got. Every name is listed in [All Diagnostics](/runtypes/diagnostics/all-diagnostics).

## Where Each Level Shows

The dev server shows only what breaks your running code.

| Where | Error | RuntimeError | Warning | Info |
| --- | --- | --- | --- | --- |
| Editor, through the [lint rules](/runtypes/tooling/linting) | `mion/error` | `mion/runtime-error` | `mion/warning` | `mion/info`, off by default |
| Dev server terminal | printed once | printed once | one line counting them | not printed |
| Browser overlay | shown when its file loads | not shown | not shown | not shown |
| Build and CI | printed, the build stops | printed, the build stops | printed | printed with `levels: 'all'` |

::tip
The dev server never stops on an error. A function with a RuntimeError throws when your code calls it.
::

## Disabling Errors

Two comments turn an error off:

- `@mion-expect-error` hides it.
- `@mion-downgrade-error` shows it as a warning, so the build does not fail.

Use `//` above a line to cover that line. Use `/* */` at the top of the file, before any code, to cover the whole file. Several names fit on one comment.

<code-import path="packages/private-examples/src/guide/disabling-errors.ts" lang="ts [disabling-errors.ts]" />

| Comment | Placement | What happens |
| --- | --- | --- |
| `// @mion-expect-error validate-symbol-root` | its own line | validate-symbol-root on the next line is hidden |
| `// @mion-downgrade-error validate-symbol-root` | its own line | validate-symbol-root on the next line becomes a warning |
| `/* @mion-expect-error validate-symbol-root */` | top of the file | every validate-symbol-root in the file is hidden |
| `/* @mion-downgrade-error validate-symbol-root */` | top of the file | every validate-symbol-root in the file becomes a warning |
| `/* @mion-expect-error */` | top of the file | every error in the file is hidden |

::tip
Always name the diagnostic. A comment with no name also hides errors you have not seen yet. A comment that turns nothing off is reported (`comment-expect-error-unused` or `comment-downgrade-error-unused`).
::

## Downgrading Errors in Config

`downgradeErrors` turns the errors you list into warnings, across the whole project. Use it when you cannot add a comment: the type is in a package you do not own, or the problem is in your config. Only the tsconfig setting also lowers them in the linter.

::code-group
```ts [vite.config.ts]
mionVitePlugin({
  runTypes: {
    downgradeErrors: ['marker-comptime-arg-forbidden-construct'],
  },
});
```
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "downgradeErrors": ["marker-comptime-arg-forbidden-construct"]}]
  }
}
```
::

A downgraded error still prints on every build:

```
node_modules/some-lib/adapter.js(41,9): warning marker-comptime-arg-forbidden-construct: ... (downgraded)
```

All the options are listed in [Configuration](/runtypes/introduction/configuration#option-reference).

::tip
`'*'` turns every error into a warning at once, useful when adding mion to an existing project. List the real names once you know them. An Error is never downgraded, not even by `'*'`.
::

## Showing Info Messages

Info messages are hidden in the build, the `mion` command line and the linter. Set `levels: 'all'` in your tsconfig to show them in the build and the command line. The build plugin also has its own setting, and the linter shows them with its [`mion/info` rule](/runtypes/tooling/linting#showing-info-messages).

::code-group
```ts [vite.config.ts]
mionVitePlugin({
  runTypes: {
    levels: 'all',
  },
});
```
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "levels": "all"}]
  }
}
```
::

## Grouping Messages

The build, the dev server and the `mion` command line print each message once, then every place it happens:

```text
error validate-non-data-root (2)
  Type `{type}` can never be validated: the generated function will always fail.
    src/routes/user.ts:12:7  type=FileHandle
    src/jobs/upload.ts:41:2  type=Socket

mion: 2 errors in 2 files
```

A value that is the same in every place goes into the message. Set `logStyle: 'lines'` to print one full line per message instead, the form CI tools read.

::code-group
```ts [vite.config.ts]
mionVitePlugin({
  runTypes: {
    logStyle: 'lines',
  },
});
```
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "logStyle": "lines"}]
  }
}
```
::
