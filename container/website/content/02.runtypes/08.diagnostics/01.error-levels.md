Error and RuntimeError both print the word `error`, so check the code to see which one you got. Every code is listed in [All Diagnostics](/runtypes/diagnostics/all-diagnostics).

## Where Each Level Shows

The dev server shows only what breaks your running code.

| Where | Error | RuntimeError | Warning | Info |
| --- | --- | --- | --- | --- |
| Editor, through the [lint rules](/runtypes/tooling/linting) | `mion/error` | `mion/error` | `mion/warning` | `mion/info`, off by default |
| Dev server terminal | printed once | printed once | one line counting them | not printed |
| Browser overlay | shown when its file loads | not shown | not shown | not shown |
| Build and CI | printed, the build stops | printed, the build stops | printed | printed with `levels: 'all'` |

::tip
The dev server never stops on an error. A function with a RuntimeError throws when your code calls it.
::

## Disabling Errors

Two comments turn an error off:

- `@mion-expect-error` hides it.
- `@mion-downgrade-error` shows it as a warning, so the build does not fail.

Use `//` above a line to cover that line. Use `/* */` at the top of the file, before any code, to cover the whole file. Several codes fit on one comment.

<code-import path="packages/private-examples/src/guide/disabling-errors.ts" lang="ts [disabling-errors.ts]" />

| Comment | Placement | What happens |
| --- | --- | --- |
| `// @mion-expect-error VL002` | its own line | VL002 on the next line is hidden |
| `// @mion-downgrade-error VL002` | its own line | VL002 on the next line becomes a warning |
| `/* @mion-expect-error VL002 */` | top of the file | every VL002 in the file is hidden |
| `/* @mion-downgrade-error VL002 */` | top of the file | every VL002 in the file becomes a warning |
| `/* @mion-expect-error */` | top of the file | every error in the file is hidden |

::tip
Always name the code. A comment with no code also hides errors you have not seen yet. A comment that turns nothing off is reported (`EXP001` or `DWN001`).
::

## Downgrading Errors in Config

`downgradeErrors` turns the codes you list into warnings, across the whole project. Use it when you cannot add a comment: the type is in a package you do not own, or the problem is in your config. Only the tsconfig setting also lowers them in the linter.

::code-group
```ts [vite.config.ts]
mionVitePlugin({
  runTypes: {
    downgradeErrors: ['CTA003'],
  },
});
```
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "downgradeErrors": ["CTA003"]}]
  }
}
```
::

A downgraded code still prints on every build:

```
node_modules/some-lib/adapter.js(41,9): warning CTA003: ... (downgraded)
```

All the options are listed in [Configuration](/runtypes/introduction/configuration#option-reference).

::tip
`'*'` turns every code into a warning at once, useful when adding mion to an existing project. List the real codes once you know them. An Error is never downgraded, not even by `'*'`.
::

## Showing Info Messages

Info messages are hidden in the build, the `mion` command line and the linter. Set `levels: 'all'` in your tsconfig to show them in the build and the command line. The build plugin also has its own setting, and the linter shows them with its [`mion/info` rule](/runtypes/tooling/linting#showing-info-messages).

::code-group
```ts [vite.config.ts]
mionVitePlugin({
  runTypes: {
    levels: 'all',
  },
});
```
```json [tsconfig.json]
{
  "compilerOptions": {
    "plugins": [{"name": "mion", "levels": "all"}]
  }
}
```
::
