The lint plugin ships inside `@mionjs/devtools` and works with OXlint (its main target) and ESLint v9 flat config. The compiler that builds your code reports the problems, so your editor shows what the build shows.

## Lint Rules

| Rule | Default | What it reports |
| --- | --- | --- |
| `runtypes/broken-tsconfig` | `error` | The tsconfig (your `tsconfig` setting, or `tsconfig.json` by default) is missing or does not parse, so type-aware linting cannot run. Fix the config, or the path you set. |
| `runtypes/invalid-expect-error` | `warn` | A `@mion-expect-error` comment that hides nothing, names a code that is always reported, or names a code that does not exist. |
| `runtypes/invalid-downgrade-error` | `warn` | A `@mion-downgrade-error` comment that lowers nothing, names a code that always stops the build, names a code that does not exist, or names one that is already a warning. |
| `runtypes/invalid-marker` | `error` | A marker call the build cannot turn into a function: a generic type argument never filled in with a concrete type, an options argument that is not a plain literal, an import that does not resolve, or a Temporal type without the Temporal lib enabled. |
| `runtypes/redundant-marker` | `warn` | A marker that works but probably not as you meant, such as a function called inside a marker only for its return type (the call is wasted), or an option with no effect on this type. |
| `runtypes/pure-functions` | `error` | A registered pure function that breaks the purity rules (uses `this`, `await`, or variables from outside its own body), is registered twice with different bodies, or is referenced but never registered. |
| `runtypes/validate-non-serializable` | `error` | A type that can never be validated. Validators check the [data-only projection](/runtypes/guide/validation) of your type (the JSON-shaped data), so a type like `symbol` or `WeakMap` at a root position has nothing to check and the generated function always fails. |
| `runtypes/validate-skipped-member` | `warn` | A property the validator silently skips. Functions, methods, statics, and symbols are not data, so the validator checks the rest of the object and ignores them. |
| `runtypes/json-non-serializable` | `error` | A type that can never be encoded to or decoded from JSON, such as a function, a `symbol`, or a `WeakMap` at a root position. The generated function would always fail, so the build stops. |
| `runtypes/json-skipped-member` | `warn` | A property the JSON encoder and decoder silently leave out, such as a function or symbol member. The rest of the object round-trips normally. |
| `runtypes/clone-unsupported-type` | `error` | A type `removeUnknownKeys` cannot clone safely: a union of objects (the clone cannot tell which shape to rebuild) or a callable root. A clone that guessed could keep unknown keys, so the build stops. |
| `runtypes/clone-shared-reference` | `warn` | A property the clone cannot rebuild (a function, symbol, or non-serializable built-in), so it stays pointing at the same value as the original. Changes through it are visible on both copies. |
| `runtypes/format` | `error` | A custom string format with a broken definition: a mock sample that does not match its own pattern, a sample that violates a sibling rule like maxLength, a pattern that is not a valid regular expression, or invalid params. |
| `runtypes/invalid-override` | `error` | An override that cannot work: the same type and function registered twice, or an override pointing at a generated module that does not exist. |
| `runtypes/override-side-effect` | `warn` | A validate override on a type whose JSON decoders also run validation internally. The override changes their behaviour too. |
| `runtypes/non-enumerable` | `warn` | A property marked `@nonEnumerable` that is not optional. A non-enumerable property can be absent from a plain object, so the type must allow undefined. |
| `runtypes/unsafe-property-name` | `warn` | A property named `__proto__`. Writing that name on a plain object swaps the prototype instead of storing a value, so the member is dropped from every compiled function. Rename it to keep the data. |
| `runtypes/other` | `error` | Any other RunTypes compiler problem the rules above do not cover. |
| `runtypes/no-enrichment-todo` | `warn` | An unfilled `@todo` placeholder the generator scaffolded in a `FriendlyText` or `MockData` file. Fill in the value, then delete the tag line. |
| `runtypes/no-orphan-carcass` | `warn` | A commented-out `@rtOrphan` or `@rtOrphanChild` block the generator left behind when a type or field disappeared. Restore the type, or run `mion enrich --prune` to remove it. |
| `runtypes/enrichment-field` | `error` | An entry in a `FriendlyText` or `MockData` map that no longer matches the type: a field the type does not declare, or a name colliding with the reserved rt$ prefix. |
| `runtypes/enrichment-message` | `warn` | A friendly error message template with a problem: an error key that is not a constraint of the field, an unknown placeholder, or a plural form that is not a valid category. |
| `runtypes/enrichment-broken-source` | `error` | A generated file whose source is gone: the file it mirrors no longer exists, or no longer declares the imported type. Re-run the generator, or delete the mirror. |
| `runtypes/enrichment-misplaced-file` | `warn` | A generated file that is no longer where the generator would write it, usually after its source file moved. Re-run the generator to relocate it. |

## Lint Plugin Setup

Extend the recommended config from `@mionjs/devtools` to turn on every rule at the defaults above. Your own rule levels win over the preset.

::code-group
```json [.oxlintrc.json]
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "extends": ["./node_modules/@mionjs/devtools/oxlint-recommended.json"],
  "rules": {
    "runtypes/validate-skipped-member": "off"
  }
}
```

```js [eslint.config.js]
import runtypes from '@mionjs/devtools/eslint';

export default [
  runtypes.configs.recommended,
  {rules: {'runtypes/validate-skipped-member': 'off'}},
];
```
::

## Choosing the TypeScript Config

The plugin reads your full project `tsconfig.json`, so the linter checks types the way your build does: `lib`, `target`, `strict`, module resolution, custom conditions and path mappings all apply. By default it finds the config the way tsc does, searching upward from the directory the linter runs in. Point it at a different config with a setting:

::code-group
```json [.oxlintrc.json]
{
  "settings": {"runtypes": {"tsconfig": "tsconfig.lint.json"}}
}
```

```js [eslint.config.js]
export default [
  runtypes.configs.recommended,
  {settings: {runtypes: {tsconfig: 'tsconfig.lint.json'}}},
];
```
::

::tip
A broken config is a `runtypes/broken-tsconfig` error. Fix it and the next lint pass picks it up.
::

## Running the Linter from the CLI

The CLI reports the same problems, for CI jobs or scripts that do not run a node linter:

```bash
mion compile --no-emit
mion enrich src/.mion/enriched/friendly/src/models/user.ts --no-emit --json
mion enrich --no-emit --json
```

`compile --no-emit` reports the build's marker and serialization problems and writes nothing. `enrich --no-emit` on one file reports its tag, content and drift problems, and exits 1 on errors. With a directory, or no path, it checks the whole mirror directory for drift.
