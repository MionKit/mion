A marker is a type you add to a function parameter, almost always the last one. You write the type, the build fills in the value, then the marker is erased. Every `createX` factory uses one, and you can use the same markers in your own helpers.

## List of Compiler Markers

Each marker does a different job at build time.

::card-group
---
class: sm:grid-cols-2 rt-markers
---
:::card
---
title: Factory injection
---
```ts
id?: InjectTypeFnArgs<T, Fn>
```
Validates the call site's compile-time arguments, then injects the one generated function you asked for. Every `createX` declares it; you never write it.
:::

:::card
---
title: Reflection id
---
```ts
id?: InjectRunTypeId<T>
```
Injects a short, stable id for `T` at each call site. The one marker you are likely to type, for wrapping your own helpers.
:::

:::card
---
title: Compile-time literals
---
```ts
options: CompTimeArgs<T>
```
Brands a parameter as "must be a literal at the call site" (or a `const` of literals). Static check only.
:::

:::card
---
title: Variant selection
---
```ts
options: CompTimeFnArgs<T>
```
Like `CompTimeArgs`, but the literal also selects which variant of a factory you get, such as the JSON encoder strategy. Static check only.
:::

:::card
---
title: Pure functions
---
```ts
fn: PureFunction<F>
```
Brands a pure function argument that passes the purity rules. The direct form: the argument is the helper itself. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
---
title: Pure function factories
---
```ts
fn: PureFunctionFactory<F>
```
The factory form of the above, for a helper that needs one-time setup or composes another pure fn. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
---
title: Pure function id
---
```ts
id?: InjectPureFnId<F>
```
Injects a pure helper's id (where it lives), so a library can wrap the registrar. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
Seven markers in total: one you will type, and six you will not.


None of them reach runtime. The build reads each one, does its job, and emits ordinary JavaScript.
:::
::

## Injecting a Type Id into a Helper

`InjectRunTypeId<T>` is the one marker you are likely to type yourself. Add a trailing `id?: InjectRunTypeId<T>` to a generic function and the build injects the type's id at every call site, so you never pass it by hand.

::note
The marker only fires where `T` is concrete, at a real call site, not inside a generic body.

## Requesting Several Functions in One Marker

One `InjectTypeFnArgs` marker can name several function families. A route wrapper that validates a request, decodes it from JSON, and encodes the response asks for all three in one marker.

<code-import path="packages/examples/src/guide/markers-multi-family.ts" lang="ts" />

Name each family at most once: a duplicate is MKR006. A name that matches no family is MKR015, and the error suggests the closest real name when there is one.
