The ideas on this page apply to both [JSON Serialization](/runtypes/guide/json-serialization) and [Binary Serialization](/runtypes/guide/binary-serialization).

## Encoding and Restoring Values

An encoder turns a typed value into JSON text or bytes, and a decoder turns it back into the same JavaScript value. The build generates both from your type, so you write no schema.

<code-import path="packages/examples/src/guide/ser-overview.ts" lang="ts" commentStart="// start-roundtrip" commentEnd="// end-roundtrip" />

| Value in your type | What the decoder returns |
| --- | --- |
| string, number, boolean, null | The same value |
| bigint | A bigint |
| Date | A Date |
| Map, Set | A Map or a Set, with its keys and values restored |
| Temporal types | The same Temporal type |
| Class instance | A real instance when the class is [registered](/runtypes/guide/json-serialization#class-serializers), a plain object otherwise |

## Serialization Functions

Each `createX<T>()` call returns a function the build made for `T`. Create it once and call it as often as you need.

| Function | What it does | Page |
| --- | --- | --- |
| `createJsonEncoderFn<T>()` | Writes a value as a JSON string | [JSON](/runtypes/guide/json-serialization#encoding-and-decoding-json) |
| `createJsonDecoderFn<T>()` | Reads a JSON string back, with no checks | [JSON](/runtypes/guide/json-serialization#encoding-and-decoding-json) |
| `createParseFn<T>()` | Restores and checks the output of `JSON.parse` | [JSON](/runtypes/guide/json-serialization#parsing-json) |
| `createBinaryEncoderFn<T>()` | Writes a value as bytes | [Binary](/runtypes/guide/binary-serialization#encoding-and-decoding-bytes) |
| `createBinaryDecoderFn<T>()` | Reads bytes back, with no checks | [Binary](/runtypes/guide/binary-serialization#encoding-and-decoding-bytes) |

::tip
Use JSON when any client must read the payload, and binary when both ends share the type. The [format benchmarks](/benchmarks/runtypes/serialization-formats) compare the two.
::

## Only Data Is Serialized

Only the data part of your type is serialized. Members with no data form are dropped by every encoder and decoder, and decoders return `DataOnly<T>`: your type without those members.

<code-import path="packages/examples/src/guide/ser-data-only.ts" lang="ts" commentStart="// start-data-only" commentEnd="// end-data-only" />

| Member | What happens |
| --- | --- |
| Function or method | Dropped |
| Symbol value or symbol key | Dropped |
| RegExp | Dropped |
| Promise | Dropped |
| ArrayBuffer, DataView or typed array | Dropped |
| A member named `__proto__` | Dropped |

::tip
A dropped member gives a build warning. A whole type with no data form, such as a function type, gives a build error, and its generated function throws when called.
::

## Why Only Data

A function, a method or a RegExp is code, and sending it would make the receiver run code it got from the wire. A symbol is an identity that cannot be rebuilt on the other side. `DataOnly<T>` makes the return type match what actually arrives, so you never call a method that is not there.

## Undeclared Keys

Functions that remove undeclared keys take the list of allowed keys from your type at build time, never from the incoming value.

<code-import path="packages/examples/src/guide/ser-undeclared-keys.ts" lang="ts" commentStart="// start-undeclared" commentEnd="// end-undeclared" />

| Function | Keys your type does not declare |
| --- | --- |
| JSON encoder | Left out, unless you pick the [mutate strategy](/runtypes/guide/json-serialization#encoder-strategies) |
| JSON decoder | Set by the [decoder strategy](/runtypes/guide/json-serialization#decoder-strategies) |
| Parse | Kept by default, removed or rejected by [strategy](/runtypes/guide/json-serialization#undeclared-keys-in-parse) |
| Binary encoder and decoder | Never written: the bytes hold only declared members |
| Validator | Accepted, unless you turn on the [unknown key check](/runtypes/guide/validation) |
| Registered class rebuild | Never set on the instance |

## Undeclared Keys in Unions

The JSON functions that remove keys cannot tell which union member matched, so they keep any key that some member declares. A union with a record member keeps every key, since a record declares them all.

::tip
To reject a key that the matched member does not declare, use parse with the `fail` strategy, or the unknown key options of the [validator](/runtypes/guide/validation).
::

## Parsing Versus Decoding

A decoder trusts its input: it restores values fast and checks nothing. Parse restores the value and then checks it against your type. Use a decoder for data you produced, and parse for anything a user or another service sends.

| | Decoder | Parse |
| --- | --- | --- |
| Formats | JSON and binary | JSON |
| Checks the value | No | Yes, after restoring it, so a Date string is checked as a Date |
| Bad input | Can return a value that fails validation, or throw an engine error | Always throws `RTParseError` |

::tip
Encoders trust your value too. A value that does not match its type can throw an engine error or write wrong data, so validate values you did not build yourself.
::

## Security

Decoders refuse input that could harm your process, and encoders never send data your type does not declare.

### Checks on Incoming Data

Anything not listed here is left for validation to reject.

| Input | Decoder | Parse |
| --- | --- | --- |
| A `__proto__` key in a record (`constructor` and `prototype` are ordinary keys) | Throws `[mion] Unsafe property name: __proto__` | Throws `RTParseError` |
| A wrong wire form, such as `null` for a Date or a number for a Set | Leaves it as is, so validation fails | Throws `RTParseError` |
| A bigint string that is not plain digits, such as `"0x1f"` or `" 42 "` | Leaves it as a string | Throws `RTParseError` |
| Bad content in the right form, such as an invalid Temporal string | Throws the engine error | Throws `RTParseError` |
| An object with a `length` key where an array goes | Does not loop over it, leaves it for validation | Throws `RTParseError` |
| A union value with an unknown member index | Throws | Throws `RTParseError` |
| A registered class whose `deserialize` throws | Throws that error | Throws `RTParseError` |
| Nesting deeper than the JavaScript stack | Can throw `RangeError` | Throws `RTParseError` |
| Malformed bytes | Throws [BinaryDecodeError](/runtypes/guide/binary-serialization#binary-decode-errors) | Not available for bytes |

::tip
A class `deserialize` handler runs before validation, so treat its input as unchecked. On a recursive type, limit the nesting depth of a body from an untrusted sender before parsing it.
::

### Checks on Outgoing Data

Encoders write only the data your type declares, with these extra guards.

| Case | What happens |
| --- | --- |
| An optional member the value holds as non-enumerable, such as an Error `stack` | Not written, so a stack trace never leaves your process |
| Your own optional member marked with a `/** @nonEnumerable */` comment | Written only when the value holds it as enumerable |
| A `__proto__` key in a record value | Left out by the clone and compact JSON encoders. The mutate and direct JSON encoders and the binary encoder write it, and the receiving decoder refuses it |
| A value that references itself | Throws `RangeError`, or a [CircularReferenceError](/runtypes/guide/json-serialization#circular-references) with the `rejectCircularRefs` option |

### Compiler Cache

The generated functions are built from text at startup, read from the compiler's disk cache under `node_modules/.cache/mion`. Trust that cache as you trust `node_modules`: whoever can write there can change what your build runs. Keep it out of any location an untrusted process can write.
