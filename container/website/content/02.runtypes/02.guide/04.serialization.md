## How Serializers Work

The build generates an encoder and a decoder for your type. The encoder turns a value into JSON or bytes, and the decoder rebuilds it with Dates, bigints, Maps and Sets as real values again.

| Format | Encoder | Decoder | Details |
| --- | --- | --- | --- |
| JSON | `createJsonEncoderFn` | `createJsonDecoderFn`, or `createParseFn` to validate too | [JSON Serialization](/runtypes/guide/json-serialization) |
| Binary | `createBinaryEncoderFn` | `createBinaryDecoderFn` | [Binary Serialization](/runtypes/guide/binary-serialization) |

::tip
Only the data in your type crosses the wire: functions, methods and symbols are dropped. See [Why Only Serializable Data](/runtypes/guide/json-serialization#why-only-serializable-data).
::

## Security

A decoder rebuilds a value but does not check it against your type.

### Decoding Untrusted Input

Pick the decoder by where the data comes from.

| Data from | Use |
| --- | --- |
| Your own code, or already validated | `createJsonDecoderFn` or `createBinaryDecoderFn` |
| Anyone else, as JSON | `createParseFn`: decodes and validates in one pass, and throws only `RTParseError`, however malformed the input. See [Parsing and Validating in One Step](/runtypes/guide/json-serialization#parsing-and-validating-in-one-step) |
| Anyone else, as bytes | `createBinaryDecoderFn`, then `createValidateFn` on the result before you use it |

::tip
The `strip` strategy blanks every undeclared property at every level, inside Map values and Set members too, before the declared shape is restored.
::

### What Decoders Refuse

A decoder converts a value only when it has the form the encoder writes. Anything else is left for validate to refuse, except a few things validate could never see, which the decoder refuses itself.

| Input | JSON decoders | Binary decoder |
| --- | --- | --- |
| A value of the wrong shape (a `null` where a Date string goes, `true` where a bigint goes) | Left as it is, validate refuses it | Not possible, the layout is fixed by the type |
| A bigint string that is not a whole number (`"12x"`, `"1e3"`, `""`) | Left as a string, validate refuses it | Left as a string, validate refuses it |
| An invalid date string | Comes back as an Invalid Date, validate refuses it | Comes back as an Invalid Date, validate refuses it |
| A Temporal string with bad content | The engine error is thrown, `parse` reports it as a serialization error | The engine error is thrown |
| A union envelope that is not a two-slot array (a bare value, a `null`) | The decoder throws a `[mion]` error | Not possible, the layout is fixed by the type |
| A union index or discriminator that matches no member | The decoder throws a `[mion]` error | The decoder throws a `[mion]` error |
| A property key named `__proto__` | The decoder throws a `[mion]` error | The decoder throws `BinaryDecodeError` |
| A cut-off buffer, a count or length past the bytes left, invalid UTF-8 | Not applicable | The decoder throws `BinaryDecodeError` |
| An `any`, `unknown` or `object` slot | Passed through unchecked | Parsed from JSON text, unchecked |

### Accepted Wire Forms

Validation runs after the decoder, so the decoder is the only check between untrusted JSON and a constructor: `new Date(true)` is a real date (epoch 1), `BigInt('')` is `0n`, `new Set(null)` is an empty set.

| Type | Converted only from |
| --- | --- |
| Date, Temporal types | a string |
| bigint | a whole-number string, or a whole number |
| Map, Set | an array |
| a union with a wire envelope | a two-slot array (anything else is refused with a typed error, since a bare value could pass validation as the wrong member) |

### Values That Cannot Cross the Wire

RegExp values and symbols, a symbol literal like `typeof mySymbol` included, cannot cross the wire. Two symbols are never equal, so a decoder could only hand you a different symbol.

As a property or a union member, either one is dropped with a build Warning, so `Date | symbol` encodes as `Date`. On its own, as an array element, or when every union member is dropped, it is a RuntimeError and the build fails.

::tip
The only regex that reaches a validator is a `pattern` format, fixed at build time. In place of a symbol, use a string literal union.
::

### Nesting Depth

On a recursive type, a value nested deeper than the engine's call stack makes validate throw `RangeError`, and `parse` reports it as a serialization error. Limit the nesting depth of a JSON body from an untrusted sender before parsing it.

### Prototype Keys in Data

`__proto__` is the only name mion treats differently: writing that key on a plain object swaps the prototype instead of storing a value. As a record key, both decoders and validate refuse it, and every encoder and clone that rebuilds an object from its keys skips it. `prototype` and `constructor` are ordinary names: a record can carry them as keys, and a type can declare them.

```ts
const decode = createJsonDecoderFn<Record<string, string>>();
decode('{"__proto__":{"admin":true}}'); // throws [mion] Unsafe property name: __proto__
decode('{"constructor":"builder","prototype":"draft"}'); // both keys, as written
```

### Prototype Keys in Types

A declared `__proto__` property is dropped, like any property that cannot cross the wire, and the rest of the type still works. TypeScript accepts the declaration, so mion warns about it: the type promises a value that does not exist at runtime.

```ts
interface Settings {ok: number; __proto__: string}
const value: Settings = {ok: 1, __proto__: 'x'}; // compiles
Object.keys(value); // ['ok']
```

### Compiler Cache

The generated functions are built from text at startup, read from the compiler's disk cache under `node_modules/.cache/mion`. Trust that cache as you trust `node_modules`: whoever can write there can change what your build runs. Keep it out of any location an untrusted process can write.
