## Choosing a Decoder

A decoder rebuilds a value from the wire. It does not check that the value matches your type, so use `createJsonDecoderFn` and `createBinaryDecoderFn` only for data you produced yourself, or data that was validated before it reached you.

For JSON from anyone else, use `createParseFn`. It decodes and validates in one walk, and it is the one function that can never throw anything but `RTParseError`, however malformed the input. For bytes from anyone else, decode with `createBinaryDecoderFn` and run the result through `createValidateFn` before you use it.

## Handling Bad Input

A decoder converts a value only when it has the form the encoder writes. Anything else is left for validate to refuse, except a few things validate could never see, which the decoder refuses itself.

| Input | JSON decoders | Binary decoder |
| --- | --- | --- |
| A value of the wrong shape (a `null` where a Date string goes, `true` where a bigint goes) | Left as it is, validate refuses it | Not possible, the layout is fixed by the type |
| A bigint string that is not a whole number (`"12x"`, `"1e3"`, `""`) | Left as a string, validate refuses it | Left as a string, validate refuses it |
| An invalid date string | Comes back as an Invalid Date, validate refuses it | Comes back as an Invalid Date, validate refuses it |
| A Temporal string with bad content | The engine error is thrown, `parse` reports it as a serialization error | The engine error is thrown |
| A union envelope that is not a two-slot array (a bare value, a `null`) | The decoder throws a `[mion]` error | Not possible, the layout is fixed by the type |
| A union index or discriminator that matches no member | The decoder throws a `[mion]` error | The decoder throws a `[mion]` error |
| A property key named `__proto__` | The decoder throws a `[mion]` error | The decoder throws `BinaryDecodeError` |
| A cut-off buffer, a count or length past the bytes left, invalid UTF-8 | Not applicable | The decoder throws `BinaryDecodeError` |
| An `any`, `unknown` or `object` slot | Passed through unchecked | Parsed from JSON text, unchecked |

## Wire Forms That Convert

Validation runs after the decoder, so the decoder is the only check between untrusted JSON and a constructor: `new Date(true)` is a real date (epoch 1), `BigInt('')` is `0n`, `new Set(null)` is an empty set.

| Type | Converted only from |
| --- | --- |
| Date, Temporal types | a string |
| bigint | a whole-number string, or a whole number |
| Map, Set | an array |
| a union with a wire envelope | a two-slot array (anything else is refused with a typed error, since a bare value could pass validation as the wrong member) |

This list is a guarantee, not a habit: the build fails when a decoder converts a value without checking its shape first.

A value nested deeper than the engine's call stack on a recursive type makes validate throw `RangeError`. `parse` reports that as a serialization error. Limit the nesting depth of a JSON body before parsing it when the sender is untrusted.

The `strip` strategy blanks every undeclared property at every level, inside Map values and Set members included, before the declared shape is restored.

::note
RegExp values cannot cross the wire. A property typed `RegExp` is dropped like a function is, with the same build Warning, and a `RegExp` at a root, array or union position is a RuntimeError: the function is written as one that throws, and the build fails. The only regex that reaches a validator is a `pattern` format, which is fixed at build time.
::

::note
Symbols cannot cross the wire either, a symbol literal like `typeof mySymbol` included. Two symbols are never equal, so a decoder could only hand you a different symbol. A symbol property is dropped with a build Warning, and a symbol at a root, array or union position fails the build. Use a string literal union instead.
::

## Unsafe Property Names

`__proto__` is the only name mion treats differently: writing that key on a plain object swaps the object's prototype instead of storing a value.

As a key in a record it is refused by both decoders, refused by validate, and skipped by every encoder and clone that rebuilds an object from its keys.

```ts
const decode = createJsonDecoderFn<Record<string, string>>();
decode('{"__proto__":{"admin":true}}'); // throws [mion] Unsafe property name: __proto__
```

As a declared property it is dropped, like any property that cannot cross the wire, and the rest of the type still works.

TypeScript accepts the declaration, so mion warns about it: the type promises a value that does not exist at runtime.

```ts
interface Settings {ok: number; __proto__: string}
const value: Settings = {ok: 1, __proto__: 'x'}; // compiles
Object.keys(value); // ['ok']
```

`prototype` and `constructor` are ordinary names. A record can carry them as keys, and a type can declare them:

```ts
const decode = createJsonDecoderFn<Record<string, string>>();
decode('{"constructor":"builder","prototype":"draft"}'); // both keys, as written
```

## Build-Time Trust

The generated functions are built from text at startup, produced by the compiler and read from its disk cache under `node_modules/.cache/mion`. That cache is as trusted as `node_modules` itself: whoever can write there can change what your build runs, cache or no cache. Keep it out of any location an untrusted process can write.
