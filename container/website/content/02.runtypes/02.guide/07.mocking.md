## Generating Mock Data

Mock generation has its own import, so an app that never uses it ships none of it. Change the type and the mocks follow, with no fixture to update.

```ts
import {createMockDataFn} from '@mionjs/run-types/mocking';
```

<code-import path="packages/examples/src/guide/mocking-basics.ts" lang="ts" commentStart="// start-basics" commentEnd="// end-basics" />

::note
`createMockDataFn` needs the Vite plugin running to read your type, and throws a clear error without it. Use it in tests and seed scripts, not in shipped runtime code.
::

## Mock Options

Pass a `mock` options bag to shape the generated values: number ranges, string lengths, how often optionals show up, and more.

<code-import path="packages/examples/src/guide/mocking-options.ts" lang="ts" commentStart="// start-options" commentEnd="// end-options" />

| Group | Option | What it does |
| --- | --- | --- |
| Ranges and lengths | `minNumber` / `maxNumber` | Inclusive bounds for generated numbers and bigints. |
| Ranges and lengths | `stringLength` / `maxRandomStringLength` | Force, or cap, generated string length. |
| Ranges and lengths | `stringCharSet` | The character set strings are built from. |
| Ranges and lengths | `arrayLength` / `maxRandomItemsLength` | Force, or cap, array, `Map`, `Set` and record sizes. |
| Ranges and lengths | `minDate` / `maxDate` | Inclusive bounds for generated dates (a timestamp or a `Date`). |
| Pools and pins | `anyValuesList` | The pool the `any` and `unknown` kinds draw from. |
| Pools and pins | `objectList` | The pool the plain `object` kind draws from. |
| Pools and pins | `regexpList` | The pool the `RegExp` kind draws from when `nonDataTypes` is on (a RegExp is not data, so a plain mock leaves it out). |
| Pools and pins | `symbolName` / `symbolLength` / `symbolCharSet` | Fix a generated symbol's name, or its random length and character set. |
| Pools and pins | `unionIndex` / `enumIndex` | Pin a union member or enum branch instead of picking at random. |
| Optionality and recursion | `optionalProbability` | Chance from 0 to 1 that an optional property is included. |
| Optionality and recursion | `optionalPropertyProbability` | Per-property override of that chance, keyed by property name. |
| Optionality and recursion | `maxMockRecursion` | How far a recursive type is followed before it bottoms out. |
| Promises | `promiseTimeOut` | Delay in milliseconds before a mocked `Promise` resolves (0 resolves immediately). |
| Promises | `promiseReject` | When set, the mocked `Promise` rejects with this value instead of resolving. |
| Advanced | `nonDataTypes` | Also generate the non-data members (functions, methods, symbols, non-serializable natives) a mock normally leaves out. Off by default. |
| Advanced | `tupleOptions` / `paramsOptions` | Per-slot options for a tuple's elements. `paramsOptions` is an alias that also covers a function's `Parameters<typeof fn>`, so each argument gets its own options. |
| Advanced | `respectBinarySize` / `binarySizingOptions` | Make a value fit, or exceed, the binary encoder's cold-start size estimate. |
| Advanced | `seed` | Fix the random source so the same seed always produces the same value. See [Seeded Data](#seeding-data). |

For realistic values (real names, your own domains, sensible ranges), use the `data` enrichment map on the [MockData](/runtypes/ai-integration/mock-data) page.

## Seeding Data

By default every call returns fresh random data. Pass a `seed` and the same seed always produces the same value, for every type.

<code-import path="packages/examples/src/guide/mocking-options.ts" lang="ts" commentStart="// start-seed" commentEnd="// end-seed" />

Time-based values (`Date`, Temporal, and uuid v7) are reproducible under a seed too. They are anchored to a fixed reference instant instead of the clock, so they still vary but stay the same on every run.

Write the seed as a literal where the mock is created (`createMockDataFn<T>(undefined, {mock: {seed: 42}})`) and the build reads it too. It generates the value pools for any [pattern](/runtypes/guide/type-formats) fields that declare no mockSamples, so pattern mocks stay identical across rebuilds. Without a literal seed those pools are drawn fresh on every build (a computed seed, or one passed per call, still makes the picks repeatable within a build).

## Generating Invalid Data

Set `invalid: true` and the generator returns a value that FAILS validation. It builds a valid value first, then replaces one field with a value of the wrong type. Use it to test your validators, decoders and error handling, with no broken fixtures to write by hand.

<code-import path="packages/examples/src/guide/mocking-invalid.ts" lang="ts" commentStart="// start-invalid" commentEnd="// end-invalid" />

`invalidLeafProbability` (0 to 1) sets how deep the bad value lands. Every position is a candidate: the whole value, any nested object or array, and every leaf field. Near the default of 0.85 it breaks a single deep field, so only one thing is wrong. Lower it and the break moves outward, to an intermediate object or array, or the whole value. At 0 it always replaces the whole value, at 1 it always breaks a leaf.

## Format-Aware Mocks

If your type uses [type formats](/runtypes/guide/type-formats), the mock respects them. An `email` field gets a real-looking address, not random characters.

<code-import path="packages/examples/src/guide/mocking-formats.ts" lang="ts" commentStart="// start-formats" commentEnd="// end-formats" />

A mock always passes the type's own validator, format checks included. When it cannot (for example every sample given for a custom pattern breaks the declared length bounds), the mock function throws a clear error naming the problem.

More format behaviour:

- A format restricted to a fixed set with `allowedValues` (the domain formats included) mocks from that set.
- A custom `pattern` mocks from its `mockSamples`. Declare none and the build generates the pool from the regex itself, so pattern fields mock out of the box.
- A format's declared `transform` (for example `TF.Lowercase`) is applied to the mock, so the mocked value is the clean one.
- Mock samples are not part of a type's identity: two formats that differ only in their samples share one compiled entry. Declaring two different sample pools for that one shape is a build error (FMT006).

The full list of formats and how each one mocks lives in [Type Formats](/runtypes/guide/type-formats).
