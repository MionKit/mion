## JSON Encoder Strategies

`createJsonEncoderFn` takes a `strategy`, a call-site literal, that decides how it walks your value and what it does with undeclared keys. The first three write the same keyed JSON, `compact` writes a smaller positional form.

<code-import path="packages/examples/src/guide/json-strategies.ts" lang="ts" commentStart="// start-strategies" commentEnd="// end-strategies" />

| Strategy | How it works | Mutates input? | Undeclared keys |
| --- | --- | --- | --- |
| `clone` _(default)_ | Builds a fresh, JSON-safe value from the declared shape, then encodes that. Cloning every object costs a little more memory. | No | Dropped (for free) |
| `mutate` | Rewrites non-serializable leaves (`Date`, `BigInt`, …) in place, then encodes. Faster, with no allocation. | **Yes** | Kept on the wire |
| `direct` | Writes valid JSON in one pass. No clone, so it uses less memory than `clone`. | No | Dropped |
| `compact` | Like `clone`, but writes every object as an array of its declared properties, in order, with no key names. 40 to 60 percent fewer bytes on real objects. An absent optional property is written as `null`. | No | Dropped |

::tip
`clone` is the safe default. Use `mutate` only where the allocation shows up in a profile and you are fine with your input changing. Use `compact` when both ends share the type and the bytes matter, like a mion route.
::

## Custom Class Serializers

Plain objects and the built-in classes (`Date`, `Map`, `Set`) round trip for free. A `RegExp` does not: a pattern is code, not data, so a `RegExp` property is dropped like a function. Your own class sends only its data and comes back as a plain object, so register it with `registerClassSerializer` to get a real instance back.

<code-import path="packages/examples/src/guide/custom-class-serializer.ts" lang="ts" />

Both halves are optional:

- `serialize` defaults to the same encoding an interface of that shape gets. Provide it only for a different wire shape (on the JSON path, keep it to the declared properties).
- `deserialize` defaults to `new YourClass()` plus the decoded properties, so a class with a zero-argument constructor needs only the class. A constructor that takes arguments needs a `deserialize`: the type checker asks for it, and if `new YourClass()` fails, decode throws a `CLS002` error.

::note
Register before anything serializes the class. One registration covers JSON and [binary](/runtypes/guide/binary-serialization) alike. `createValidateFn` always checks a class by its structural shape and never goes through the serializer.
::

## Rebuilding the Right Class

One registration covers every instantiation of a generic class: `RpcError` rebuilds both `RpcError<'a'>` and `RpcError<'b', Data>`. Registering the same class again updates its handlers and never drops an instantiation that worked before.

A union picks each member by the actual instance, so a `Circle | Square` field comes back as the right class even when both have identical fields. A plain object in the same union (`Money | {amount: number}`) stays a plain object.

A subclass is a class of its own. Declare it next to its base (`AuthError | RpcError`) and register it: it keeps every field it declares and comes back as an `AuthError`, in any member order. Left unregistered, it takes its own member by shape and comes back as a plain object. Passing a subclass to an encoder built for the base alone is a type error.

## Serializing Errors

Classes extending Error always serialize `name` and `message`. The optional `stack` and `cause` are sent only when they are enumerable own properties (the same test `JSON.stringify` applies), so a stack trace never leaks by default. To send one, make it enumerable: `Object.defineProperty(err, 'stack', {value: err.stack, enumerable: true})`.

A `@nonEnumerable` JSDoc tag adds the same guard to your own property. It works only on an optional property: a required one still serializes, and a lint rule tells you.

## Detecting Circular References

To stay fast, an encoder does not track the objects it has seen, so a value that points back at itself (`a.next = a`) recurses until the stack overflows. Set `rejectCircularRefs` on `createJsonEncoderFn` and that encoder throws a `CircularReferenceError` with the path to the cycle instead.

Decoders need no guard: a serialized payload cannot contain a runtime cycle. The option is off by default.

## Parsing and Validating in One Step

A decoder trusts its input. For JSON you do not control, `createParseFn<T>()` restores the value, checks it and collects the errors in one call.

<code-import path="packages/examples/src/guide/parse-basics.ts" lang="ts" />

A match comes back typed, with dates and bigints as real values. Anything else throws `RTParseError`, never another error, however malformed. `isSerializationError` tells a failed check from a value that could not be decoded at all.

A value is rebuilt only from the form the encoder writes: a `Date` or a `bigint` from its string, a `Map` or a `Set` from its array. Anything else is left for the check to refuse, so a `null` never turns into an epoch date and a `true` never turns into `1n`. The plain decoders follow the same rule, and [Decoding Untrusted Input](/runtypes/guide/decoding-untrusted-input) has the details.

`strategy` decides what happens to undeclared properties. Set `parse: {strategy: 'strip'}` in the plugin options to change the default for every parser; a per-call `strategy` still wins.

| Strategy | Undeclared properties |
| --- | --- |
| `preserve` (default) | Kept. The cheapest option: no extra pass, no key check. |
| `strip` | Set to `undefined`, at every level. Safer for a payload you will store or forward. |
| `fail` | Rejected, anywhere in the value, like `checkUnknowns` on a validator. |

Use `createJsonDecoderFn<T>()` for data you already trust, and `createValidateFn<T>()` for a value in hand rather than a wire payload.

## Decoders Return Data Only

`createJsonDecoderFn<T>()` and `createBinaryDecoderFn<T>()` return `DataOnly<T>`, not `T`. A decoded value holds only serializable data, so the type leaves out what cannot be sent, like methods. Only the type changes, nothing at runtime.

<code-import path="packages/examples/src/guide/json-dataonly.ts" lang="ts" commentStart="// start-dataonly" commentEnd="// end-dataonly" />

A property guarded by enumerability (anything optional inherited from Error, or one tagged `@nonEnumerable`) is always optional in `DataOnly<T>`, because the wire might omit it.

## Why Only Serializable Data

Validation and both codecs use only the serializable part of your type. Functions, methods and symbols are dropped, so a validator for `{name: string; onClick: () => void}` checks only `name`.

The build shows a `VL010`-family **Warning**, and a warning never stops anything. Where the drop would throw at runtime, like a union member or array element, it is a **RuntimeError**: the function is still written but throws when called, and the build fails (see [Diagnostics](/runtypes/diagnostics/error-levels)). The reasoning is in [Built on typescript-go](/runtypes/introduction/built-on-typescript-go#extending-typescript-go-without-modifying-it).

## Encoding Values Without the JSON String

`createPrepareForJsonFn` turns a typed value into a JSON-safe value, and `createRestoreFromJsonFn` turns it back, with no string in between. Use them when your code owns the `JSON.stringify` and `JSON.parse` (a framework that parses one request body and stringifies one response), so many values share one envelope.
