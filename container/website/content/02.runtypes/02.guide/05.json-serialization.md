The JSON functions write standard JSON text. Data only types, undeclared keys and input checks are covered on the [Serialization](/runtypes/guide/serialization) page.

## Encoding and Decoding JSON

`createJsonEncoderFn<T>()` returns a function that writes a value as a JSON string. `createJsonDecoderFn<T>()` returns one that reads that string back into your type.

::tip
The encoder returns `string | undefined`, because `undefined` has no JSON text, as with `JSON.stringify`. Invalid JSON makes the decoder throw the `SyntaxError` from `JSON.parse`.
::

## Encoder Strategies

The `strategy` option picks how the encoder walks your value. Pass options as an object literal: the build reads them, and a variable falls back to the default.

<code-import path="packages/examples/src/guide/ser-json-strategies.ts" lang="ts" commentStart="// start-encoder-strategies" commentEnd="// end-encoder-strategies" />

| Strategy | Changes your value | Undeclared keys | Output | How it works |
| --- | --- | --- | --- | --- |
| `clone` (default) | No | Left out | Keyed JSON | Builds a new value from the type, then calls `JSON.stringify` |
| `mutate` | Yes | Written | Keyed JSON | Converts values in place, no copy, then calls `JSON.stringify` |
| `direct` | No | Left out | Keyed JSON | Writes the string in one pass with no copy, slower on larger types |
| `compact` | No | Left out | Arrays, no key names | Builds a new array per object, needs the [compact decoder](#compact-wire) |

::tip
Keep `clone` unless you have a reason to change it. Use `mutate` only on a value you throw away after encoding, and `compact` when both ends share the type and payload size matters.
::

## Decoder Strategies

The decoder's `strategy` option decides what happens to keys your type does not declare.

<code-import path="packages/examples/src/guide/ser-json-strategies.ts" lang="ts" commentStart="// start-decoder-strategies" commentEnd="// end-decoder-strategies" />

| Strategy | Undeclared keys | Reads |
| --- | --- | --- |
| `strip` (default) | Kept as keys, with the value set to `undefined` | Keyed JSON |
| `preserve` | Kept with their values | Keyed JSON |
| `compact` | Never present, values are read by position | Arrays from the compact encoder |

::tip
Setting a value to `undefined` is cheaper than deleting the key, and `JSON.stringify` skips `undefined` values, so those keys never reach the wire again.
::

## JSON Wire Format

Values JSON has no form for are written in the spellings below. `JSONShape<T>` is the TypeScript type of the written JSON.

<code-import path="packages/examples/src/guide/ser-json-wire.ts" lang="ts" commentStart="// start-wire" commentEnd="// end-wire" />

| Value | Written as |
| --- | --- |
| bigint | A string of decimal digits |
| Date | An ISO 8601 string |
| Temporal types | Their standard string |
| Map | An array of `[key, value]` pairs |
| Set | An array of its values |
| A union with a member that needs converting, such as `string \| Date` | `[member index, value]` |
| `undefined` in a tuple | `null` |
| `NaN` and `Infinity` | `null`, as `JSON.stringify` writes them |
| An absent optional property | Left out |

::note
Unions of plain JSON values, such as `string | number` or objects with no converted members, are written as is. A client that does not use RunTypes sees the `[member index, value]` form, so keep other unions out of JSON that such clients read.
::

## Undeclared Keys in Parse

The `strategy` option decides what parse does with keys your type does not declare.

<code-import path="packages/examples/src/guide/ser-json-parse.ts" lang="ts" commentStart="// start-parse-strategy" commentEnd="// end-parse-strategy" />

| Strategy | Undeclared keys |
| --- | --- |
| `preserve` (default) | Kept |
| `strip` | Set to `undefined` at every depth, before the value is restored |
| `fail` | Rejected with `RTParseError`, checked against the union member that matched |

::tip
Use `strip` or `fail` for a body you store or forward.
::

## Parse Errors

`RTParseError.issues` holds one of two failures, and `isSerializationError()` tells them apart.

<code-import path="packages/examples/src/guide/ser-json-parse.ts" lang="ts" commentStart="// start-parse-errors" commentEnd="// end-parse-errors" />

| Failure | `issues` | `cause` |
| --- | --- | --- |
| The value restored but does not match the type | The list `createGetValidationErrorsFn<T>()` returns | `undefined` |
| Restoring failed, for example on a bad union value or a `__proto__` key, or the value is nested too deep | `{deserializeError: string}` | The original error |

::tip
The error message names the first failing path and counts the rest, for example `parse failed at id: expected number (+1 more)`.
::

## Class Serializers

A class instance is encoded by its declared properties and decoded as a plain object. Register the class with `registerClassSerializer()` from `@mionjs/run-types/runtime` to get a real instance back.

<code-import path="packages/examples/src/guide/ser-class.ts" lang="ts" commentStart="// start-class" commentEnd="// end-class" />

| Class | What to register |
| --- | --- |
| Constructor with no arguments | The class alone: the decoder calls `new` and sets the declared properties. If `new` throws, decoding fails with a `CLS002` error |
| Constructor with arguments | A `deserialize` handler that builds the instance from its data |
| Custom wire shape | A `serialize` handler, returning an object with the declared property names |

::tip
Register once at startup, before the first decode. The registration also applies to parse and to the binary functions. Validators always check a class by its shape and never call the serializer.
::

## Rebuilding the Right Class

One registration covers every instantiation of a generic class: `RpcError` rebuilds both `RpcError<'a'>` and `RpcError<'b', Data>`. Registering the same class again updates its handlers.

| Declared type | What comes back |
| --- | --- |
| A union of classes, such as `Circle \| Square` | The class of the actual instance, even when both have the same fields |
| A class and a plain object, such as `Money \| {amount: number}` | The plain object stays a plain object |
| A registered subclass next to its base, such as `AuthError \| RpcError` | An `AuthError` with every field it declares, in any member order |
| An unregistered subclass | A plain object, matched by shape |

::tip
Passing a subclass to an encoder built for the base class alone is a type error. Declare the subclass in the union.
::

## Circular References

::

## Value-Level JSON Functions

These functions skip the string step, so one `JSON.stringify` call can hold many typed values inside your own envelope.

<code-import path="packages/examples/src/guide/ser-json-value-level.ts" lang="ts" commentStart="// start-value-level" commentEnd="// end-value-level" />

| Function | What it does |
| --- | --- |
| `createPrepareForJsonFn<T>()` | Converts a typed value into a JSON-safe value |
| `createRestoreFromJsonFn<T>()` | Restores a `JSON.parse` value, with no checks |
| `createStringifyJsonFn<T>()` | Writes one value as a JSON string in a single pass, leaving out undeclared keys |
| `createStripUnknownKeysFn<T>()` | Sets the undeclared keys of a `JSON.parse` value to `undefined` |

::tip
Prepare and restore take the `clone` (default), `mutate` or `compact` strategy. Use the same strategy on both sides.
::
