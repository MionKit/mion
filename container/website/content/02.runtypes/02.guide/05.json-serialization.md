`createJsonEncoderFn<T>()` returns a function that turns a value into a JSON string. `createJsonDecoderFn<T>()` returns a function that turns the string back into your type.

<code-import path="packages/examples/src/guide/serialization-overview.ts" lang="ts" commentStart="// start-json" commentEnd="// end-json" />

::note
The JSON serialization functions only emit the code strictly needed to encode and decode what JSON does not support directly, like `Date`, `bigint`, `Map` or unions. When no custom logic is needed, no code is emitted and the function is marked `isNoop` (no operation).
::

## What the JSON Looks Like

Types that JSON supports stay as they are. The others become strings or arrays, and the decoder converts them back.

<code-import path="packages/examples/src/guide/json-wire-format.ts" lang="ts" commentStart="// start-types" commentEnd="// end-types" />

- A missing optional property stays missing.
- `undefined` in an array or tuple becomes `null`, so the positions stay the same.
- `NaN`, `Infinity` and `-Infinity` become `null`, as with `JSON.stringify`.

## Unions

A union whose members are all plain JSON (strings, numbers, booleans, `null`) stays as it is. When a member needs converting, like a `Date` or a `bigint`, the value is written as `[index, value]`. The index tells the decoder which member to rebuild.

<code-import path="packages/examples/src/guide/json-wire-format.ts" lang="ts" commentStart="// start-unions" commentEnd="// end-unions" />

::tip
Only a RunTypes decoder for the same type can read the index. If another tool reads your JSON, keep union members to plain JSON values.
::

## JSON Strategies

The `strategy` option sets what happens to properties your type does not declare. Use the same one on the encoder and the decoder.

<code-import path="packages/examples/src/guide/json-strategies.ts" lang="ts" commentStart="// start-strategies" commentEnd="// end-strategies" />

| Strategy | Undeclared properties | Changes your value |
|---|---|---|
| `clone` (default) | dropped | no, builds a new value |
| `mutate` | kept | yes, converted in place |
| `compact` | dropped, and property names are not written | no |

::note
With `mutate`, an undeclared property goes to `JSON.stringify` untouched. An undeclared `bigint` makes it throw.
::

With `rejectCircularRefs: true`, the encoder throws a `CircularReferenceError` on a value that points back to itself.

Decoders do not validate. Check the result with `createValidateFn<T>()` when the JSON comes from outside your app.

::note
Write the options as a literal object in the call. A variable falls back to the default strategy.
::

## Compact JSON

The `compact` strategy writes each object as an array of its values, in the order your type declares them. `{name: 'pen', price: 5n}` becomes `["pen","5"]`. The output is smaller.

- Encode and decode with `compact` on both sides, and the same type.
- A missing optional property is written as `null`. So for an optional property typed `T | null`, a `null` value and a missing value both decode to `undefined`.

## Encode Values Inside Your Own JSON

Use the value functions to put several typed values in one JSON document. They convert values but leave `JSON.stringify` and `JSON.parse` to you.

<code-import path="packages/examples/src/guide/json-value-level.ts" lang="ts" />

| Function | What it does |
|---|---|
| `createPrepareForJsonFn<T>()` | converts a typed value to a value `JSON.stringify` can write |
| `createRestoreFromJsonFn<T>()` | converts a parsed value back to your type |

Both functions take the same `strategy` option.
