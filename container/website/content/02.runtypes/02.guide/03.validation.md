Every `createX<T>()` factory turns a type into a function the build writes for you, with no schema object and no runtime reflection. This page covers **validation**: the type guards, the error reports and unknown-key handling. [JSON round trip](/runtypes/guide/json-round-trip), [mocking](/runtypes/guide/mocking) and [reflection](/runtypes/guide/reflection) have their own pages.

::note
**Validators check serializable data.** `createValidateFn`, `createGetValidationErrorsFn` and the JSON codecs work on `DataOnly<T>`, the JSON-shaped part of your value. Functions, methods, getters, symbols, promises, `RegExp` values and built-ins with no JSON form, such as `URL` or a typed array, are skipped. The build names each one in an Info message, shown with `levels: 'all'`. If the root type is not serializable, the generated function throws and the build reports a RuntimeError. Decoders also return `DataOnly<T>`, not the full type.
::

## Types from Other Libraries

`any` and `unknown` count as data, so types from other libraries keep working. The validator accepts any value there, and a required property only has to be present.

When the whole type is `any` or `unknown`, the build adds an Info message. An `any` from a name or an import that did not resolve is a RuntimeError instead.

## Validation Errors

Same checks, but you get an array of what failed instead of a boolean. Each entry is `{path, expected}`, and a format failure adds a `format` detail.

<code-import path="packages/private-examples/src/guide/validation-basics.ts" lang="ts" commentStart="// start-errors" commentEnd="// end-errors" />

### Format Error Types

Some formats fail in more than one way, and set an `errorType` on the `format` detail naming the mode. The modes are stable strings, exported as union types from the formats subpath (`CreditCardErrorType`, `EmailErrorType`, `DomainErrorType`, `IpErrorType`).

```ts
const errors = getErrors(card);
switch (errors[0]?.format?.errorType) {
  case 'format': // not shaped like a card number at all
  case 'checksum': // right shape, the digits do not add up (a typo)
  case 'network': // a good card, just not one this field takes
}
```

| Format | Modes | When |
| --- | --- | --- |
| `CreditCard` | `format`, `checksum`, `network` | `network` only when the field sets `networks` |
| `EmailAddress`, `IdnEmail` | `format`, `localPart`, `domain`, `addressLiteral`, `length` | which part of the address is wrong (`format` means no `@` at all) |
| `EmailParts` | `format`, `localPart` | the domain half reports under the `domain` format with its own modes |
| `Hostname`, `IdnHostname` | `label`, `punycode`, `bidi`, `length` | which rule the name broke |
| `DomainParts` | `label`, `tld` | which label failed |
| `IPv4WithPort`, `IPv6WithPort`, `IPWithPort` | `address`, `port` | only the port-accepting presets |

::tip
Every format not in the table (`Url`, `UUIDv4`, the plain `Email` and `Domain` presets, the number and date formats) has one failure mode and leaves `errorType` unset. Each of its constraints reports its own error, and the `formatPath` on it says which one. In every format, a bound on the whole value (like `maxParts` on `DomainParts`) also leaves `errorType` unset.
::

## Validation Options

Both validators take an options object as a second argument.

<code-import path="packages/private-examples/src/guide/validation-options.ts" lang="ts" commentStart="// start-options" commentEnd="// end-options" />

| Option | What it does |
| --- | --- |
| `numberMode` | Chooses how a `number` is checked. `isFinite` (the default) rejects `NaN` and `Infinity`; `typeof` accepts them (matching ajv, typia, and JSON Schema); `notNaN` rejects `NaN` but keeps `Infinity`. |
| `checkUnknowns` | Rejects a property your type does not declare, anywhere in the value. See [Checking for Unknown Keys](#checking-for-unknown-keys). |
| `checkUnionUnknowns` | Rejects an undeclared property on a union member only. See [Unions](#unions). |
| `rejectCircularRefs` | Rejects a value that contains a reference cycle. The errors form reports it as `{expected: 'circular'}`. |

::warning
Pass the options as an **object literal**, or a `const` declared `as const`. They are read at build time, so a value made at runtime is reported as an error.
::

### A Project-Wide Number Mode

Set `numberMode` once under a `validate` object in the plugin (or the tsconfig `mion` plugin entry) and every validator uses it.

```ts
runtypes({validate: {numberMode: 'typeof'}})
```

::tip
A per-call `numberMode` wins over the project default for that validator, so `numberMode: 'isFinite'` at a call opts it back out.
::

### Unions

A union needs its own option: its members share one list of property names, and a member with an index signature declares every property. `checkUnionUnknowns` checks the property list of the member that actually matched. It does nothing outside a union, so pair it with a decoder that already dropped the rest.

```ts
type Pet = {kind: 'cat'; meows: boolean} | {kind: 'dog'; barks: number};
// {kind: 'cat', meows: true, barks: 3}  ->  rejected, barks belongs to Dog, not to Cat

type Something = {a: string} | Record<string, number>;
// {a: 'x', evil: 'garbage'}  ->  rejected, it matches neither member

type Loose = {a: string} | Record<string, string>;
// {a: 'x', evil: 'garbage'}  ->  accepted, every value is a string
```

::tip
The check runs only when the union has two or more members that carry properties by name, so `{a: string} | number` answers as plain `validate` does. Set both options and `checkUnknowns` wins.
::

## Removing Unknown Keys

`checkUnknowns` rejects extra keys, `createRemoveUnknownKeysFn` drops them. The copy keeps every member your type declares, or the build fails.

<code-import path="packages/private-examples/src/guide/remove-unknown-keys.ts" lang="ts" />

| Declared member | On the copy |
| --- | --- |
| Data, Dates, Maps and Sets | A new copy |
| Class instance | A new object with the same prototype. The constructor does not run. |
| Class method or getter | Still works, from the prototype |
| Function, Promise, RegExp or a built-in like `Int8Array` | The same value as the input, with a warning |
| Symbol-keyed property, or a class with `#private` fields | Build error, the function always throws |
