A marker is a type you add to a function parameter, almost always the last one. You write the type, the build fills in the value, then the marker is erased. Every `createX` factory uses one, and you can use the same markers in your own helpers.

## List of Compiler Markers

::card-group
---
class: sm:grid-cols-2 rt-markers
---
:::card
---
title: Factory injection
---
```ts
id?: InjectTypeFnArgs<T, Fn>
```
Validates the call site's compile-time arguments, then injects the generated functions you asked for. Every `createX` declares it, and so can your own wrappers.
:::

:::card
---
title: Reflection id
---
```ts
id?: InjectRunTypeId<T>
```
Injects a short, stable id for `T` at each call site. The marker you are most likely to type, for wrapping your own helpers.
:::

:::card
---
title: Compile-time literals
---
```ts
options: CompTimeArgs<T>
```
Brands a parameter as "must be a literal at the call site" (or a `const` of literals). Static check only.
:::

:::card
---
title: Variant selection
---
```ts
options: CompTimeFnArgs<T>
```
Like `CompTimeArgs`, but the literal also selects which variant of a factory you get, such as the JSON encoder strategy. Static check only.
:::

:::card
---
title: Pure functions
---
```ts
fn: PureFunction<F>
```
Brands a pure function argument that passes the purity rules. The direct form: the argument is the helper itself. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
---
title: Pure function factories
---
```ts
fn: PureFunctionFactory<F>
```
The factory form of the above, for a helper that needs one-time setup or composes another pure fn. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
---
title: Pure function id
---
```ts
id?: InjectPureFnId<F>
```
Injects a pure helper's id (where it lives), so a library can wrap the registrar. See [pure functions](/runtypes/guide/pure-functions).
:::

:::card
Seven markers in total. The factories and registrars already declare them, so you type one only in a helper that wraps them.
:::
::
