## Pure Function Rules

A helper must be self-contained: no outer-scope captures, no `this`, no `await` or `yield`, and no dynamic `import`. Anything it needs goes inside the function. Break a rule and the build reports an error.

Standard built-ins are allowed: `Math`, `JSON`, the binary toolbox (`ArrayBuffer`, `DataView`, typed arrays like `Uint8Array`, `TextEncoder`, `TextDecoder`, `btoa` and `atob`), which is enough for a hash, a binary codec or a text-encoding routine. I/O and async are not, because the helper is inlined into synchronous code: no `fetch` or network, no timers, no `process` or `globalThis`, and nothing that must be awaited. That is why `crypto.subtle.digest` does not fit (implement the hash over the typed arrays instead), while a synchronous call like `crypto.randomUUID` is fine.

Write the helper inline, right where you register it: a name anything else could reach is rejected.

```ts
// Rejected: a name something else could reach
import {validate} from './validators';        // imported
export const validate = (v) => /* … */ true;  // exported
const validate = (v) => /* … */ true;         // a named local binding
registerValidator(validate);

// Fine: inline at the call site
registerValidator((v: unknown) => typeof v === 'string');
```

## Publishing Pure Functions in a Package

A pure function registered in one package can be used from another, like any export. Build the package with a mion bundler plugin or with `mion compile`, and the build adds one directory next to the bundle, published with the rest of dist:

```
dist/
  index.js
  index.d.ts
  mion-pure-fns/
    index.json                     # maps every exported name to its id
    @acme/text/9Zt1bRm4cVaPqL.js   # one compiled file per pure function
    @acme/text/Q2xVn7eK0sLmYb.js
```

With `mion compile`, put the gen dir inside the output dir, for example `--gen-dir dist/.mion`, so it ships with the compiled files that import it.

A consuming build reads only the functions it uses from that directory and compiles them into its own output, registering each one before anything calls it. A package built without mion ships no such directory, so importing one of its ids fails the consuming build with `PFE9016`, which names the id and the package: build the package with mion, or publish its TypeScript sources with its output, and the build reads those instead.

::tip
The directory is build-time input only: nothing imports it at runtime, so it adds nothing to any bundle. Its files are the same compiled modules your own build uses.
::

## Looking Up a Pure Function at Runtime

`usePureFn` and the other tracked lookups need an id the build can read. When the id only exists at runtime, for example one that arrives in a request, use the untracked accessor instead:

```ts
import {getRTUtils} from '@mionjs/run-types';

// `wireId` came in over the network, so it is a plain runtime string.
const fn = getRTUtils().getPureFnByKey(wireId);
if (getRTUtils().hasPureFnByKey(wireId)) {
  // dispatch on it
}
```

`getPureFnByKey` and `hasPureFnByKey` take a plain string and are not build-tracked. Use them for framework dispatch on a runtime id, and keep `usePureFn` for the references you want the build to check.

## Sharing Compiled Functions Across Bundles

A validator or encoder that the build generates in one bundle can run in another. A server sends the functions for its types to a browser client, and the client rebuilds and runs them without ever running the compiler. mion's router works this way on the path from server to client.

On the sending side you serialize the closure-free form of an entry, its `CompiledFnData`, whose `code` field carries the function body as text. On the receiving side you restore the factory from that text with `buildFactoryFromCode`, write it back into the runtime cache with `addToRTCache`, then look it up by its hash and call it.

```ts
import {getRTUtils, buildFactoryFromCode, type CompiledFnData, type CompiledTypeFn} from '@mionjs/run-types';

// `wire` arrived over the network as plain data.
function ingest(wire: CompiledFnData) {
  const restored: CompiledTypeFn = {...wire, createRTFn: buildFactoryFromCode(wire.code!)};
  getRTUtils().addToRTCache(restored);
}

// Later, on the client, look one up by its hash and call it.
const isUser = getRTUtils().getRTFn(rtFnHash);
```

Pure functions travel the same way, with `buildPureFnFactoryFromCode` and `addPureFn` in place of the two type-function helpers. Which entries a payload depends on, and how you version the envelope you send them in, stay your framework's call.

## Overriding Generated Functions

The `overrideX` helpers register your own pure function for one type, and every matching `createX` call returns it instead of the generated body. Use one for a hand-tuned encoder, a wire format that is not the plain shape of your type, or a workaround for a one-off bug.

```ts
import {overrideJsonEncoder, createJsonEncoderFn} from '@mionjs/run-types';

// Declared once, near the type. The function must be pure, same rules as above.
overrideJsonEncoder<User>((user) => `{"id":${user.id}}`);

// Anywhere else, nothing changes at the call site:
const encode = createJsonEncoderFn<User>();
```

Every factory has an override twin (`overrideValidate`, `overrideJsonEncoder`, `overrideBinaryEncoder`, and so on). Your function has to match the signature the family uses internally, so a validation-errors override receives the value, the path, and the errors list, exactly like the generated one.

An override applies to its type everywhere the type appears, so an override on a field type reaches every object that contains that field. You can register exactly one override per type and function, and a second one (with any body) is a build error. Decoders use validation to tell union branches apart, so a looser validator makes those decoders looser as well, and the build warns you when that happens.

## Limiting an Override to One Type

An override is matched by the **shape** of the type, not its name, so `overrideValidate<string>` applies to every string in the build, including string fields inside other objects. Give the type a brand when you mean one specific type.

```ts
type UserId = string & {readonly __brand: 'UserId'};

// Only UserId, not every string.
overrideValidate<UserId>((v) => typeof v === 'string' && (v as string).startsWith('u_'));
```
