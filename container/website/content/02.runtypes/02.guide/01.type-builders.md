## Types vs Type Builders

Same shape, two spellings: `isProductA` and `isProductB` are identical validators. A builder returns a run-type, a value you can store, pass to a function or build up piece by piece.

## Labeled Tuples and Named Parameters

A tuple label like `[x: number, y: number]` is part of the type. To write one with builders, wrap each element in `RT.slot(name, runType)`.

<code-import path="packages/examples/src/guide/type-builders-labeled.ts" lang="ts" />

| Builder | Group | Holds |
| --- | --- | --- |
| `RT.tuple` | `required` | The elements that always appear |
| `RT.tuple` | `optional` | The trailing elements that may be left out |
| `RT.tuple` | `rest` | A single element type that repeats |
| `RT.func` | `params` | The parameters |
| `RT.func` | `ret` | The return type |

::tip
Use slots on every element or on none, as TypeScript requires for tuple labels. Without slots you get unlabeled tuples and unnamed parameters.
::

## Recursive Shapes

A shape can contain itself, like a comment with replies. Wrap the body in `RT.circular` and point back at it with `RT.self()`.

<code-import path="packages/examples/src/guide/type-builders-recursive.ts" lang="ts" />

| Limit | What happens |
| --- | --- |
| `RT.self()` more than 24 levels deep in the body | The inferred type keeps `RT.self()` instead of your shape |
| The shape points back straight from a tuple slot, like `[number, Pair]` | Builders cannot write it. Put the loop behind an object, array, Map, Set or function, or write the shape as a type |
| A value nested deeper than the call stack | Validation throws `RangeError`. See [Checks on Incoming Data](/runtypes/guide/serialization#checks-on-incoming-data) |

::tip
For two shapes that point at each other, write `RT.self()` for the shape itself and name the other one by its const.
::

## Reusing Shared Fields Across Builders

Keep shared fields in one object and spread it into each builder that needs them. The spread is read at build time, so every run-type keeps its full, exact type.

```ts
import * as RT from '@mionjs/run-types/builders';
import * as TF from '@mionjs/run-types/formats';

const base = {id: TF.number(), createdAt: TF.number()};

const User = RT.object({...base, name: TF.string()});      // {id, createdAt, name}
const Post = RT.object({...base, published: RT.boolean()}); // {id, createdAt, published}
```

::tip
Spread a `const`, written inline or imported from another module. Spreading a value made at runtime, like a function call's result, is reported as an error.
::

## Reusing Option Presets

A `createValidateFn` or `createJsonEncoderFn` call can spread a preset of options and override keys inline. A key written after the spread wins.

```ts
import {createJsonEncoderFn} from '@mionjs/run-types';

const preset = {strategy: 'mutate'} as const;

const encodePost = createJsonEncoderFn<Post>(undefined, {...preset});
```
