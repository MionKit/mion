A plain type is the fast path: nothing to write but the type you already have. A builder returns a run-type, a value you can store, pass to a function, or build up piece by piece.

## Inferring the Type from a Builder

A run-type is a value. `InferType<typeof runType>` gives you back the TypeScript type it stands for.

<code-import path="packages/examples/src/guide/type-builders-static.ts" lang="ts" />

Start from a type and reflect it, or start from a run-type and infer the type. Either direction gives you one source of truth, so you never write a shape twice.

::tip
When other files only need the shape, export the type rather than the schema: a schema you only take the type of adds nothing to your bundle. Pass it to a create function, read its properties or export it, and its runtime description ships too.
::

## Labeled Tuples and Named Parameters

TypeScript lets a tuple name its slots (`[x: number, y: number]`) and those names are part of the type. To write them with builders, wrap each element in `RT.slot(name, runType)`.

<code-import path="packages/examples/src/guide/type-builders-labeled.ts" lang="ts" />

| Builder | Group | Holds |
| --- | --- | --- |
| `RT.tuple` | `required` | The elements that always appear |
| `RT.tuple` | `optional` | The trailing elements that may be left out |
| `RT.tuple` | `rest` | A single element type that repeats |
| `RT.func` | `params` | The parameters |
| `RT.func` | `ret` | The return type |

::tip
Slots go all in or not at all, TypeScript's own rule for tuple labels. Run-types without slots still mean unlabeled tuples and unnamed parameters.
::

## Recursive Shapes

A shape that holds more of itself, like a comment with replies. Wrap the body in `RT.circular` and write the loop back with `RT.self()`.

<code-import path="packages/examples/src/guide/type-builders-recursive.ts" lang="ts" />

| Limit | What happens |
| --- | --- |
| `RT.self()` nested more than 24 levels deep inside the body | The inferred type keeps the `RT.self()` placeholder instead of your shape |
| The loop points back straight from a tuple slot, like `[number, Pair]` | There is no builder spelling. Put the loop behind an object, array, Map, Set or function slot, or write the shape as a type |
| A value nested deeper than the call stack | Validation throws `RangeError`, see [decoding untrusted input](/runtypes/guide/decoding-untrusted-input) |

::tip
For two types that point at each other, each type writes its own loop back with `RT.self()` and names the other one by its const.
::

## Reusing Shared Fields Across Builders

Run-types are plain values, so you can keep a set of shared fields in one place and spread it into each builder that needs them. The merge happens at build time, so every run-type still reflects its full, exact type.

```ts
import {object, number, string, boolean} from '@mionjs/run-types';

const base = {id: number(), createdAt: number()};

const User = object({...base, name: string()});      // {id, createdAt, name}
const Post = object({...base, published: boolean()}); // {id, createdAt, published}
```

::tip
The fragment you spread has to be a `const`, written inline or imported from another module. A value produced at runtime, like the result of a function call, cannot be read at build time, so spreading one is reported as an error.
::

## Reusing Option Presets

A `createValidateFn` or `createJsonEncoderFn` call can spread a preset of options and override single keys inline. A key written after the spread wins.

```ts
import {createJsonEncoderFn} from '@mionjs/run-types';

const preset = {strategy: 'mutate'} as const;

const encodePost = createJsonEncoderFn<Post>(undefined, {...preset});
```
