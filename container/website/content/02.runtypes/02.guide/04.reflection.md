Reflection gives you your TypeScript types at runtime: a short, stable id for any type, or a RunType node you can walk. Validation, serialization and mocks read the same graph, and you can read it too. There is one node per type, tagged with a `kind` and linked to the inner types it holds.

## Getting a RunType Id

`getRunTypeId` returns a short, stable id for any type. The id is a fingerprint of the type's *shape*, so two types that look the same share one id. Use it as a cache key, a registry key or a discriminator.

## RunType Node Fields

Every node has a `kind`, one of the `RunTypeKind` values. The rest depends on that kind, but the edges that hold inner types are always one of these:

- `child` is the single inner type, like an array's element, a promise's value, or a property's type.
- `children` are the inner types of a container, like an object's properties, a union's members, or a tuple's slots.
- `parameters` and `return` are a function's argument nodes and its return node.

Members also carry `name` and `optional`, literals and enums carry `literal` and `values`, and a branded [TypeFormat](/runtypes/guide/type-formats) carries `formatAnnotation`.

On a node with a `formatAnnotation`, `name` is the canonical format name (`uuid`, `email`, `dateTime`) and its optional `params` holds that format's constraints. To map a format onto something outside RunTypes, a database column or a UI label, look the name up in `typeFormats`, the table of every built-in format name paired with the base kind it refines. `typeFormats` and the `FormatName` union of its names are importable from `@mionjs/run-types/runtime`.

Names come from your source, tuple element labels and function parameter names included. Two tuples with the same element types but different labels are distinct reflected types, each carrying its own labels.

::note
Builtin classes (Date, Map, Set, Temporal) stop at the class node: they carry a `subKind` and a name instead of walkable `children`, so a walk can treat them as leaves. Detect them by subKind (`node.subKind === RunTypeSubKind.date`), not by name, since one of your own classes could also be called Date. `RunTypeKind` and `RunTypeSubKind` are importable from the package root.
::

## RunType Node Kinds

A node's `kind` is always one of these, grouped by how you walk it:

```text
Atomic (leaves)    string  number  boolean  bigint  symbol  null  undefined  void
                   never  any  unknown  object  regexp  literal  templateLiteral  enum
Single child       array  promise  rest                      (read child)
Containers         tuple  union  intersection  objectLiteral  (read children)
Members            property  propertySignature  parameter  tupleMember  indexSignature
Callables          function  method  callSignature  methodSignature  (read parameters, return)
Class              class, covering Date / Map / Set / Temporal or a plain shape (read subKind)
Type level (rare)  typeParameter  infer  enumMember  ref
```
