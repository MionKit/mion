`createBinaryEncoderFn<T>()` returns a function that writes a value as bytes, in a `Uint8Array`. `createBinaryDecoderFn<T>()` returns a function that reads the bytes back into your type.

<code-import path="packages/examples/src/guide/binary-basics.ts" lang="ts" />

## Both Sides Need the Same Type

The bytes hold only values, never property names. The decoder knows what comes next from your type. So:

- Encode and decode with the same type. Bytes written with one version of a type do not decode with another.
- Properties your type does not declare are never written.
- Only RunTypes can read the bytes. For clients you do not control, use JSON.

## How Values Are Written

| Type | Bytes |
|---|---|
| `boolean`, `null`, `undefined` | 1 |
| `number` | 8 (a 64-bit float, `NaN` and `Infinity` kept) |
| `string` | the length (1 byte up to 127 bytes of text), then the UTF-8 text |
| `bigint` | its decimal digits as a string |
| `Date` | 8 |
| Array, `Map`, `Set` | the count, then each item or entry |
| Object | the declared properties in order, with one bit per optional property to mark it present |
| Union | the member index (1 byte), then the value |
| `Temporal.Instant` | 12 |
| `Temporal.PlainTime` | 9 |
| `any`, `unknown`, `object` | a JSON string |

## Use Fewer Bytes for Numbers

A number format with integer bounds takes the smallest size that fits them. Your own bounds work too: an integer from 0 to 1000 takes 2 bytes.

<code-import path="packages/examples/src/guide/binary-number-formats.ts" lang="ts" />

| Format | Bytes |
|---|---|
| `TF.Int8`, `TF.UInt8` | 1 |
| `TF.Int16`, `TF.UInt16` | 2 |
| `TF.Int32`, `TF.UInt32` | 4 |
| `TF.BigInt64`, `TF.BigUInt64` | 8 |

A `bigint` needs both a `min` and a `max` inside the 64-bit range to take 8 bytes, otherwise it is written as a string. Other formats, like `TF.Email` or `TF.UUIDv4`, are written like their base type.

## Pick a Buffer Strategy

The `sizeStrategy` option sets how the encoder gets its buffer. Every strategy writes the same bytes.

<code-import path="packages/examples/src/guide/binary-size-strategies.ts" lang="ts" commentStart="// start-strategies" commentEnd="// end-strategies" />

| Strategy | Call | Buffer size | When the value does not fit |
|---|---|---|---|
| `dynamic` (default) | `encode(value)` | guessed from the values encoded before | the buffer grows, rarely |
| `precalculate` | `encode(value)` | exact, measured first (the value is read twice) | cannot happen |
| `initialSize` | `encode(value, size)` | the size you pass | throws a `RangeError` |
| `intoBuffer` | `encode(value, arrayBuffer)` | your own `ArrayBuffer` | throws a `RangeError` |

::note
The encoder returns a view of its buffer, not a copy. With `intoBuffer` that buffer is yours, so the next call overwrites the bytes. Call `.slice()` on the result to keep a copy.
::

To get the exact size first, use `createBinarySizerFn<T>()`. It allocates no buffer.

<code-import path="packages/examples/src/guide/binary-size-strategies.ts" lang="ts" commentStart="// start-sizer" commentEnd="// end-sizer" />

The encoder also takes `rejectCircularRefs: true`, which throws a `CircularReferenceError` on a value that points back to itself.

## Handle Bad Bytes

The decoder throws a `BinaryDecodeError` when the bytes are too short, cut off, or hold text that is not valid UTF-8. Decoders do not validate: bytes from another source can decode to values of the wrong kind, so check the result with `createValidateFn<T>()`.

## Tune Buffer Sizing

`setSerializationOptions` changes how the `dynamic` strategy sizes new buffers, for every binary encoder in your app.

<code-import path="packages/examples/src/guide/binary-options.ts" lang="ts" />

| Option | Default | What it does |
|---|---|---|
| `defaultBufferSize` | `16384` | first buffer size for a type with no size history and no size estimate from the build |
| `sizeMultiplier` | `2` | extra room above the average size, in standard deviations |
