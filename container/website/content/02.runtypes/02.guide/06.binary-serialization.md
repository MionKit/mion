The binary functions write only the values, in the order your type declares them, with no key names. Data only types, undeclared keys and input checks are covered on the [Serialization](/runtypes/guide/serialization) page.

## Encoding and Decoding Bytes

`createBinaryEncoderFn<T>()` returns a function that writes a value into a `Uint8Array`. `createBinaryDecoderFn<T>()` returns one that reads it back. [Class serializers](/runtypes/guide/json-serialization#class-serializers) and the [rejectCircularRefs](/runtypes/guide/json-serialization#circular-references) option work the same as for JSON.

<code-import path="packages/examples/src/guide/ser-binary-basics.ts" lang="ts" commentStart="// start-basics" commentEnd="// end-basics" />

::tip
The bytes hold no key names and no type information, so both ends must use the same type. The decoder ignores any bytes after the end of the value.
::

## Buffer Sizing Strategies

The `sizeStrategy` option decides where the encoder's buffer comes from. Every strategy writes the same bytes, and `createBinarySizerFn<T>()` gives the exact byte count without writing any.

<code-import path="packages/examples/src/guide/ser-binary-sizing.ts" lang="ts" commentStart="// start-sizing" commentEnd="// end-sizing" />

| Strategy | Call | Buffer | When the value does not fit |
| --- | --- | --- | --- |
| `dynamic` (default) | `encode(value)` | Sized from earlier payloads of the same type, the first one from an estimate of the type | Grows and copies |
| `precalculate` | `encode(value)` | Measured in an extra pass, then allocated exactly | Cannot happen |
| `initialSize` | `encode(value, size)` | `size` bytes | Throws `RangeError` |
| `intoBuffer` | `encode(value, buffer)` | Your `ArrayBuffer` | Throws `RangeError` |

::tip
Every strategy returns a view of just the written bytes. Send the view itself, since its `.buffer` can be larger.
::

## Smaller Payloads With Formats

A number takes 8 bytes. An integer format whose range fits a smaller integer, such as `UInt8` or `Int16`, takes 1, 2 or 4 bytes instead.

<code-import path="packages/examples/src/guide/ser-binary-formats.ts" lang="ts" commentStart="// start-formats" commentEnd="// end-formats" />

| Format | Bytes |
| --- | --- |
| `UInt8`, `Int8`, or an integer format with `min` and `max` inside their range | 1 |
| `UInt16`, `Int16`, or an integer range inside theirs | 2 |
| `UInt32`, `Int32`, or an integer range inside theirs | 4 |
| Any other number | 8 |
| `BigInt64`, `BigUInt64`, or a bigint range inside theirs | 8 |
| Any other bigint | Its decimal digits as a string |

::tip
The encoder does not check the range: 300 in a `UInt8` field is written as 44.
::

## Binary Wire Format

Values are written little-endian, in declaration order. The [binary serialization article](/runtypes/articles/binary-serialization) explains the format in depth.

| Value | Written as |
| --- | --- |
| boolean, null, undefined | 1 byte |
| number | An 8-byte float |
| string | Its UTF-8 byte length in 1 to 5 bytes, then the bytes |
| bigint | Its decimal digits as a string |
| Date | Its time in milliseconds as an 8-byte float |
| Array, Map, Set | The item count, then the items |
| Record | A 4-byte entry count, then key and value pairs |
| Optional properties | One bit each, then the values that are present |
| `any`, `unknown`, `object` | JSON text, written as a string |
| Registered class with a `serialize` handler | The handler's result as JSON text |

## Tuning the Dynamic Buffer

The `dynamic` strategy sizes each buffer from earlier payloads that share a cache key. `setSerializationOptions()` changes the other settings for every encoder.

| Option | Set with | Default | What it does |
| --- | --- | --- | --- |
| `cacheKey` | Encoder options | The type's id | Groups size history, so encoders with the same key share it |
| `sizeMultiplier` | `setSerializationOptions()` | 2 | Buffer size is the average payload plus this many standard deviations |
| `defaultBufferSize` | `setSerializationOptions()` | 16 KiB | Buffer size when there is no size history and no estimate |
| `maxStrCacheLength` | `setSerializationOptions()` | 64 | Strings shorter than this keep their UTF-8 bytes cached for the next encode |
| `maxCacheSize` | `setSerializationOptions()` | 1000 | Cached strings before half of the cache is dropped |

## Binary Decode Errors

Every malformed buffer makes the decoder throw `BinaryDecodeError`, and a count is checked before anything is allocated for it.

<code-import path="packages/examples/src/guide/ser-binary-errors.ts" lang="ts" commentStart="// start-errors" commentEnd="// end-errors" />

| Input | Checked |
| --- | --- |
| A buffer that ends before the value does | Every read, and the final position |
| An item count larger than the bytes left can hold | Before the items are allocated |
| More than 1,048,576 items that take no bytes, such as literals | Against the `MAX_ZERO_BYTE_ITEMS` limit |
| A length longer than 5 bytes | While reading the length |
| A string that is not valid UTF-8 | While decoding the string, never replaced |
