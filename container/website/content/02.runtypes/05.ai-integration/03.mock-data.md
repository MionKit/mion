[Experimental]{.rt-badge-experimental} The enrichment workflow works today; the generated file shape and the commands may still change between minor versions.

`MockData<T>` gives a type realistic sample values: pools of names and emails, ranges for numbers and dates, and hints for arrays and optional fields. It feeds the [`createMockDataFn<T>()`](/runtypes/guide/mocking) generator. Like [`FriendlyText<T>`](/runtypes/ai-integration/friendly-type), you [commit](/runtypes/ai-integration/workflow-and-commands) it next to your type and the compiler checks it against that type on every build.

| Option | Applies to | What it does |
| --- | --- | --- |
| `pool` | strings, numbers, booleans, bigints, … | draw the value from this list |
| `min` / `max` | numbers, dates | bound the generated range |
| `rt$items` | arrays | the element node (a `MockData` node for `T[number]`) |
| `rt$length` | arrays | fixed length, or a `[min, max]` range |
| `rt$optional` | objects | chance (0 to 1) that an optional member is present |

## Checking Sample Values at Build Time

[Planned]{.rt-badge-experimental} The compiler checks every pool value and range against its field at build time, not when your tests run. A bad value fails the build, and a `min` above `max` is reported too.

```ts
export const mockUser: MockData<User> = {
  profile: {
    email: { pool: ['alice@example.com', 'not-an-email'] },   // error: 'not-an-email' isn't a valid email
    score: { min: 0, max: 150 },                              // error: 150 is above the field's max of 100
  },
};
```

## Format-Aware Defaults

Without a pool, the generator still follows [type formats](/runtypes/type-formats/overview): an `email` field gets a real-looking address, a `uuidv4` field a real-looking UUID. Use `MockData<T>` when you want believable values instead: real names in `name`, your own domains in `email`, realistic ranges in `age`. Any field you leave out falls back to the format-aware generator.

::note
Use `MockData<T>` in tests and seed scripts, and import `createMockDataFn` from `@mionjs/run-types/mocking`, so your app bundle ships no mock pools.
::
