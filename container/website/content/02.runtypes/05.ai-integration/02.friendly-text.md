[Experimental]{.rt-badge-experimental} The enrichment workflow works today. The generated file shape and the commands may still change between minor versions.

`FriendlyText<T>` gives every field of a type a **label** and **error messages**. You [commit](/runtypes/ai-integration/workflow-and-commands) the map next to your type, and the compiler checks it against that type on every build. Use it to turn validation errors into messages people can read.

## FriendlyText Shape

The map mirrors your type, every field included. Every node is `{ rt$label, rt$errors, ...fields }`: both `rt$` keys always, then one key per child field. Arrays use `rt$items`, tuples `rt$slots`, a Map `rt$keys` and `rt$values`, a Set `rt$values`.

## Keeping FriendlyText in Sync

When your type changes, `enrich --update` re-syncs the map and keeps every label and message you wrote. Text an edit would throw away is kept as a comment:

```ts
export const friendlyUser: FriendlyText<User> = {
  rt$label: 'User account',
  rt$errors: { type: '' },
  name: { rt$label: 'Full name', rt$errors: { type: '' } },
  /* @rtOrphanChild isActive: { rt$label: 'Active?', rt$errors: { type: '' } }, */   // you removed isActive
};
```

| The edit | What happens to your text |
| --- | --- |
| Rename a field or a whole type | it follows the field, untouched |
| Remove a field | its node is kept as a comment marked `@rtOrphanChild` |
| Change a field's type | the label always survives, and only the messages the new type no longer declares are kept as comments |
| Change a field to a different shape (a number becomes an array of objects) | the whole old node is kept as a comment and a fresh blank takes its place |
| Delete a whole type | its entire map is kept as a comment marked `@rtOrphan` |

## Pruning Comments Left by Removed Fields

Comments left by a removed field or type stay until a prune clears them all at once.

```bash
mion enrich --prune
```

::tip
Prune removes only the `@rtOrphan` and `@rtOrphanChild` comments, never a live field or a `@todo` blank. Bring a removed field or type back and the next `enrich --update` restores its text.
::

::note
`MockData<T>` works the same: a removed field's sample pool is kept as a comment until `enrich --prune`.
::

## Error Message Keys

Each `rt$errors` key names the rule the value broke, and `type` covers a value of the wrong kind. TypeScript requires every key your type can fail and rejects any other, so a typo or a leftover key shows in your editor. Params that never fail validation (`isCurrency` and the `transform` block) never become keys.

| Failure | `rt$errors` key | `$[val]` resolves to |
| --- | --- | --- |
| base type-shape (wrong kind) | `type` | n/a |
| string `minLength` / `maxLength` | `minLength` / `maxLength` | the bound (`2`, `60`) |
| string `pattern` | `pattern` | n/a |
| number `min` / `max` | `min` / `max` | the bound |
| number `lt` / `gt` | `lt` / `gt` | the bound |
| number `integer` | `integer` | `true` |
| date/time `date` / `time` | `date` / `time` | n/a |
| `uuid` version | `version` | `'4'` |

::note
Errors **accumulate**: a value that breaks both `minLength` and `pattern` gets **one message per broken rule**. For one message per field, use `rt$default` below.
::

## Message Placeholders

The compiler checks these `$[…]` tokens and the renderer fills them in.

| Token | Resolves to |
| --- | --- |
| `$[label]` | the node's `rt$label`, falling back to the raw field name |
| `$[val]` | the failed constraint's bound (e.g. `2` for `minLength: 2`) |
| `$[path]` | the dotted path to the field (`profile.email`) |
| `$[index]` | the array element index, for `rt$items` failures |

::note
`$[value]` (the received value) is not supported yet: the error does not carry the input.
::

## Plural Messages

A count rule (`minLength`, `maxLength`, `min`, `max`, `lt`, `gt`) can hold one wording per plural form instead of a single string. The form follows the broken limit (the `3` in `minLength: 3`), and only `other` is required.

```ts
minLength: {
  one: '$[label] needs at least $[val] character',
  other: '$[label] needs at least $[val] characters',
},
```

The scaffold has the forms each file's language needs (English gets `one` and `other`, see [Translations (i18n)](/runtypes/ai-integration/i18n)). Other rules (`type`, `pattern`, and the rest) stay a single string, and a single string still works on a count rule when one wording fits every count.

## One Message per Field

Make `rt$default` the only key in `rt$errors` and it becomes the message for every failure of that field. A node has either `rt$default` or the per-rule keys, never both, so each field picks its own mode. It is [translatable](/runtypes/ai-integration/i18n) like any other message.

## Rendering Messages

`createFriendlyText<T>(map)` returns a renderer with two methods. It needs only the map and the errors.

<code-import path="packages/private-examples/src/enrich/friendly-render.ts" lang="ts" />

`errors()` groups failures by path, picks the message for each broken rule and fills in its tokens. Each result is a `FriendlyMessage`:

```ts
interface FriendlyMessage {
  path: string;     // dotted path to the field ('profile.email'); '' for the root
  label: string;    // the field's rt$label, or its raw last path segment as fallback
  message: string;  // the interpolated message
}
```

A blank or missing message falls back to "<label> is invalid". A blank label falls back to the raw field name.

::note
Error rendering works today. **Form-building UI is coming later.**
::
