:::div{class="ai-steps-head"}
### The compiler writes the code, your agent fills the blanks
The compiler can't invent a field label, an error message or a sample name. It scaffolds a typed source file, your agent fills in the blanks, and the compiler keeps the file in sync with your type.
:::

:::div{class="ai-steps"}
::::div{class="ai-step"}
[1]{.ai-step-num}[The compiler scaffolds]{.ai-step-title}

From your type it writes a source file, every field in place, correctly typed, each blank marked.
::::

::::div{class="ai-step"}
[2]{.ai-step-num}[The AI agent fills the gaps]{.ai-step-title}

The agent fills the blanks with labels, messages and sample values, guided by the type.
::::

::::div{class="ai-step"}
[3]{.ai-step-num}[The compiler checks & keeps in sync]{.ai-step-title}

It checks every value against the type and updates the file as your type changes, keeping your edits.
::::
:::

  age: {
    rt$label: 'Age',

      min: '$[label] must be at least $[val]',

## Agent Skills for Enrichment

Ready-made **agent skills** teach an AI agent the whole enrichment workflow. The main skill covers the commands and the JSDoc tags they rely on (`@rtType`, `@rtIds`, `@rtOrphan`, `@rtOrphanChild`, `@todo`). Two companion skills cover authoring, one for friendly labels and error messages, one for mock data.

Install them with one command:

::code-group

```bash [Claude]
npx mion-skills --claude
```

```bash [Agent]
npx mion-skills --agent
```

::

`--claude` writes into `.claude/skills/`, `--agent` into `.agent/skills/`. Use `--dir <path>` for another folder.

The agent picks the right skill automatically. No extra prompting needed.

## Generated Enrichment Files

`enrich` produces an ordinary TypeScript file, committed with your code and safe to hand-edit. Every field is there and fully typed, with the blanks marked.

The agent fills the blanks, and TypeScript checks them against your type. A new field gets a new blank, a changed field is flagged as stale, a removed field is cleaned up. Your filled-in values are never overwritten.

The files mirror your source tree under `<genDir>/enriched` (see [genDir](/runtypes/introduction/configuration)), by default `src/.mion/enriched`. Friendly maps go under `friendly/`, mock data under `mock/`, and [translations](/runtypes/ai-integration/i18n) under `i18n/<locale>/`. So the maps for `models/user.ts` are:

```
src/.mion/enriched/friendly/models/user.ts
src/.mion/enriched/mock/models/user.ts
```

## Enrichment Commands

A small CLI drives the loop, for an agent or for your CI. An opt-in bundler-plugin option runs the same scaffold and sync during dev, so a running dev server keeps the files current (see [Configuration](/runtypes/introduction/configuration)).

| Command | What it does |
| --- | --- |
| `enrich <file> <Type>` | Scaffold the source file with the blanks the agent fills. |
| `enrich … --update` | Re-sync the file after a type change, keeping your filled-in values. |
| `enrich … --prune` | Clean up entries left behind by deleted types or fields. |
| `enrich [files] --no-emit` | Health check, writing nothing. Fails on wrong or stale content, and allows unfilled blanks. Good for a quick pre-commit check. |
| `enrich [files] --require-complete` | Everything `--no-emit` catches, plus it fails on anything unfinished: an unfilled `@todo`, a blank value, a missing or out of date translation. A production build enforces this gate. Good for CI and release checks. |
| `enrich --i18n <locale>` | Scaffold the [translation](/runtypes/ai-integration/i18n) files for a locale, or `all` for every configured one. Takes `--update` and `--prune` like plain `enrich`. |
| `enrich --i18n <locale> --no-emit` | Report a locale's translation status (or `all`), writing nothing. Add `--require-complete` (or set `i18n.strict`) to fail CI on anything untranslated or out of date. |

Both checks list what is missing and take a `--json` flag for scripts. The same errors drive the lint rules in the [Linting guide](/runtypes/guide/linting), so you see them in your editor and can block unfinished files at commit time.

Every command takes a `--tsconfig <path>` flag. Without it, the CLI finds your tsconfig like tsc does, searching upward from the current directory. A config that fails to load stops the command with an error.

These map cleanly onto **MCP tools**, so any agent (Claude Code, Cursor, your own) can drive the whole thing.
