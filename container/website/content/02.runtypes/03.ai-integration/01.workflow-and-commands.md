:::div{class="ai-steps-head"}
### How Enrichment Works
The compiler can't invent a field label, an error message or a sample name, so your agent fills those in.
:::

:::div{class="ai-steps"}
::::div{class="ai-step"}
[1]{.ai-step-num}[The compiler scaffolds]{.ai-step-title}

From your type it writes a source file, every field in place, correctly typed, each blank marked.
::::

::::div{class="ai-step"}
[2]{.ai-step-num}[The AI agent fills the gaps]{.ai-step-title}

The agent fills the blanks with labels, messages and sample values, guided by the type.
::::

::::div{class="ai-step"}
[3]{.ai-step-num}[The compiler checks & keeps in sync]{.ai-step-title}

It checks every value against the type and updates the file as your type changes, keeping your edits.
::::
:::

## Agent Skills for Enrichment

Ready-made **agent skills** teach an AI agent the enrichment workflow, and the agent picks the right one on its own. The main skill covers the commands and the JSDoc tags they use (`@rtType`, `@rtIds`, `@rtOrphan`, `@rtOrphanChild`, `@todo`); two more cover writing labels and error messages, and mock data.

::code-group

```bash [Claude]
npx mion-skills --claude
```

```bash [Agent]
npx mion-skills --agent
```

::

`--claude` writes into `.claude/skills/`, `--agent` into `.agent/skills/`, `--dir <path>` into another folder.

## Generated Enrichment Files

`enrich` writes an ordinary TypeScript file that you commit and can safely edit. A new field gets a new blank, a changed field is flagged as stale, a removed field is kept as a comment until `--prune`.

The files mirror your source tree under `<genDir>/enriched` (see [genDir](/runtypes/introduction/configuration)), by default `src/.mion/enriched`: friendly maps under `friendly/`, mock data under `mock/`, [translations](/runtypes/ai-integration/i18n) under `i18n/<locale>/`. For `models/user.ts`:

```
src/.mion/enriched/friendly/models/user.ts
src/.mion/enriched/mock/models/user.ts
```

## Enrichment Commands

A small CLI drives the loop, for your agent or your CI. An opt-in bundler plugin option runs the same scaffold and sync in your dev server (see [Configuration](/runtypes/introduction/configuration)).

| Command | What it does |
| --- | --- |
| `enrich <file> <Type>` | Scaffold the source file with the blanks the agent fills. |
| `enrich … --update` | Re-sync the file after a type change, keeping your filled-in values. |
| `enrich … --prune` | Clean up entries left behind by deleted types or fields. |
| `enrich [files] --no-emit` | Check, writing nothing. Fails on wrong or stale content, allows unfilled blanks. Good before a commit. |
| `enrich [files] --require-complete` | Everything `--no-emit` catches, plus anything unfinished: an unfilled `@todo`, a blank value, a missing or out of date translation. With the bundler plugin option on, a production build runs this check too. Good for CI and releases. |
| `enrich --i18n <locale>` | Scaffold the [translation](/runtypes/ai-integration/i18n) files for a locale, or `all` for every configured one. Takes `--update` and `--prune` like plain `enrich`. |
| `enrich --i18n <locale> --no-emit` | Report a locale's translation status (or `all`), writing nothing. Add `--require-complete` (or set `i18n.strict`) to fail CI on anything untranslated or out of date. |

Both checks list what is missing and take `--json` for scripts. The [lint rules](/runtypes/guide/linting) report the same errors in your editor and can block unfinished files at commit time.

Every command takes `--tsconfig <path>`. Without it, the CLI searches upward from the current directory, like tsc. A config that fails to load stops the command with an error.

Any agent that can run shell commands (Claude Code, Cursor, your own) can drive them.
