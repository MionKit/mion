[Experimental]{.rt-badge-experimental} The enrichment workflow works today; the generated file shape and the commands may still change between minor versions.

Your [`FriendlyText<T>`](/runtypes/ai-integration/friendly-type) map is the source language, so there is no separate message catalog. A translation is one optional file per locale with the same shape, and any blank string in it falls back to the source text.

## Configuring Locales

List your locales in the tsconfig plugin entry that holds the rest of your [configuration](/runtypes/introduction/configuration).

```json
{
  "compilerOptions": {
    "plugins": [
      {
        "name": "mion",
        "i18n": {
          "sourceLocale": "en",
          "locales": ["es", "pl", "pt-BR"]
        }
      }
    ]
  }
}
```

## Translation Workflow

Each locale runs the same [enrichment loop](/runtypes/ai-integration/workflow-and-commands): scaffold, fill the blanks, keep in sync.

```bash
# scaffold the Polish translation files; existing files are left alone
mion enrich --i18n pl

# re-sync after a change, keeping everything you wrote
mion enrich --i18n pl --update

# every configured locale in one go
mion enrich --i18n all --update

# CI gate: fail if any translation is missing, untranslated, or out of date
mion enrich --i18n all --require-complete

# clear the comments left by removed fields
mion enrich --i18n pl --prune
```

`enrich --i18n --no-emit` reports a missing file, unfilled blanks, an out of date translation, and leftovers waiting for a prune. By default these are warnings and the command succeeds: add `--require-complete` to fail that run, or set `i18n.strict: true` to fail every run. Rendering at runtime stays lenient either way.

## Translation Files

Translations live under `<genDir>/enriched/i18n/<locale>/`, mirroring your source tree like the friendly files. A regional tag like pt-BR works as a folder name.

```
src/.mion/enriched/
  friendly/models/user.ts      friendlyUser (the source language)
  mock/models/user.ts          mockUser (mock data is never translated)
  i18n/pl/models/user.ts       pl_friendlyUser (Polish)
  i18n/pt-BR/models/user.ts    pt_BR_friendlyUser (Brazilian Portuguese)
```

## Keeping Translations in Sync

The friendly map and every locale file are generated from your type, never from each other. After a change, `enrich --i18n pl --update` adds a new message as a blank, keeps a removed one as a comment until `--prune`, and never loses what you wrote. Renaming a type renames its consts in every locale too.

## Plural Forms per Locale

Each count rule (`minLength`, `maxLength`, `min`, `max`, `lt`, `gt`) is scaffolded with exactly the plural forms of that file's language: English gets `one` and `other`, Polish gets `one`, `few`, `many` and `other`. Other rules (`type`, `pattern`, and the rest) stay a single string.

```ts
// in the English source map
minLength: {
  one: '$[label] needs at least $[val] character',
  other: '$[label] needs at least $[val] characters',
},
```

The form is picked per locale with the built-in plural rules (`Intl.PluralRules`). Only `other` is required: a form you leave out or blank uses it, and if `other` is blank too, the source is used. A plain string also works when one wording fits every count.

::warning
**The count is the rule's limit, not what the user typed.** For minLength 3, the plural form and `$[val]` follow the 3, never the length of the received text.
::

## Locale Matching

The renderer tries the exact tag, then trims it (pt-BR finds pt), then any tag with the same base language (zh-Hant finds zh-Hans). If nothing matches, it uses the source map. A missing translation never throws, and `resolveLocale(locale, translations)` exports the same logic.

## Money in Messages

To show a money limit, declare the field with the Currency format and set `currency` on the renderer, not in the type or the template. Any ISO code works (EUR, USD, PLN), and like `locale` it can be a `{value}` ref you switch at runtime.

`$[val]` then renders the amount for the active locale. Without `currency` it renders a plain localized number and never guesses a symbol. An app with one fixed currency can write the symbol into its templates and keep a plain number type.

## Dates in Messages

Date limits need no setup. A field with any date format (a date string, a native Date bound, a Temporal type) renders its `$[val]` as a date in the active locale. A relative limit like now-P1D stays as written.
