# @ts-runtypes/devtools

Build-time tooling for **RunTypes**. Two surfaces in one package:

- a **cross-bundler plugin** built on [unplugin](https://github.com/unjs/unplugin)
  that rewrites RunTypes marker calls (`getRunTypeId`, `createValidateFn`,
  `createJsonEncoderFn`, …) into specialized, type-derived code generated by the
  RunTypes Go resolver, and
- a **lint plugin** (OXlint and ESLint v9) that surfaces the compiler's diagnostics
  in your editor and CI.

The runtime half is [`@ts-runtypes/core`](https://www.npmjs.com/package/@ts-runtypes/core).

## Entry points

| Import                           | What it is                                                         |
| -------------------------------- | ------------------------------------------------------------------ |
| `@ts-runtypes/devtools/vite`     | Vite plugin (default export is the plugin factory)                 |
| `@ts-runtypes/devtools/rollup`   | Rollup plugin                                                      |
| `@ts-runtypes/devtools/rolldown` | Rolldown plugin                                                    |
| `@ts-runtypes/devtools/webpack`  | webpack plugin                                                     |
| `@ts-runtypes/devtools/rspack`   | Rspack plugin                                                      |
| `@ts-runtypes/devtools/esbuild`  | esbuild plugin                                                     |
| `@ts-runtypes/devtools/unplugin` | the framework-agnostic unplugin instance (`.vite`, `.rollup`, …)   |
| `@ts-runtypes/devtools/oxlint`   | the OXlint plugin (the primary lint transport)                     |
| `@ts-runtypes/devtools/eslint`   | the same rules behind an ESLint v9 flat-config adapter             |
| `@ts-runtypes/devtools`          | the unplugin instance (default export) plus shared types + helpers |

> The transform is identical across bundlers; the Vite entry additionally wires
> HMR. Vite and Rollup are covered by tests today; webpack, Rspack, Rolldown and
> esbuild ride the same unplugin core. esbuild has no native transform phase, so
> unplugin emulates it via `onLoad`.

## Install

```bash
pnpm add -D @ts-runtypes/devtools
```

The plugin runs a small prebuilt Go binary. It resolves the right binary for
your platform automatically through `@ts-runtypes/bin`; pass `binary` only to
point at a custom or in-repo build.

## Usage

```ts
// vite.config.ts
import {defineConfig} from 'vite';
import runtypes from '@ts-runtypes/devtools/vite';

export default defineConfig({
  plugins: [runtypes()],
});
```

Every other bundler is the same shape, e.g. Rollup:

```ts
// rollup.config.js
import runtypes from '@ts-runtypes/devtools/rollup';

export default {
  plugins: [runtypes()],
};
```

## Options

The canonical home for the project-level knobs is the `ts-runtypes` entry under
`compilerOptions.plugins` in `tsconfig.json` — see the
[Configuration guide](https://runtypes.pages.dev/introduction/configuration). Every
one of those keys is accepted here too, as a per-build override that wins over
tsconfig. `binary`, `cwd`, `tsconfig` and `genDir` are host-specific and have no
tsconfig equivalent.

| Option                            | Default                       | Description                                                                                 |
| --------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------- |
| `binary`                          | auto (via `@ts-runtypes/bin`) | Path to a custom `ts-runtypes` binary.                                                      |
| `cwd`                             | bundler root                  | Project root (where `tsconfig.json` lives).                                                 |
| `tsconfig`                        | `"tsconfig.json"`             | tsconfig path, relative to `cwd`.                                                           |
| `genDir`                          | inferred from tsconfig        | Generated-output root: cache modules under `<genDir>/types/`, enrichment under `enriched/`. |
| `emitMode`                        | `"code"`                      | What each cache entry ships: `code`, `functions`, or `both`.                                |
| `moduleMode`                      | `"default"`                   | Virtual-module grouping: `default`, `allSingle`, `allModules`.                              |
| `inlineMode`                      | `"default"`                   | Child-inlining policy: `default` or `allInternal`.                                          |
| `transformMode`                   | `"edits"`                     | How the rewrite crosses the wire: `edits` (plugin applies) or `go` (resolver applies).      |
| `sourcesContent`                  | `true`                        | `go` mode only: embed the original source in the returned map's `sourcesContent`.           |
| `hashLength`                      | `7`                           | Length of the short structural-hash ids in generated names.                                 |
| `size`                            | see guide                     | Binary `dynamic` buffer-size estimate knobs: `{bias, items, stringBytes, maxBytes}`.        |
| `validate`                        | `{}`                          | Project-wide defaults for the per-call `ValidateOptions` bag, e.g. `{numberMode}`.          |
| `failOnError`                     | `true`                        | Whether Error-severity build diagnostics fail the build in every lane.                      |
| `allowUncheckedPatterns`          | `false`                       | Allow format patterns whose mock samples the build cannot verify (JS-only regex features).  |
| `pureFnReport`                    | off                           | Emit the pure-fn build report: `'file'`, `'callback'`, or `false`.                          |
| `onPureFnReport`                  | —                             | In-process pure-fn report callback; setting it implies `pureFnReport: 'callback'`.          |
| `enrich`                          | off                           | Enrichment auto-sync: `{friendly, mock, i18n, suppressHmr}`.                                |
| `parallelScan` / `parallelRender` | `true`                        | Opt out of the resolver's parallel phases (benchmarking / debug).                           |
| `singleThreaded`                  | `false`                       | Force single-checker, fully-serial scan/render.                                             |

The on-disk artifact cache (`node_modules/.cache/ts-runtypes`) has no option here: it follows TypeScript's `incremental` / `composite` tsconfig setting (on when your project is incremental, off otherwise).

## Linting

The lint plugin ships two rule families: compiler diagnostics surfaced at the call
site, and enrichment hygiene (no unfilled `@todo`, no stale `@rtOrphan`). OXlint is
the primary transport; the `./eslint` subpath exposes the same rules as an ESLint v9
flat config. See the
[linting guide](https://runtypes.pages.dev/guide/linting) for the setup.
