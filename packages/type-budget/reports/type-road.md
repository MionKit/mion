# Type road vs builder road, per table shape

Generated by `packages/type-budget/test/typeRoad.compile.test.ts`. Do not edit by hand.
Measured with TypeScript 6.0.3 and drizzle-orm 0.45.2.

The same table, declared three ways and read through the same models:

- **builder road** the table built with the recorder builders, `pgTable('t', {...})`
- **type road** the table written as a pure type, `PgTable<'t', {...}>`
- **pre-branded** the columns named as the branded types the builders return,
  which skips normalization entirely. Nobody authors this; it is the floor the
  other two are measured against.

| Case | Net instantiations | Budget |
| ---- | -----------------: | -----: |
| builder road, 5 mixed columns | 646 | 646 |
| type road, 5 mixed columns | 1258 | 1258 |
| type road, 5 mixed columns + insert model | 1895 | 1895 |
| type road, 20 plain columns | 2116 | 2116 |
| builder road, 20 plain columns | 465 | 465 |
| pre-branded, 20 plain columns | 436 | 436 |

The gap between the type road and the pre-branded floor is what normalizing an
authored column record costs. Budgets may only ever be lowered. Every one of
these is paid again on every keystroke, because each edit builds a new checker.
